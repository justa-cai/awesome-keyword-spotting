# NTC-KWS: Noise-aware CTC for Robust Keyword Spotting（噪声感知 CTC 的鲁棒关键词唤醒）

- **作者/机构**: Yu Xi, Haoyu Li, Hao Li, Jiaqi Guo, Xu Li, Wen Ding, Kai Yu（俞凯，通讯作者）(上海交通大学 MoE 人工智能重点实验室 / X-LANCE 实验室；思必驰 AISpeech 苏州；NVIDIA 上海)
- **发表日期**: 2024年12月（arXiv:2412.12614v2，2024-12-24 更新）
- **链接**: https://arxiv.org/abs/2412.12614
- **关键词**: noise-aware CTC, keyword spotting, WFST decoding, wildcard arcs, noise robustness, low SNR, false alarm control

## 问题陈述

### 问题背景和领域痛点

关键词唤醒是智能音箱、耳机、车载、IoT 设备上人机交互的第一入口，系统部署在设备端并且全天候连续运行。随着应用场景越来越多样，如何在资源受限的条件下提升噪声鲁棒性，已经成为 KWS 领域的关键研究方向。CTC 基的端到端 KWS 系统通常部署在低资源计算平台上，模型尺寸和算力的双重限制在复杂声学场景下会形成瓶颈：约束带来的直接后果是模型容量有限时更容易过拟合，且在强噪声下把背景噪声与目标关键词混淆，从而推高误报率——误报每小时的次数直接决定用户体验，音箱在电视声、音乐、餐厅嘈杂声里自己醒来是最招用户反感的失败模式。

论文的引言里给了一段非常关键的预实验观察，这是整个方法的地基：第一，在低信噪比下，强噪声能量天然导致召回下降；第二，用含极低信噪比的仿真数据训练，模型会过拟合到噪声上，最终拖累整体性能而不仅仅是低信噪比那一档的性能。作者的归因是：挑战性训练数据中的噪声掩盖了关键词语音的一部分，模型于是把噪声和目标关键词混淆起来。

这个归因值得展开，因为它解释了 CTC 训练在加噪数据上为什么会"中毒"。CTC 的训练目标是把输入帧序列对齐到标签序列，训练语料给的标签是干净录制语音的转写。论文图一给了一个具体例子："Hey Snips" 的干净语音音素序列是 HH EY1 S N IH1 P S；与 WHAM! 噪声混合之后，语音实际呈现的内容变成了 HH <噪声> EY1 S <噪声> N EH0 P S。对比两条序列可以读出三类错误：噪声帧插进了音素之间（图中蓝色标注的插入错误），IH1 被扭曲成了 EH0、音素被掩盖替换（图中红色标注的掩盖与干扰错误），整体与干净转写之间产生了错配。CTC 训练在这种错配监督下别无选择：损失函数要求把噪声主导的那些帧对齐到转写里的关键词音素上，等价于用梯度一遍遍告诉模型"这段噪声就是 IH1"。噪声的随机模式就这样被当作音素判别的证据写进了参数，模型学到的是"某种噪声长得很像唤醒词"，误报与低召回同时恶化。这不是数据量的问题，而是训练准则没有给噪声主导的帧一个合法去处。

### 现有方法的具体不足

论文把已有的噪声鲁棒 KWS 工作分成两支。第一支是在 KWS 模块前面加单通道或多通道语音增强前端，先洗干净再识别；第二支是设计新的训练策略或网络架构来直接获得噪声鲁棒的 KWS。论文指出的关键共性是：无论走哪条路线，仿真含噪数据都扮演着关键角色。而预实验的第二个观察恰恰说明仿真数据本身有毒性边界——把信噪比压得过低去"练"模型，反而练坏。这就把问题从"数据够不够狠"转移到了"训练准则怎么消化噪声"。

在训练准则层面，CTC 系的 ASR 领域其实已经有一批通配符建模工作：W-CTC 在损失里引入通配符处理不准确的转写，Star Temporal Classification 处理部分标注数据，Bypass Temporal Classification 及其后续用旁路弧处理有缺陷的转写。但这些方法的出发点全部是文本侧的错误——转写写错了、漏了、没标。噪声诱导的语音侧错误（语音内容本身被噪声吃掉一段）在问题结构上是对偶的：前者是"标签比语音少信息"，后者是"语音里混进了标签没有的东西"。此前没有人把通配符思想搬到 KWS 的声学侧噪声建模上，更没有人把通配符路径塞进 KWS 的 WFST 解码图里做免训练的推理增强。后者是本文标题里"noise-aware"落到解码端的关键一环，也是和所有只改训练的方法拉开差距的地方。

从端侧部署角度还有一个隐性不足：加语音增强前端意味着加参数、加计算、加流水线延迟，而 KWS 是全天候常驻的模块，每一毫瓦的持续功耗都敏感；改训练策略则往往需要重新设计数据配比。本文选择的道路是既不动声学模型结构、也不加前端，只改训练损失里的图和解码时的图——对部署最友好的一层。

### 该论文要解决的关键挑战

综合起来，论文要同时解三个互相牵制的挑战。其一，如何在 CTC 训练准则里显式建模噪声主导的语音段，让模型不再被迫把噪声对齐成音素，从源头阻断对噪声的过拟合；其二，如何让训练阶段学到的噪声建模能力在解码阶段真正兑现——如果解码图里没有对应的路径，训练学到的能力就是死资产；其三，放松解码约束天然有误报风险：给解码器"跳过音素"和"吸收噪声"的自由度，纯噪声就有机会拼出一条关键词路径，必须在提升低信噪比召回与控制每小时误报次数之间做出严格平衡。方法设计里的转移代价、指数衰减惩罚、全通配符路径丢弃，都是围绕第三个挑战的安全阀。

## 方法论

### 整体架构设计和设计动机

NTC-KWS 的整体管线是：原始音频提取四十维对数梅尔滤波器组特征，二十五毫秒窗长、十毫秒帧移；当前帧与前五帧、后五帧拼接成模型输入，并施加帧跳步因子三做降采样以降低计算量；随后进入六层深度前馈序列记忆网络编码器，隐层五百一十二维、投影层三百二十维，每层的左右上下文阶数分别为八和二；编码器输出帧级的音素后验，建模单元是来自 CMU 发音词典的七十个单音素加一个空白符号；最后走 WFST 解码图做令牌传递搜索，搜索结果计算置信度得到关键词激活分数。NTC 相比 CTC 最多额外引入两个特殊符号：自环符 @ 和旁路符 *，但注意这两个符号并不增加神经网络的输出单元——它们的后验由公式五从既有音素后验推导（详见下文），这是设计上非常克制的一笔。

选 DFSMN 做骨干的理由论文说得直白：轻量且有效的语音编码器，是 KWS 任务的主流架构，同团队此前的 TDT-KWS 等工作都在用。更值得说的是所有对比模型（CTC 基线、NTC、各消融变体）都从同一个预训练检查点初始化、用同样的 SGD 优化——把变量严格锁死在训练准则和解码图上，这让后面消融表里的每一个数字差异都能干净地归因。

选 CTC 而非端到端封闭式模型的动机，从实验配置可以读出来：音素级建模单元加 WFST 组合式解码，意味着换唤醒词只需要换语法图而不必重训声学模型，这是 CTC-KWS 相对端到端黑盒的结构性优势（论文未明说此点，但从其七十单音素加紧凑语法图的配置可以合理推断）。同时 KWS 的语法图只包含关键词路径和可选的背景路径，不展开整个声学空间，搜索开销天然可控。

### 核心算法的数学原理

先看论文如何用 WFST 语言重写 CTC。输入声学特征序列为若干帧的矩阵，输出标签序列是若干个音素 token，因为引入了空白符号来建模每帧的空输出，帧数远大于标签数。对齐序列是每一帧上取普通音素或空白的序列，CTC 的目标是最小化给定输入下所有合法对齐路径负对数似然的总和，即公式一：损失等于负的对所有能映射回标签的对齐路径求概率的对数，其中映射把合法对齐压缩回标签（去掉空白、合并重复 token）。解码是公式二：找最可能的标签，近似为在对齐空间里做 Viterbi 找最优路径。

WFST 实现的关键是把搜索空间写成三个转移器的复合：搜索空间等于 CTC 合并转移器、词典转移器（词到 token 的映射）和语法转移器的复合，再与建模声学后验的稠密发射图求交。于是公式三把训练写成一个式子：CTC 损失等于在复合图上做前向计算再取负；公式四把解码写成在复合图上做 Viterbi。令牌传递是图上做 Viterbi 的高效实现，当一个令牌到达终节点时一条解码路径完成。这个形式化的价值在于：改训练准则和改解码策略都变成同一件事——改图，训练和解码的一致性有了统一的数学载体。

KWS 与 ASR 在这个框架下只有两处不同：语法图更紧凑轻量，只有关键词路径加可选背景路径；搜索结果要转成关键词激活分数，论文沿用文献二十二提出的置信度度量。

### 关键技术创新一：噪声感知的 CTC 训练准则（通配符弧加指数衰减惩罚）

训练侧的核心动作是在训练图的关键词音素序列上引入两类通配符弧。自环弧 @ 建模插入错误：噪声帧插进两个关键词音素之间，对应图一里蓝色的噪声段，自环允许路径在原音素上多停留任意多帧来"吸收"这些噪声帧。旁路弧 * 建模替换与删除错误：音素被噪声掩盖、扭曲（IH1 变 EH0 这类），对应图一里红色的错误，旁路允许路径直接跳过被吃掉的音素。两类弧合起来表达的概念论文原话是"过度的语音噪声与干扰"。

通配符弧上的声学后验由公式五给出：自环符和旁路符的后验相等，都等于该帧上除空白外全部词表 token 后验的总和除以非空白词表长度，也就是全部非空白音素后验的平均值。为什么取平均而不是让网络直接多输出两个类别？因为噪声主导的帧没有特定的音素身份，任何非空白音素都可能出现，平均值恰好表达了"不确定是哪个音素、但可能是语音里某个音素"的中立假设。更实际的收益是不引入新参数、不改变输出层结构、不增加训练不稳定性，端侧模型寸土寸金，这个设计把训练准则的修改成本压到了图这一层。代价也明显：平均值抹掉了"什么样的噪声更该走通配符"的判别信息，这为后续改进留了空间。

第二个关键机制是公式六的惩罚调度：为了确保模型优先学习正确对齐而不是通配符路径，训练初期给两类弧赋予很大的初始惩罚，随后惩罚随训练轮数指数衰减，第 l 轮的惩罚等于初始惩罚乘以衰减系数的 l 次方。为什么必须有这个调度？如果通配符弧从第一轮就零代价可用，模型会发现一条捷径——把大量难分的帧统统甩给通配符，音素判别本身学不扎实，这正是通配符类方法的经典风险。初期重罚强制模型先在干净对齐上学好音素，惩罚逐渐退火后通配符路径才慢慢可用，模型逐步学会"只在噪声真正主导的段走旁路"。超参取值上，初始惩罚两类弧都是负四，衰减系数自环弧取零点九九九、旁路弧取零点九七五——旁路弧的惩罚退火明显更快，意味着训练更早允许跳音素；论文未详细解释两者取值差异的原因，从数据分布看插入型噪声（每句加噪都会引入大段噪声帧）远比音素被掩盖常见，自环弧需要更长的保护期以免被高频使用，这个不对称可以作为合理推断记下。

### 关键技术创新二：免训练的通配符解码策略（扩展 WFST 解码搜索空间）

第二个创新回答了一个容易被忽略的问题：训练改好了，解码怎么办。论文观察到，虽然模型通过 NTC 训练学会了用通配符路径处理关键词的噪声主导部分，但标准的 CTC-KWS 解码图里根本没有这些弧，训练得到的能力在解码时无从使用，尤其在低信噪比下浪费严重。为了让训练和解码对齐，解码侧同样修改语法图：以关键词 "A B C"、词表含 "A B C D E" 加空白为例，在语法图上关键词序列的相邻子词之间插入自环弧和旁路弧，得到新的语法图，再与转移器和词典复合构成 NTC 搜索空间。

相比标准搜索空间，扩展后的图在两方面的收益论文说得很清楚。第一是训练与解码方法的对齐保证了一致性——这是原则层面的理由。第二更实质：当噪声占主导时，要求路径逐个认出关键词的每个 token 是苛刻的，在复杂声学环境下放松解码限制是合理的提召回手段，因为模型获得了在噪声段选择通配符弧的选项，正确关键词路径不会因为个别帧的音素后验崩溃而被搜索剪掉。图一右侧的玩具例子把这个机制画得很直观：蓝色弧接住插入噪声，红色弧放过被掩盖的音素。

放松必然带来误报风险，安全阀有两个。一是给两类弧设置转移代价（图一里的两个代价系数），在召回与误报之间调平衡；二是硬约束——如果一条解码路径完全由通配符 token 组成、不含任何关键词音素，该路径直接丢弃。第二个约束堵住了最危险的漏洞：纯噪声拼关键词。免训练是这项技术最有工程价值的属性：把 NTC 解码套在一个标准 CTC 训练好的模型上，不用重训就能拿收益，后面消融实验证明这个收益平均百分之二点七——对于已经上线、重训代价高昂的系统，这是可以直接落地的升级路径。

### 与现有方法的技术差异

与语音增强前端路线相比，本文不加模块、不加参数、不加流水线延迟，修改全部发生在损失函数的图和解码图上，部署形态与原系统完全一致。与通用的噪声鲁棒训练（多条件数据增强、对抗训练等）相比，本文不是让模型硬扛噪声，而是显式给噪声主导的帧在训练目标里一个合法去处，从对齐结构上消除"噪声被迫对齐成音素"的错误监督。与 ASR 侧的 W-CTC、StarTC、BTC 等通配符前驱相比，问题对偶：它们修文本侧的标签错误，本文修声学侧的语音损伤；且本文首次把噪声建模路径引入 WFST 基的 KWS 解码，并提出该策略无需 NTC 训练即可独立生效。与端到端 KWS 相比，保留了 WFST 组合的灵活性，换词只换图。与本文团队自己的 TDT-KWS 相比，骨干相同但问题正交：那边解决快和准，这边解决吵。

## 实验结果

### 使用的数据集及其规模

三个开源语料构造全部实验。LibriSpeech：广泛使用的英文语音识别语料，九百六十小时带转写，用作基础模型的预训练数据和 KWS 微调时的通用语音数据。Hey Snips：围绕唤醒词 "Hey Snips" 的开源 KWS 数据集；由于负样本语音没有转写，而 CTC 类模型无法在无转写语音上训练，负样本数据只用于评估不用于训练——论文把训练、开发、测试集里的全部负样本合并成一个大测试集（沿用其 TDT-KWS 的数据准备方式），新负测试集时长约九十七小时。WHAM!：包含音乐、餐厅声等多种环境噪声，用于给训练和评估合成含噪语音。训练数据构造分三步：先用干净 LibriSpeech 预训练基础编码器；再用 Snips 正样本加等量 LibriSpeech 微调 KWS 模型；最后做含噪仿真，把 Snips 与 LibriSpeech 的每条干净波形与从 WHAM! 随机选取的噪声样本混合，信噪比从零到二十分贝均匀采样，干净与含噪语音合并为训练集。评估数据：负测试集用与训练相同的方式混噪；正测试语音在零、五、十、十五、二十分贝五个固定信噪比档混噪；另造一套负五分贝数据，代表极低且域外的信噪比，考察分布外极限。

模型与特征配置：训练用 K2 工具包构建可微 WFST，解码系统用 OpenFST 构建；六层 DFSMN，隐层五百一十二、投影三百二十，左右上下文八和二；输出七十个单音素加空白；两组数据增强——在线语速扰动（扰动因子在零点九、一点零、一点一里均匀采样）加 SpecAugment（每条语音两个频率掩码最大十、两个时间掩码最大五十）；超参上衰减系数零点九九九与零点九七五，训练初始通配符代价负四，解码系数测试时调，令牌传递推理时最多二十个活跃令牌。参数量、推理延迟、实时率等端侧指标论文未报告。

### 评估指标的定义和选择理由

指标是各信噪比档、给定每小时误报次数下的召回率。已发表的 SOTA 模型通常报告每小时零点五次或一次误报下的召回，为公平起见基准对比沿用同样设置。但论文明确指出这个标准相对宽松——在这么高的误报预算下各系统性能普遍偏强，区分度小。为压低偏差和随机性的影响，初次对比之后所有系统统一在严格得多的每小时零点零五次误报下评估。选择理由站得住：严格误报档会把系统间真实差距放大，九十七小时的大负测试集配合严格档位，是 KWS 评估里区分度与稳定性兼顾的做法。这个指标选择本身也是论文的一个隐性贡献，揭示了宽松档位下各家报告数字趋同的假象。

### 与基线方法和 SOTA 的详细对比

表一对比端到端基线与本文 CTC、NTC 系统在干净 Hey Snips 上的表现。上半部分用官方 Snips 数据：RIL KWS 在每小时零点五和一次误报下召回分别为百分之九十六点四七和九十七点一八；WaveNet 基线在零点五档百分之九十九点八八；WeKws 的 MDTC 在零点五档九十九点八八、一点零档九十九点九二。下半部分因负样本无转写重建了数据设置：WeKws-MDTC 只用 Snips 正样本训练（记为正样本集），在九十七小时负测试集上每小时零点零五、零点五、一点零误报档召回分别为百分之八十九点五二、九十八点八五、九十九点二九；CTC-KWS 用 Snips 正样本加等量 LibriSpeech 训练，三档分别为九十八点七七、九十九点七二、九十九点七六；NTC-KWS 为九十八点九七、九十九点六四、九十九点七二。三点结论：其一，本文模型与官方设置下的最好端到端系统性能相当；其二，同等数据训练时 CTC 与 NTC 模型在零点五和一点零档都超过端到端基线；其三，在最苛刻的零点零五档，CTC 系模型绝对召回优势超过九个百分点——严格档位放大了 CTC 系模型与端到端基线的差距，反过来也说明宽松档位下的"打平"掩盖了真实优势。干净条件下 NTC 相对 CTC 只有零点二个点的微弱优势（九十八点九七对九十八点七七），符合预期：干净语音没有多少噪声段可让通配符发挥作用，NTC 的主战场在噪声。

### 消融实验的发现

表二是全文最有信息量的消融：训练准则（CTC 或 NTC）与解码图（CTC 或 NTC）的二乘二组合，在负五到二十分贝六档信噪比下的召回。四行数据依次是：CTC 训练加 CTC 解码，各档召回百分之四十一点六、七十五点一、九十点二、九十五点八、九十七点五、九十八点三，平均八十三点一；NTC 训练加 CTC 解码，四十一点七、七十四点三、八十九点八、九十五点八、九十七点五、九十八点一，平均八十二点九；CTC 训练加 NTC 解码，五十二点零、七十九点八、九十一七、九十六点二、九十七点四、九十八点零，平均八十五点八；NTC 训练加 NTC 解码，五十六点六、八十三点四、九十三点二、九十七点六、九十八点二、九十八点七，平均八十八点零。

第一个发现反直觉：只把训练换成 NTC 而解码仍用 CTC，性能不升反微降（平均八十二点九对八十三点一，零分贝档甚至从七十五点一掉到七十四点三）。论文的解释是 NTC 训练本身并不强迫模型把噪声当作语音的一部分对待，通配符路径只是被允许而非被强制使用，于是模型的行为接近于在干净高质量语音上训练的 CTC 模型。这个结果戳破了"更好的训练准则必然更好"的直觉，也把本文方法的重心悄悄移到了解码侧。第二个发现：CTC 训练的模型直接换上 NTC 解码，平均召回绝对提升二点七个百分点，且增益集中在低信噪比档（负五分贝从四十一点六跳到五十二点零，涨十点四；零分贝涨四点七）——免训练拿到核心收益，印证低信噪比下令牌解码才是瓶颈。第三个发现：NTC 解码套在 NTC 模型上再涨二点二个点，论文归因于训练与推理过程的对齐，一致性收益显性化。合并起来，NTC-KWS 相对 CTC-KWS 平均召回绝对提升四点九个百分点，负五分贝和零分贝档分别拿到十五个和八点三个百分点的绝对增益——极端噪声下的鲁棒性是全套设计的核心卖点，且从二乘二表可以精确拆账：四点九的总增益里，解码图贡献约二点七，训练解码对齐贡献约二点二，训练准则单独贡献约零。

表三对解码期两个转移系数做网格搜索，表中负数代表惩罚、正数代表奖励。最优配置是自环系数四、旁路系数二，即两个系数都取正值，各档召回五十六点六、八十三点四、九十三点二、九十七点六、九十八点二、九十八点七，平均八十八点零。这个结果的信息量在于它说明 NTC 模型在训练中没有过拟合通配符捷径，推理时反而需要给通配符路径正向加权才能与真实音素弧同台竞争——旁证了公式五的平均后验天然偏低，也旁证了退火调度的必要性。系数取负值时改善弱于正值但仍旧超过 CTC 基线，说明即使惩罚通配符，图上多出的路径本身仍有搜索价值。两个系数都设为负无穷时，NTC-KWS 的行为退化为表二里的 F 模型，即解码策略塌缩回 CTC 方法——彻底关死通配符弧等价于没加。敏感性上解码阶段对旁路系数远比自环系数敏感：自环系数从四降到二、零、负无穷，平均召回从八十八点零缓降到八十六点零，每档损失零点几到两个点；而旁路系数从二抬到四，平均召回直接从八十八点零崩到八十一点五，负五分贝档从五十六点六掉到四十点零。为什么旁路弧这么危险？因为自环弧只在同一音素上多停几帧，属于温和的插入吸收；旁路弧直接跳过关键词音素，代价一旦过低，解码器会轻易放过那些虽有噪声干扰但本可认出的音素，对齐质量与触发判别同时受损，误报压力陡增。论文在结尾承认只在当前噪声设置下搜索了参数，未来计划跨噪声类型进一步研究这两个解码参数。

## 主要贡献

论文自列三条贡献，逐条都有实验背书。第一，提出噪声感知的 CTC 训练准则，在复杂声学场景下建模噪声主导的语音段，防止模型过拟合噪声——机制上通过自环与旁路两类通配符弧加指数衰减惩罚实现，公式五和公式六给出完整形式。第二，首次采用把噪声建模路径并入 WFST 基 KWS 解码的免训练解码策略——在噪声环境下不依赖 NTC 训练即可提升性能（表二平均加二点七），叠加进 NTC-KWS 框架还能进一步改善（再加二点二）。第三，相对 SOTA 端到端系统和 CTC-KWS 基线，NTC-KWS 在干净与含噪条件下全面占优，极端场景提升显著——干净 Hey Snips 上达到 SOTA（表一），全信噪比平均召回绝对加四点九，负五与零分贝分别加十五与八点三个百分点（表二）。从更大的图景看，这篇论文的方法论贡献是把"噪声鲁棒性"从数据和模型结构层面挪到了对齐结构与解码图层面：噪声不再是被对抗或被过滤的对象，而是被显式建模成搜索空间里的一等公民。

## 局限性与展望

### 方法的技术局限性

第一，通配符后验取非空白音素的平均（公式五），这个设计虽然零参数开销，但抹平了噪声段的判别信息——模型无法区分"可吸收的稳态噪声"与"不该走旁路的真实语音"，只能靠转移代价在解码端事后把关，表三里旁路系数的极端敏感性正是这个缺陷的下游症状。第二，方法的有效性重心严重偏向解码侧：表二证明训练准则单独不可用（F 行甚至微降于 D 行），全部增益都要靠解码图兑现，这意味着方法的本质是"用扩展搜索空间换召回"，声学模型本身并没有变得更鲁棒，极端噪声下编码器输出的音素后验质量依旧。第三，两套超参（训练期初始惩罚与两个衰减系数、解码期两个转移系数）共五个旋钮，其中解码系数是测试时调的，存在向测试分布过拟合调参的风险，跨噪声场景的泛化性论文自己承认待验证。第四，转移代价全局恒定，不随当前帧的实际信噪比或噪声估计自适应，理想情况下旁路弧的代价应当在确定噪声主导时才降低。

### 实验设计的不足

其一，全部实验单一英文唤醒词 Hey Snips，未覆盖多关键词、中文唤醒词、用户自定义唤醒词场景，而后两者恰恰是 WFST 式 CTC-KWS 最有结构优势的应用面。其二，噪声来源单一（WHAM!），训练与测试负样本用同一分布混噪（零至二十分贝均匀），严格说属于域内评测；负五分贝虽标注为域外，但噪声类型仍同源，缺少真实采集噪声、混响、多说话人干扰的考验。其三，负测试集混噪方式与训练完全一致，模型见过完全相同的噪声库采样，鲁棒性结论的强度打了折扣。其四，端侧指标全线缺席：参数量、每帧推理延迟、实时率、内存占用、扩展解码图相对标准图的额外搜索开销均论文未报告，而论文开篇的动机恰恰是低资源平台——令牌数上限二十的设置暗示搜索开销可控，但没有数字支撑。其五，与语音增强前端路线没有直接对照实验，无法量化"改图不加了前端"在这条赛道上的真实位次。

### 未来可能的改进方向

沿着论文自己的展望，最直接的是跨噪声类型、跨信噪比分布系统研究两个解码系数的取值规律，理想目标是从需要网格搜索走向有理论指引或可自适应。方法层面值得推进的方向包括：把通配符后验从简单平均升级为可学习的噪声判别函数（例如以噪声主导概率为门控），让"何时走旁路"成为模型的输出而非解码端的固定代价；把转移代价做成随帧级信噪比估计动态调整的调度；将噪声建模弧的思想从 CTC 迁移到转录器家族（RNN-T、TDT 等），对齐机制不同但问题同构。评测层面，补上多唤醒词、多语言、真实远场噪声与端侧开销测量，才能完整回答这篇论文在开篇立下的资源受限场景命题。从系列视角看，这篇论文与库中 TDT-KWS 构成同一团队在"KWS 的 CTC 图上做手术"的两条分支——一个用 token 与时长建模压缩解码步数求快，一个用通配符弧扩张搜索空间求稳，两者在图操作层面天然存在组合空间，是后续值得留意的合流方向。
