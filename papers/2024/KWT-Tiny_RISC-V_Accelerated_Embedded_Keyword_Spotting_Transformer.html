裁到 1646 个参数，再把 GELU 焊进指令集

KWT-Tiny: RISC-V Accelerated Embedded Keyword Spotting Transformer

作者：Aness Al-Qawlaq、Ajay Kumar M、Deepu John —— 都柏林大学学院（UCD）

发表：2024.07 · arXiv:2407.16026 · 代码开源（anessk01/kwt_tiny）

1646 参数（−99.73%）非对称双 scale 量化裸机 C 张量库 双内存银行RISC-V custom-1 指令LUT 加速 GELU/SoftMax~5× 加速 / 29% 面积

一分钟版本

  • 三道墙：KWT-1 要 2.42 MB 内存，目标平台 lowRISC Ibex 只有 64 kB RAM / 50 MHz / 无 FPU——模型比内存大 37 倍；无 FPU 意味着一切浮点靠软件模拟（SoftMax 归一化、GELU 的除法尤其贵）；常驻监听下时钟周期数直接乘以每周期能耗 = 电池寿命。
  • 反抽象的四步组合拳：① 迭代裁剪——逐层评估影响删最小的层：深度 12→1（一个 Transformer 层就够双类任务；深度容量主要为多类判别买单）、MLP 256→24、输入 [40,98]→[16,26]；② 静态 PTQ——权重 INT8 + 中间残差 INT16，scale 取 2 的幂（反量化退化成移位）；③ 裸机 C 自建 Transformer 张量库（8 个函数）+ 双内存银行替代 malloc；④ RISC-V 自定义指令把 GELU/SoftMax 换硬件查找表。
  • 量化关键发现：非对称双 scale（权重 64 / 输入 32）82.5%——权重取值 0-1 可以用大 scale 提精度；输入幅值可达数百，提到 64 就撞溢出墙（65.2%，崩塌）。
  • GELU 硬件近似（自认新颖点）：x>1.595 直接取 x、x<−1.857 取 0、过渡区 32 元素 LUT——阈值由梯度下降寻优，精度退化仅 0.0042%（比量化误差低两个数量级）。
  • 账本：模型 2.42MB→1.65kB（369×）；周期 26M→5.5M（量化 2× + 指令 2.4× ≈ 4.7×，推断约 5× 功耗降）；精度 96.9→~80%（累计 −17 点）；面积 +29% + 2.69 kB ROM。每一步的代价都来自真实运行而非仿真——这是对「用仿真测加速、无法评估精度退化」的既有工作的正面回应。
  • 成色缺口：只有双类（dog/notdog）——87.2%/82.5% 与 35 类的 96.9% 不在同一任务难度平面；~80% 精度对商用唤醒词不够且无 FAR/FRR；无外部基线（DS-CNN / TFLite Micro 没比）；功耗是周期数推断非实测。

§01 · 问题陈述

64 kB 的世界里，底层是唯一能挖的空间

两条线的盲区：① 硬件加速类（AI-RISC / AIfES / FlexACC / DaDianNao / RISC-VTF / A³）——从高功耗高性能系统视角出发，很少关注微控制器的内存第一瓶颈；且往往用仿真操作测加速比而非真实模型端到端——「加速带来多少精度退化」无从回答，因为被加速的不是一个真的、可验证精度的模型。② 软件部署生态（TFLite / ONNX / TVM）——库自身就几 MB，很多嵌入式平台连库都装不下；更深层是抽象边界错了：框架把工程师隔离在算子底层之外，想针对特定平台优化反而困难——通用性是用「摸不到底层的权利」换来的。四个子挑战：裁到什么程度精度不崩（哪些层能安全下刀）；无 FPU 的 scale 怎么选（精度 vs 溢出）；不用 MB 级框架裸机实现 + 手工内存管理；最小面积（~29%）的自定义指令把最耗时非线性算子换 LUT 换 ~5× 加速。

§02 · 方法论

训练-量化-裸机-硬件全真实的移植路径

图 A·选 GELU/SoftMax 做硬件化的双重理由：profiling（Fig.3-5）显示它们最耗时；且这两个算子被许多 DNN 共享——投入可摊薄到更广模型家族。裁剪经验规律：缩小 MLP + 深度的组合是最佳精度-体积刀口，过度缩归一化向量 DIM 会精度陡降——γ/β 逐维作用于特征，砍 DIM 等于直接压缩表示本身，砍深度/MLP 只是砍「在表示上做的加工量」。

softmax(x)i = emax(x)−xi / Σ emax(x)−xj；　Wint = floor(W × 2y)；　GELU 分段：x>1.595→x，x<−1.857→0，中间 LUT
人话：数值稳定形式的指数参数从无界 x 换成有界的 max(x)−x（实测 0-10）——没有有界性，有限长查找表根本不成立；权重 scale 取 2 的幂让量化反量化退化成移位（几乎零成本），中间残差 INT16 防 INT8 累积溢出。

§03 · 实验结果

每一级台阶的代价都有真实数字

设置：GSC 全集，双类任务 dog / notdog（天然适合「Hey Google / Alexa」单唤醒词场景而非 35 词全类判别——任务难度不在同一平面，不能读作「Transformer 缩小只掉 10%」）；平台 Ibex@Arty-A7-35T FPGA、64 kB RAM、50 MHz、RV32IMC。指标：参数 / 体积（装不装得下）、时钟周期（与主频解耦、固定每周期能耗假设下正比于功耗）、FPGA 资源（LUT/DSP/FF/BRAM）、top-1 准确率。未报：实测功耗、FAR/FRR/DET、墙钟时间（按 50MHz 推算 5.5M 周期 ≈ 110ms，笔记推算值）。

表 IX 复绘·三面板各按自身量程归一。体积面板第 4 柱含 +2.69kB LUT ROM；程序体积（未入图）：浮点版 58.8kB → 量化 44.4kB → 加硬件 44.6kB（查表调用逻辑略增）。周期面板从 26M 到 5.5M 合计 ≈4.7×——论文宣称约 5× 加速并据此推断约 5× 功耗降。

表 V 复绘·三条读数：对称配置单调改善（8/8→32/32 从 60.3 爬到 77.3）——未溢出区间内量化粒度越细精度越高；32/32→64/32 再涨 5.2 点——此时权重精度是主要瓶颈而输入还有溢出余量；64/64 崩到 65.2——验证输入侧大 scale 触发中间结果溢出，非对称双 scale 的必要性由此成立。

硬件综合（Table VIII）与读表提醒：LUT 资源 5092→7368、DSP 10→16、FF 5276→6074、BRAM 不变 16。表中 Overhead 列（10.94%/6.67%/1.92%）是相对 FPGA 器件总容量的增量占比，而正文「约 29% 面积增长」是修改版相对基线的膨胀——两个不同分母，读表易混淆。软件侧未挖的空间：matrixMultiply 明确用基础 O(n³)（无循环展开 / 分块 / 乘加融合）；SoftMax 与 LayerNorm 仍走浮点——软浮点库并未彻底清除。

§04 · 主要贡献

可转述的四个判断

1全真实 > 仿真加速
训练-量化-裸机-上板贯穿始终——每一分加速对应的精度损失都有数字（82.5→~80），回应既有工作「仿真测加速、无法评估精度退化」的缺口。
2裁剪知道哪里能下刀
深度 12→1 + MLP 256→24 是安全刀口（深度容量主要为多类买单）；归一化向量 DIM 不能砍——砍它等于压缩表示本身。
3非对称双 scale 有机理支撑
权重 0-1 可用大 scale（64）提精度；输入幅值数百、scale 64 触发溢出（82.5→65.2）——不是经验调参而是取值范围的必然。
4最小面积的非线性算子加速
GELU 分段近似（梯度下降寻优阈值，退化 0.0042%）+ SoftMax LUT（依赖数值稳定形式的有界性）——29% 面积 + 2.69kB ROM 换 2.4× 周期。

§05 · 局限性与展望

双类设定让精度数字失去可比性；「迷你 Transformer 好不好」没关上

方法局限

  • 任务设定根本局限：双类（notdog 混 34 词为负类），87.2/82.5% 与 35 类 96.9% 不在同一难度平面；~80% 绝对精度对商用唤醒词不够，且无 FAR/FRR/DET。
  • LUT 依赖标定：e^(max−x) ∈ [0,10] 是该模型/特征/数据上的经验事实——换模型越界就要重标，加速器不即插即用。
  • 软件未优化：O(n³) 朴素矩阵乘、SoftMax/LN 仍浮点——周期数还有可观软件压缩空间。
  • 功耗是推断：周期数 ×固定每周期能耗的假设，无实测；FPGA 动态功耗与 ASIC 流片有差距。

实验设计不足

  • 覆盖窄：单数据集、单平台、单次综合，无多种子无方差。
  • 零外部基线：无 DS-CNN / BC-ResNet / MatchboxNet，也无 TFLite Micro 同平台实测——「1646 参数的 Transformer」在同预算下是否优于成熟 CNN 无从判断。
  • 训练细节缺失：epoch / 优化器 / 学习率 / 数据划分全未报——结果难精确复现。
  • scale 搜索粗：只 2 的幂五个组合；无 QAT 对照——PTQ 与 82.5% 之间还有多少空间未知。
  • 无噪声/远场测试——唤醒词真实部署环境的常态缺位。
值得追的方向：① 输出类扩展到多唤醒词 + 误唤醒 / 漏检率评估；② QAT 替代纯 PTQ + SoftMax/LN 定点化，彻底清除软浮点；③ LUT 有效域自动标定流程让加速器可移植；④ 矩阵乘换优化实现（分块 / 展开 / 乘加融合）、库扩展到卷积算子；⑤ 最有价值的补课：真实芯片或系统 FPGA 功耗实测 + 与 CNN 系小模型同 RAM 预算正面对比——回答「在微控制器上迷你 Transformer 到底是不是好选择」这个开了头没关上的问题；⑥ 线性 attention / 低秩近似等结构性降本 + VAD-KWS 级联摊薄平均功耗。
