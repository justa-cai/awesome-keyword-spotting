## 问题陈述

### 问题背景和领域痛点

关键词识别（KWS）指在流式音频中检测预定义关键词的任务。随着物联网与智能座舱的快速发展，以唤醒词检测（WWD）为代表的 KWS 系统已深入日常生活。论文开篇就把这类系统的工程本质点透了：要在「尽量少的误报、尽量高的召回、尽量低的计算负担」三者之间找平衡。前两条是精度约束——误报多了用户被莫名打扰，漏唤醒多了交互入口形同虚设；第三条是资源约束——唤醒词模型部署在边缘设备上，必须用轻量网络迁就有限的算力与存储。三者的张力之所以尖锐，根源在于唤醒词系统是常驻运行的：它不像一次性调用的 App，而是每时每刻都在消耗算力的守夜人，任何一次不必要的计算都会被全天候放大。

Transducer（RNN-T）近年来在语音识别、语音翻译和 KWS 上都取得了成功，是这一任务的主流架构选项之一。但由于唤醒词模型要部署在端侧，网络必须轻量。Tiny Transducer（ICASSP 2021，文献[15]）给出了一个成熟范式：用 DFSMN 块做编码器、无状态网络做预测器、线性层做 joiner 来压缩参数量，专为端侧流式识别设计；后续的小脚印唤醒词工作（文献[12]）与 CaTT-KWS（文献[14]）都沿用同一网络架构，本文也部分沿用其配置。这条脉络说明「Transducer 做端侧 KWS」在架构层面已经有共识，剩下的问题出在解码与搜索层面。

痛点恰恰在这里。尽管 Transducer 性能优异，其自回归解码是计算密集的，会引入可观的计算延迟，对在有限硬件资源上运行的 KWS 尤其致命。更具体的表现是搜索方式：现有 KWS 搜索算法普遍走帧同步路线，每一帧都要重复做搜索决策——而绝大多数帧与关键词无关（静音段、非关键词语音）。为一个几秒钟才出现一次的词支付逐帧全量的搜索代价，是这类系统算力浪费的结构性根源。论文摘要的第一句技术判断即是冲此而来：既然多数帧与关键词无关，凭什么每帧都做决策？

### 现有方法的具体不足

论文指出现有 Transducer 类 KWS 存在一条共同的技术路线及其缺陷：据作者所知，所有已有的 Transducer-based KWS 系统（文献[10][11][12][13][14]）都采用「直接跑常规 ASR 解码、再检查解码输出里是否含关键词」的直白做法。这种做法的不足可以拆成三层：

- **搜索空间不加约束**。ASR 解码在整个词表空间里搜索完整假设，而 KWS 只关心固定关键词在与不在。把概率质量与搜索算力分配给大量与任务无关的 token 路径，既不有效也不高效（论文原话 neither effective nor efficient）。数字佐证见论文 Table 2：RNN-T KWS 用贪心搜索在 Hey Snips 上宏召回只有 79.7，束宽 10 的束搜索也只有 89.4，而把搜索空间约束到关键词本身后（Proposed 行）达到 98.7；在更难的 test-other 上差距更悬殊（57.6 与 60.0 对 88.1），相差接近三十个百分点。
- **自回归依赖推高解码成本**。ASR 解码中预测器被递归地喂入部分假设（partial hypotheses），每个假设 token 都要更新预测器状态再做 joiner 计算，解码计算量随假设长度增长，在资源受限硬件上代价高昂。
- **帧同步决策本身就是浪费**。RNN-T 的搜索每一帧都必须做一次决策（论文 Algorithm 1 中 RNN-T 分支的步长 d 恒为 1），哪怕该帧纯属静音或与关键词毫无关系的语音。跳不掉帧，就省不下这部分计算。

另一方面，新近提出的 Token-and-Duration Transducer（TDT，ICML 2023，文献[17]）通过联合预测 token 及其时长，在一系列序列建模任务上同时取得了比常规 RNN-T 更好的性能和显著加速。它精巧的设计与优势使其天然适合 Transducer 相关的 KWS 系统——但 TDT 的默认搜索算法同样是为 ASR 任务设计的，不考虑 KWS 任务特性，直接搬来用照样既不有效也不高效。这就是本文要填补的空白：TDT 的潜力需要一种 KWS 专用的解码算法才能充分释放。

### 该论文要解决的关键挑战

论文要同时回答三个环环相扣的问题。第一，如何为 Transducer 设计 KWS 专用的流式解码算法：把搜索空间约束到固定关键词上，同时支持关键词在连续语音流中任意时刻开始——唤醒可能发生在任何一帧，这是流式唤醒检测与固定 utterance 分类的本质区别，起始点不确定使朴素的路径枚举不可行。第二，如何把 TDT 引入 KWS 并利用时长预测实现帧异步搜索，在召回不掉点的前提下拿到真实可测的推理加速，而不是纸面上的理论加速。第三，加速是否以鲁棒性为代价：真实设备工作在嘈杂环境，低信噪比下既能保住召回又能压住误报、还能维持加速，才算端侧可用的完整方案。

## 方法论

### 整体架构设计和设计动机

TDT-KWS 的网络骨架沿用 Tiny Transducer 的配置：编码器由 6 层 DFSMN 组成，隐层与投影维度分别为 512 和 320，所有 DFSMN 层的左右上下文帧设为 8 和 2；预测器采用 NeMo 中的无状态实现，上下文大小为 2、嵌入维度 320；joiner 把 320 维的编码器输出与解码器输出变换到 256 维表示，经激活后投影到最终输出。建模单元是 70 个单音素（来自 CMU 发音词典 cmudict-0.7b）加一个 blank 符号；TDT 模型的输出单元额外包含可选的时长输出。两种模式的模型都约 2M 参数，符合端侧 KWS 的体量。RNN-T 与 TDT 用完全一致的网络配置，只差时长头——这让 Table 3 里两者的对比是干净的控制变量实验。

几个设计选择背后的为什么。其一，为什么用 DFSMN 做编码器而不是 LSTM 或 Conformer：DFSMN 是前馈记忆块结构，参数效率高，Tiny Transducer 已在端侧流式识别上验证过这条路线，小脚印唤醒词后续工作与 CaTT-KWS 都沿用，工程上是被反复确认的低风险选择；论文的表述是沿用 Tiny Transducer 的编码器架构与超参设置。其二，为什么用音素级建模单元：唤醒词是固定词表的小任务，音素单元让任意关键词都能由一整套小词表组合出来（本文 LibriKWS-20 的 20 个关键词全部由同一套 70 音素覆盖），输出层轻，且换关键词不必换输出单元。其三，为什么时长头的开销可以无视：TDT 用于时长预测的额外参数只占总参数量的 0.1%（论文 3.2 节），即约两千个参数的量级，却换来搜索步数成倍下降——典型的以极小代价博取大收益。

训练配置同样遵循该系列惯例：在线语音扰动（扰动因子从 0.9、1.0、1.1 中随机采样）；声学特征为 40 维 log 梅尔滤波器组系数，25 毫秒窗长、10 毫秒帧移；SpecAugment 的频率遮罩最大 F=10、时间遮罩最大 T=50，每样本各用两个；左右各拼接 5 帧上下文构成 440 维特征（40 维乘 11 帧），帧跳参数设 3 实现三倍子采样。训练数据的组织因数据集而异：LibriKWS-20 上直接用 LibriSpeech-960h 训练；Hey Snips 上先用 LibriSpeech-960h 预训练的模型初始化，再用 Hey Snips 全部正样本加等量从 LibriSpeech-960h 随机抽取的语句联合训练。之所以不把 Hey Snips 负样本放进训练，是因为该数据集负样本没有完整转写文本，只能留作误报评估用——这也解释了为什么要额外抽 LibriSpeech 语句来平衡训练分布。

### 核心算法的数学原理

Transducer 由编码器、预测器、joiner 三模块组成：编码器吃声学特征、捕获语音信号的声学特性；预测器（论文中也称 decoder）吃文本输入，通常是音素、字素或子词这类语言单元；两者的高层表示送入 joiner，在每个格点生成分布 P(v|t,u)，其中 v 可以是词表中任意 token 或特殊 blank 符号，t 与 u 分别是声学帧索引与文本 token 索引。三个模块联合训练，目标是最大化给定声学输入下正确标注的概率，而该概率通过对输入输出之间所有可能对齐路径求和得到——对齐的引入方式是在标注序列中插入 blank。这正是 Transducer 类模型需要「搜索」的原因：训练时用前向-后向隐式穷举对齐，推理时要在格点图上找最优路径。

TDT 在此之上做了一处关键扩展：joiner 的输出从 P(v|t,u) 升级为联合分布 P(v,d|t,u)，新增变量 d 是该位置预测的时长。原文采用一个简单的条件独立假设（式 1）：P(v,d|t,u) = PT(v|t,u) · PD(d|t,u)，即 token 分布与时长分布解耦、各占一个输出头。这个假设的工程价值有两层：时长头可以做成极小的附加输出（0.1% 参数），且两个头并行计算、不引入新的串行依赖。时长预测 d 在推理时引导解码跳过输入帧：Dmax 是训练前预设的超参数，例如 Dmax=4 时可选时长集合为 0 到 4；Dmax 越大，模型的跳帧行为越激进。引入时长建模后，TDT 执行帧异步搜索，相比帧同步的 RNN-T 类系统取得显著加速——这是论文把 TDT 引入 KWS 的直接动机。

KWS 解码算法的数学骨架如下。记声学特征序列 x，关键词 token 序列 y = {y0=blank, y1, …, yU}。按标准 Transducer 记号定义发射概率（式 2、式 3）：y(t,u) = P(y_{u+1} | x[1:t], y[0:u])，φ(t,u) = P(φ | x[1:t], y[0:u])，即给定前 t 帧声学与关键词前 u 个 token 的条件下，下一个 token 是第 u+1 个关键词元素、或是 blank 的概率。在论文 Fig.1 的解码格点图上，每个节点 (t,u) 表示到 t 时刻为止已输出关键词前 u 个元素的最优路径得分，竖直箭头对应发射关键词 token 的概率 y(t,u)，水平箭头对应发射 blank 的概率 φ(t,u)。定义 δ(t,u) 为到达节点 (t,u) 的所有路径中得分最高者的分数，用动态规划递推（Algorithm 1 第 5 行）：δ(t,u) = max( δ(t,u−1)·y(t,u−1), δ(t−d,u)·φ(t−d,u) )。t 时刻的关键词置信度由式 4 给出：Score[t] = δ(t,U) · φ(t,U)，即「到 t 时刻恰好完整输出全部 U 个关键词 token 的最优路径分数」再乘上该格点继续发射 blank 的概率。结合 Fig.1 理解，乘 blank 这一项相当于给置信度加上「关键词在此刻收尾、而非更长词的前缀」的收尾约束。

### 关键技术创新一：KWS 专用的流式解码算法

这是论文最核心的贡献（Algorithm 1），适用于常规 Transducer 与 TDT，也可推广到其他 Transducer 变体。算法由三个互相咬合的设计构成。

**设计一：预测器只吃关键词 token 序列。** 与 ASR 解码把部分假设递归喂给预测器不同，本算法只把解码的关键词 token 序列喂给预测器。理由是 KWS 的主要目标是判断关键词在与不在，而不是生成完整假设。论文类比这是 RNN-T 损失的并行计算或自回归模型训练常用的 teacher forcing 策略。这一改变的意义远不止省一点计算：预测器的输入从「长度不确定的假设前缀」固定为「长度至多 U 的关键词前缀」，(t,u) 格点上的概率于是可以按关键词前缀系统性算出，整个动态规划才有良定义的基础。从算法结构看，每帧的 DP 开销与关键词 token 数 U 同阶、与词表大小无关——音素级的关键词不过十几个 token，搜索开销天然很小。

**设计二：δ(t,0)=1，支持任意时刻开始的关键词检测。** 流式场景中唤醒词可能从任何时刻开始，算法在每个时间步 t 都把 δ(t,0) 置为 1（Algorithm 1 第 3 行），相当于允许「关键词从这一帧重新开始」的假设免费入场。这一步解决了流式唤醒检测里最微妙的起始点问题：不需要显式枚举所有可能的起始时刻，DP 自动维护从任意起点出发的最优路径。论文强调这正是该算法能无缝支持连续语音中唤醒词检测的机制所在。

**设计三：TDT 分支的时长引导跳帧。** RNN-T 分支中步长 d 恒为 1，退化为帧同步搜索；TDT 分支在每步计算 d = argmax PD(d|t,G) 与 v = argmax PT(v|t,G)，把预测出的 token v 追加进已解码历史 G，随后把被跳过的 t+1 至 t+d−1 帧的 Score 直接置零，t 前进 d 帧（Algorithm 1 第 11 至 18 行）。被跳过的帧既不产生置信度输出、也不触发搜索计算——这就是帧异步搜索的实现载体。这里有个值得注意的细节：DP 格点上的 y(t,u) 与 φ(t,u) 以关键词前缀 y[0:u] 为条件（teacher forcing 式），而决定跳几帧的时长与 token 分布以贪心解码历史 G 为条件——两套条件各司其职，前者保证路径分数的可计算性与一致性，后者为跳帧决策提供已解码上下文。

这套算法为什么比 ASR 解码更准？论文 4.1 节给出的解释是：搜索空间被限制在关键词本身而非所有可能的解码序列，模型不必在与任务无关的词表路径上分散概率质量。Table 2 的数字是硬证据：RNN-T KWS 上贪心 79.7 提升到本文算法 98.7（Snips），test-other 从 57.6 提升到 88.1；TDT-KWS 上贪心 85.4 提升到 98.9。基于此，论文后续所有实验统一只用 KWS 专用解码算法。

### 关键技术创新二：把 TDT 引入 KWS 并转化为真实加速

TDT 源自同一团队先前的一作工作（文献[17]），原始应用是一般序列建模任务。本文的判断是：TDT 的设计与优势使其适配 Transducer 相关的 KWS 系统——因为 KWS 音频里绝大多数帧与关键词无关，恰是时长引导跳帧最能发挥的场景。加速的机制性解释：RNN-T 每帧都要做一次搜索决策，模型调用次数等于帧数；TDT 一次可跨多帧，模型调用次数随 Dmax 增大而下降。Table 3 显示加速随 Dmax 单调上升：Dmax=2 时相对搜索加速 1.44 至 1.57 倍，Dmax=4 时 3.20、2.03、1.98 倍，Dmax=8 时 4.09 倍，Dmax=10 时 4.19 倍（均为 Snips 列，Table 3）。论文 Fig.2 的 (t,u) 格点热图给出直观证据：对 test-clean 中关键词为 everything 的例句，TDT 明显更少的搜索频率清晰可见，竖直黄虚线标出强制对齐得到的词边界。摘要层面给出的总括数字是推理加速 2 至 4 倍（引言贡献第二条）。

值得一提的是加速的两种口径：相对搜索加速只量推理模块（搜索算法）本身，相对运行加速量整个系统。跳帧只作用于搜索端，特征提取与编码器开销不变，所以系统级加速略低于搜索级加速（如 Dmax=10 时 Snips 上搜索 4.19 倍、系统 3.58 倍，Table 3）——分开报告才能看清加速来源与端到端真实收益，这是论文在指标设计上的细致之处。

### 与现有方法的技术差异

与「ASR 解码加关键词匹配」路线（文献[10] 至 [14] 的全部工作）相比，本文把搜索空间约束到关键词、把预测器输入固定为关键词序列、用 DP 路径分数显式定义关键词置信度，而不是从自由解码的文本里做事后字符串匹配——准与快两端同时受益（Table 2 与 Table 3）。与原生 TDT-ASR 相比，原生 TDT 的默认搜索算法为 ASR 任务设计、不考虑 KWS 特性，本文把 TDT 的时长跳帧嫁接到 KWS 专用 DP 搜索上；摘要的结论是 TDT-KWS 达到与常规 RNN-T 及传统 TDT-ASR 系统持平或更好的唤醒检测性能，同时显著加速——对应 Table 2 中 TDT-KWS 贪心 85.4 对本文算法 98.9 的对比。与帧同步 RNN-T KWS 相比，在完全相同的约 2M 参数与编码器配置下，TDT-KWS 三个测试集召回持平或更好（Table 3），额外获得成倍加速，且噪声下优势进一步拉大（Fig.3）。

## 实验结果

### 使用的数据集及其规模

实验覆盖三个场景：固定单关键词 utterance 检测、连续语音中的关键词检测、噪声环境下的检测，分别由三个数据源支撑。

- **Hey Snips**（开源 KWS 数据集）：关键词为 Hey Snips，两词之间连续发音不停顿。训练、开发、测试集分别有 5876、2504、2588 条正样本 utterance，以及 45344、20321、20821 条负样本。因负样本无完整转写，只用于误报评估、不进训练。误报评估集由训练、开发、测试全部负样本拼接而成，约 97 小时音频。
- **LibriSpeech 与自建 LibriKWS-20**：LibriSpeech 是 960 小时带转写的朗读英语语料。为模拟连续语音流中检测唤醒词的场景，从中选 20 个词作关键词，构成 KWS 版语料 LibriKWS-20。关键词列表见论文 Table 1（almost、anything、behind、captain、children、company、continued、country、everything、hardly、himself、husband、moment、morning、necessary、perhaps、silent、something、therefore、together），test-clean 与 test-other 两个测试集用同一组关键词。误报集由测试集中不含所选关键词的音频拼接而成，两个测试集各约 3 小时。
- **WHAM!**（噪声语料库）：在餐厅、酒吧等城市环境实录的环境噪声，覆盖多种真实场景。取其测试部分与 Hey Snips 正样本在不同信噪比下混合，做鲁棒性评测。

### 评估指标的定义和选择理由

召回率固定在特定误报率下报告（recall at a specific FAR）。选择理由：唤醒词系统的实际工作点由误报预算决定——每小时误报次数是用户可直接感知的打扰频率，在同等打扰水平下比较召回才有工程意义的可比性。Hey Snips 上的工作点为 FAR=0.02 次/小时，即 97 小时误报集上 2 次误报（Table 3 标题）；LibriKWS-20 上为平均 FAR=0.67 次/小时，即 3 小时上 2 次。因 LibriKWS-20 含 20 个关键词，采用跨关键词的宏召回与平均 FAR：多关键词下整体性能不应被单个关键词主导，宏平均对每个关键词等权，这是多类检索任务的标准处理。推理速度用两个指标：系统整体推理加速（相对运行加速）与推理模块执行加速（相对搜索加速）。分开定义的理由如方法论节所述：跳帧只作用于搜索模块，混在一起报告会稀释真实加速来源。两者均相对 RNN-T 基线测量。

### 与基线方法和 SOTA 的详细对比

**解码算法对比（Table 2，宏召回）**：RNN-T KWS 用贪心搜索在 Snips、test-clean、test-other 上分别为 79.7、82.5、57.6，束宽 10 的束搜索为 89.4、82.7、60.0，本文算法为 98.7、97.5、88.1——test-other 上比贪心高 30.5 个点、比束搜索高 28.1 个点。TDT-KWS 上贪心为 85.4、84.6、63.2，本文算法为 98.9、98.3、87.9。论文注明为公平比较，各系统的误报水平保持相近；TDT 的束搜索实现在写作时尚不可用（Table 2 注），故 TDT 无束搜索行。这组实验说明性能提升的第一来源不是换模型而是换搜索：同一模型、同一训练，只把解码从自由搜索换成关键词约束搜索，召回即可提升十到三十个点。

**RNN-T 对 TDT（Table 3）**：RNN-T 基线在 Snips、test-clean、test-other 上召回为 98.1、99.0、90.2。TDT-KWS 各 Dmax 设置下：Dmax=2 为 98.2、97.9、89.3（相对搜索加速 1.44、1.57、1.57 倍）；Dmax=4 为 98.0、98.5、91.9（3.20、2.03、1.98 倍），其中 test-other 的 91.9 超过基线 90.2；Dmax=6 为 97.7、99.1、90.3（3.63、2.06、2.03 倍），其中 test-clean 的 99.1 超过基线 99.0；Dmax=8 为 96.2、98.8、90.9（4.09、2.06、2.00 倍）；Dmax=10 为 98.6、98.7、89.5（4.19、2.15、2.05 倍）。相对运行加速（系统级）从 Dmax=2 的 1.39 至 1.54 倍到 Dmax=10 的 3.58、2.04、1.97 倍。总括结论：召回持平或更好的前提下，搜索模块加速约 1.4 至 4.2 倍、系统整体加速约 1.4 至 3.6 倍。

**噪声鲁棒性（Fig.3）**：用 WHAM! 测试噪声给 Hey Snips 正样本加噪，信噪比取 0、5、10、15、20 dB，模型不在加噪数据上重训；图例中对比的是 TDT-10（即 Dmax=10）模型，横轴另含 +inf 表示不加噪。结果（Fig.3 左子图）显示随噪声增强，RNN-T KWS 与 TDT-KWS 的性能差距进一步拉大，TDT 一致更优；同时 TDT-KWS 在各信噪比下一致保持对 RNN-T 的搜索加速（Fig.3 右子图）。各信噪比下的逐点精确数值论文未以表格形式报告，以曲线图呈现（Fig.3）。论文的结论是 TDT 模型不仅在噪声中性能更好，还通过持续稳定的加速维持了效率，使其成为噪声环境下 KWS 的有前景选择。至于 TDT 为何在噪声中更占优，论文只报告现象、未解释机理；从机制上推测（笔者分析，非论文观点），帧同步搜索在每帧都做一次决策，噪声让逐帧 token 判断更不确定、错误决策逐帧累积，而 TDT 的时长机制相当于在时间维度上聚合声学证据、跳过不确定帧，减少了错误传播的机会。

### 消融实验的发现

论文最系统的消融是 Dmax 扫描（Table 3），揭示了一个任务依赖的分化现象。

- **Hey Snips 对大 Dmax 不敏感**：Dmax 从 2 拉到 10，Snips 召回在 96.2 至 98.6 间波动，Dmax=10 仍有 98.6，Dmax=8 的 96.2 是唯一明显低点。论文 4.2 节的解释：每条正样本由静音段加 Hey Snips 这一个短语构成，模式相对简单，模型容易学会哪几帧含关键语音信息，即使跳掉大量帧也能自信定位关键帧，因此大 Dmax 下表现依然出色。
- **LibriKWS-20 存在甜点区**：test-clean 在 Dmax=6 达 99.1（该列全表最高），test-other 在 Dmax=4 达 91.9（该列全表最高）；Dmax 超过 6 后性能逐渐退化。论文的解释分两层：较难的语料上，不太大的 Dmax 让模型选择性忽略干扰帧、聚焦含关键音素信息的帧，性能反而提升——跳帧从省算力的手段意外变成了涨精度的正则化；但 Dmax 显著增大后，模型可能跳过本该被预测的 token，导致退化。这组发现勾勒出性能与计算效率之间的权衡边界：Dmax 是旋钮，甜点位置由任务难度决定。
- **加速随 Dmax 单调上升但边际递减**：Snips 列搜索加速从 Dmax=4 的 3.20 倍到 Dmax=8 的 4.09 倍再到 Dmax=10 的 4.19 倍，增益趋缓；test-clean 与 test-other 上 Dmax 达 4 之后加速基本平台化在 2.0 至 2.05 倍附近。合理的解释是有效跳帧量受语料中连续可跳帧数量的物理约束，静音段长度有上限，Dmax 再大也无帧可跳。
- 另一组广义消融是解码算法本身的对比（Table 2，见上一小节），证明收益的第一来源是搜索空间约束而非模型差异；Fig.2 的热图则从单条语音的微观视角佐证了跳帧行为的发生。

## 主要贡献

1. **提出面向 Transducer 的 KWS 专用流式解码算法**：以 δ(t,0)=1 支持关键词任意时刻开始、预测器只喂关键词 token 序列、用动态规划显式计算关键词路径置信度。该算法对常规 Transducer 与 TDT 通用，在三个测试集上大幅超越常规 ASR 解码算法（Table 2：如 test-other 从 57.6 到 88.1）。
2. **提出 TDT-KWS，首次把 Token-and-Duration Transducer 引入 KWS**：在开源 Hey Snips 与自建 LibriKWS-20 上取得与常规 RNN-T KWS 持平或更好的性能（Table 3），推理额外加速 2 至 4 倍（摘要与引言），时长预测的参数代价仅占总量的 0.1%。
3. **验证低信噪比下的鲁棒性优势**：WHAM! 加噪实验（Fig.3）显示噪声越大、TDT-KWS 相对 RNN-T KWS 的性能差距越大，且加速在不同信噪比下保持——对极端环境下压低误报、守住唤醒率有实际意义。

## 局限性与展望

### 方法的技术局限性

- **条件独立假设的建模损失**：式 1 把 token 分布与时长分布解耦。该假设换来极小的开销（0.1% 参数）与实现简单，但 token 身份与持续时长天然相关——不同音素的时长分布差异很大，解耦建模可能损失部分联合信息。论文未对假设本身做对照实验，其影响几何未知。
- **置信度分数未归一化**：Score[t] 是路径概率连乘，数值随关键词 token 数 U 增大单调变小，理论上不同长度的关键词不宜共用同一触发阈值。论文用固定 FAR 的宏平均评测回避了显式阈值标定问题，但实际多关键词系统部署时长度偏置可能显现。论文未讨论此点。
- **跳帧决策依赖贪心历史且不可回溯**：TDT 分支的时长预测以贪心解码历史 G 为条件（Algorithm 1 第 11、12 行），贪心错误会传导进跳帧决策，且被跳过的帧无法追回。4.2 节观察到的大 Dmax 下「跳过本该预测的 token 导致退化」，正是该机制无纠错能力的直接体现。
- **TDT 侧缺少束搜索对照**：Table 2 注明 TDT 的束搜索实现在写作时不可用，TDT-KWS 只与贪心版 ASR 解码对比过解码算法，未与更强的束搜索 ASR 解码正面对垒，解码算法对比一侧不完整。
- **多关键词的搜索成本未量化**：算法针对固定关键词设计，20 个关键词靠逐词宏平均评测；关键词数量增加时每个关键词需各自维护 DP 搜索，其代价如何扩展论文未报告。

### 实验设计的不足

- **LibriKWS-20 是自建仿真场景**：从朗读语料选词模拟连续语音检测，与真实唤醒词的口语化发音、远场混响、信道差异仍有距离；误报集仅约 3 小时，FAR=0.67 次/小时的工作点只对应 2 次误报的样本量，统计置信度有限。
- **Hey Snips 负样本未参与训练**：因无转写文本，97 小时负样本只用于评测。负例监督的缺失可能影响模型对易混淆词的抑制；论文未尝试以无监督方式利用这部分数据压误报。
- **缺少与非 Transducer 路线的对比**：未与 cFSMN、DS-CNN、MatchboxNet 等经典或主流小脚印 KWS 架构比较，也未与同为 Transducer 系多阶段方案的 CaTT-KWS 正面比较，TDT-KWS 在更大 KWS 版图中的位置无法定位。
- **只报告单一工作点**：Table 3 仅在 FAR=0.02 次/小时与 0.67 次/小时两个单点上比较，没有完整的 ROC 或 DET 曲线，不同误报预算下的相对优劣不可见。
- **加速为相对值、缺绝对量与硬件信息**：论文未报告测试硬件平台、绝对实时率、内存占用与功耗，只有相对 RNN-T 的倍数，端侧部署的真实收益与能耗代价无法直接换算。
- **噪声评测维度单一**：仅 WHAM! 加性噪声且不重训（多条件训练缺位），未覆盖混响、多说话人、音乐等真实噪声类型，Fig.3 的逐点数值也未列表给出。

### 未来可能的改进方向

论文结论中自己指出两个方向：在更复杂的声学环境中进一步探索 TDT-KWS 的潜力；继续优化解码算法。结合上述局限还可以推演出若干具体路线：对时长头做 token 条件化或联合建模，以放宽条件独立假设换取精度上限；对置信度做长度归一化或引入多关键词统一阈值的标定方法，使宏平均场景下触发逻辑更稳；把 KWS 专用解码与量化、剪枝等端侧压缩手段叠加，验证复合加速收益；在真实远场唤醒数据上做多条件训练并复验噪声结论；利用无转写负样本做误报抑制类训练（如对比学习或负例微调）以进一步压低 FAR；把解码算法推广到自定义唤醒词与多关键词共享搜索结构，降低关键词数量增长带来的搜索开销。
