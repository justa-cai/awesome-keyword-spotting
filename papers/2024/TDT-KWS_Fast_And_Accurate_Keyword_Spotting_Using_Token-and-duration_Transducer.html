多数帧与关键词无关，凭什么每帧都做决策？——
锁死搜索空间 + 时长跳帧，准与快两端同时受益

TDT-KWS: Fast and Accurate Keyword Spotting Using Token-and-Duration Transducer

作者：Yu Xi、Hao Li、Baochen Yang、Haoyu Li、Hainan Xu、Kai Yu（通讯）—— 上海交大 X-LANCE · 思必驰 · NVIDIA

发表：arXiv 2403.13332（2024-03）· ~2M 参数端侧配置，TDT 时长头仅占 0.1%

KWS 专用流式解码δ(t,0)=1 任意起点帧异步跳帧搜索 test-other 召回 57.6→88.1搜索加速 1.4–4.2×噪声下优势拉大

一分钟版本

  • 痛点：常驻系统的结构性浪费。唤醒词系统是每时每刻都在耗算力的守夜人——误报、召回、计算负担三角张力尖锐。Transducer 性能好但自回归解码计算密集；更结构性的是所有已有 Transducer KWS 都「直接跑 ASR 解码再检查输出里有没有关键词」：搜索空间不加约束（概率质量与算力分配给无关 token 路径）、自回归假设递归推高解码成本、帧同步决策让静音段也逐帧付账——为一个几秒出现一次的词支付逐帧全量搜索代价。
  • 核心算法（对 RNN-T 与 TDT 通用）三个咬合设计：① 预测器只吃关键词 token 序列（teacher forcing 式）——每帧 DP 开销与关键词长度 U 同阶、与词表大小无关；② δ(t,0)=1——每个 t 都允许「关键词从这帧重新开始」的假设免费入场，DP 自动维护任意起点最优路径（流式唤醒最微妙的起始点问题被一行解决）；③ TDT 分支时长引导跳帧——每步 d=argmax P_D，跳过的帧不产生置信度也不触发搜索。
  • 收益第一来源是搜索不是模型（Table 2 硬证据）：同一 RNN-T 模型，贪心→本文算法在 test-other 上 57.6→88.1（+30.5 点）、束搜索 60.0→88.1；TDT 上 63.2→87.9。越难的集，锁死搜索空间的收益越大。
  • TDT 首次进 KWS：joiner 输出升级为 P(v,d|t,u)=P_T(v)·P_D(d)（条件独立，时长头仅 0.1% 参数）——一次跨多帧，模型调用次数随 Dmax 下降。召回持平或更好（Snips 98.6 vs 基线 98.1；test-other Dmax=4 的 91.9 还超基线 90.2）的前提下，搜索加速 1.4–4.2×、系统级 1.4–3.6×。
  • Dmax 甜点由任务难度决定（最有信息量的消融）：Snips（静音+一个短语，模式简单）对大 Dmax 不敏感；LibriKWS-20 甜点在 4–6——适度跳帧意外成为「聚焦关键帧」的正则化，跳过头则漏 token 退化；加速边际递减（静音段长度有上限，无帧可跳）。
  • 噪声鲁棒：WHAM! 加噪不重训——噪声越大 TDT 相对 RNN-T 优势越大，且各 SNR 下加速保持。机理（笔者推测）：帧同步在噪声下逐帧决策错误累积，TDT 时长机制在时间维聚合证据、跳过不确定帧。
  • 边界：条件独立假设未做对照实验；置信度未长度归一化（不同长度关键词不宜共用阈值，论文靠固定 FAR 宏平均回避）；跳帧依赖贪心历史不可回溯（大 Dmax 退化的直接体现）；TDT 侧缺束搜索对照；加速只有相对倍数（无硬件、绝对 RTF、功耗）；LibriKWS-20 是自建仿真且误报集仅 ~3 小时（FAR=0.67/h 对应 2 次误报，统计置信度有限）。

§01 · 问题陈述

架构层面已有共识，问题出在解码与搜索层面

三层不足拆解：① 搜索空间不加约束——ASR 解码在整个词表空间搜索完整假设，而 KWS 只关心固定关键词在与不在，把概率质量与算力分配给无关路径「既不有效也不高效」（RNN-T 贪心在 Snips 宏召回只有 79.7、束 10 也只 89.4，约束到关键词后 98.7）；② 自回归依赖推高成本——预测器被递归喂部分假设，每个假设 token 都要更新预测器状态再做 joiner 计算，解码计算量随假设长度增长；③ 帧同步决策本身是浪费——每帧都必须做一次搜索决策（步长 d≡1），哪怕纯属静音。
为什么是 TDT：Token-and-Duration Transducer（ICML 2023，同团队前作）联合预测 token 及其时长，在序列建模上同时拿到更好性能与显著加速——KWS 音频里绝大多数帧与关键词无关，恰是时长引导跳帧最能发挥的场景。但 TDT 的默认搜索同样为 ASR 设计、不考虑 KWS 特性，直接搬来照样不行——本文填补的空白：TDT 的潜力需要 KWS 专用解码算法才能释放。三个环环相扣的问题：KWS 专用流式解码（约束搜索空间 + 任意时刻起始）；时长预测换真实可测加速而非纸面理论值；加速不以鲁棒性为代价。

§02 · 方法论

格点上的动态规划 + 时长跳帧

图 1/2 复绘：格点图上竖直箭头发射关键词 token、水平箭头发射 blank；δ(t,0)=1 让新起点假设每帧免费入场——两个设计合起来把搜索从「全词表 × 全时刻」压缩到「关键词 × DP 自动管理的起点」。

P(v, d | t, u) = PT(v | t, u) · PD(d | t, u)
式 1 · TDT 的条件独立假设：token 分布与时长分布解耦、各占一个输出头。工程价值两层：时长头极小（0.1% 参数）、两头并行无串行依赖；代价是 token 身份与时长天然相关（不同音素时长分布差异大），解耦可能损失联合信息——论文未对此假设做对照实验（见 §05）。Dmax 是训练前超参，越大跳帧越激进。
δ(t,u) = max( δ(t,u−1)·y(t,u−1),  δ(t−d,u)·φ(t−d,u) )；  Score[t] = δ(t,U) · φ(t,U)
式 2–4 · DP 递推与置信度：y(t,u) 是发射第 u+1 个关键词 token 的概率（竖直箭头），φ(t,u) 是发射 blank 的概率（水平箭头）；Score[t] 取「到 t 时刻恰好完整输出全部 U 个 token 的最优路径分数」再乘该格点继续发 blank 的概率——乘 blank 这一项给置信度加上「关键词在此刻收尾、而非更长词前缀」的收尾约束。注意：路径分数以关键词前缀为条件（teacher forcing），跳帧决策以贪心历史 G 为条件——两套条件各司其职。

§03 · 实验与消融

固定 FAR 工作点 + 两种加速口径分开报告

数据与指标：Hey Snips（正样本 5876/2504/2588 训练/开发/测试；负样本无转写不进训练，拼成 ~97 小时误报集）；LibriKWS-20（自建：从 LibriSpeech-960h 选 20 个词模拟连续语音流检测，误报集各 ~3 小时）；WHAM! 噪声。指标：固定误报率下的召回（Snips FAR=0.02 次/h；LibriKWS-20 宏召回 @ 平均 FAR=0.67 次/h——20 关键词等权宏平均，不被单关键词主导）；加速分搜索模块级与系统级两种口径（跳帧只作用于搜索端，混报会稀释真实来源——Dmax=10 Snips：搜索 4.19× / 系统 3.58×）。

为什么换关键词不痛：建模单元是 70 个 cmudict 单音素 + blank——任意关键词都能由同一套小词表组合出来（LibriKWS-20 的 20 个词全部覆盖），输出层轻，换关键词不必换输出单元，只需换解码模板的 token 序列。网络骨架沿用 Tiny Transducer（ICASSP 2021）被后续多工作反复确认的低风险配置：DFSMN 编码器（前馈记忆块、参数效率高）+ 无状态预测器 + 线性 joiner，~2M 参数；RNN-T 与 TDT 版本网络完全一致只差时长头——Table 3 因此是干净的控制变量实验。

§04 · 主要贡献

三条贡献 + 一条可迁移判断

1面向 Transducer 的 KWS 专用流式解码算法：δ(t,0)=1 任意起点 + 预测器只喂关键词序列 + DP 显式路径置信度；对常规 Transducer 与 TDT 通用，三个测试集大幅超越 ASR 解码（test-other 57.6→88.1）。
2首次把 TDT 引入 KWS：持平或更好的召回 + 推理加速 2–4×，时长头参数代价仅 0.1%——极小代价博取大收益的典型。
3低信噪比鲁棒性验证：WHAM! 加噪下噪声越大优势越大、加速各 SNR 保持——对极端环境压误报守唤醒有实际意义。
★可迁移判断：当任务只关心固定小词表在与不在时，把「约束」写进搜索结构（预测器输入固定、搜索空间锁定、置信度按关键词路径定义）比换更强的模型收益更大、代价更小；而「跳过与任务无关的帧」不仅是省算力——适度跳帧还能当正则化用（聚焦关键帧），甜点位置由任务难度决定。

§05 · 局限与边界

贪心历史不可回溯，加速只有相对倍数

技术局限

  • 条件独立假设的建模损失：token 与时长解耦换来 0.1% 开销与实现简单，但不同音素时长分布差异大——联合信息损失几何未知，论文未做对照实验。
  • 置信度未归一化：Score[t] 是路径概率连乘，数值随关键词 token 数 U 增大单调变小——不同长度关键词不宜共用阈值；论文靠固定 FAR 宏平均回避显式阈值标定，多关键词部署时长度偏置可能显现。
  • 跳帧依赖贪心历史且不可回溯：时长预测以贪心解码历史 G 为条件，贪心错误传导进跳帧决策、被跳的帧无法追回——大 Dmax 下「跳过本该预测的 token」正是无纠错能力的直接体现。
  • TDT 侧缺束搜索对照（写作时实现不可用）+ 多关键词搜索成本未量化：20 个词靠逐词宏平均；关键词数量增长时每个词各自维护 DP 的代价扩展未报告。

实验设计不足

  • LibriKWS-20 是自建仿真：朗读语料选词模拟，与真实唤醒词的口语化发音、远场混响、信道差异有距离；误报集 ~3 小时，FAR=0.67/h 只对应 2 次误报——统计置信度有限。
  • Hey Snips 负样本未参与训练：97 小时负样本因无转写只用于评测——负例监督缺失可能影响易混淆词抑制，未尝试无监督利用。
  • 缺非 Transducer 路线对比：不与 cFSMN / DS-CNN / MatchboxNet 等经典小脚印架构比，也不与同为 Transducer 系的 CaTT-KWS 正面对垒——版图位置无法定位。
  • 单一工作点 + 相对加速：无完整 ROC/DET 曲线，不同误报预算下优劣不可见；无测试硬件、绝对实时率、内存、功耗——端侧真实收益无法直接换算；噪声仅 WHAM! 加性且不重训，未覆盖混响 / 多说话人 / 音乐。
值得补的方向：时长头做 token 条件化或联合建模，放宽条件独立假设换精度上限；置信度长度归一化或多关键词统一阈值标定；与量化、剪枝叠加验证复合加速；真实远场多条件训练复验噪声结论；利用无转写负样本做误报抑制训练（对比学习 / 负例微调）压 FAR；解码算法推广到自定义唤醒词与多关键词共享搜索结构，降低关键词数增长的搜索开销。
