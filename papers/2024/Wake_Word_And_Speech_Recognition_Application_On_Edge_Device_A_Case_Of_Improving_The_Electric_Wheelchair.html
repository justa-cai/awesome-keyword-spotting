轮椅的「大脑」不该在别人的手机里——
本地唤醒词常驻、云端识别只开一小扇窗

Wake Word and Speech Recognition Application on Edge Device: Improving the Electric Wheelchair

作者：Low Jian He（INTI 国际大学槟城 · 现萨里大学）；Solahuddin Yusuf Fadhlullah（通讯）、Khadijah Kamarulazizi；Samihah Abdullah、Shabinar Abdul Hamid（UiTM 槟城）

发表：Journal of Electrical and Electronic Systems Research Vol.24（UiTM Press，2024-04）· Pi 4 + 自造唤醒词「Hey SellTron」

应用案例研究（非算法创新）两级门控架构Pi 4 边缘部署 自造唤醒词数据工程11 条命令含 6 条位置命令命令依从性 100%

一分钟版本

  • 为什么「解放双手」是刚性需求：70–100% 手动轮椅使用者会出现上肢损伤（手腕 40–66%、肩膀 30–60%、腕管综合征 27–90%）；摇杆仍有机械磨损且对震颤 / 抓握障碍 / 高位截瘫用户不可及。语音是自然路径——但常开麦克风 = 连续计算 + 隐私暴露（41% 用户担忧），轮椅是贴身设备，矛盾比智能音箱更尖锐。
  • 核心架构判断（全文最重要的一句）：语音识别只应在指定唤醒词被唤起之后才激活——避免背景语音或偶然对话中的词句意外触发轮椅移动。两级门控：轻量本地 LSTM 常驻监听「Hey SellTron」→ 唤醒后才初始化 Google Speech API 做命令识别——连续计算压到最低、云端窗口压到最小。
  • 两代已有方案都不合格：Arduino + 专用语音模块（HM2007 等）= 小词表模板匹配硬件、需近讲、对说话人敏感、完全没有唤醒词门控（环境里说出命令词就直接动车——安全性致命）；手机 + 云 API = 「轮椅的大脑在别人的手机里」——行动障碍用户操作手机本身就是负担、依赖网络、隐私放大。作者声称这是首个把独立唤醒词系统集成到边缘轮椅原型的工作。
  • 自造唤醒词的数据工程（可直接照抄的路线图）：正样本 = 自录 500 条（Pi 自己的麦克风直录、避免信道染色）+ 多 TTS 网站多口音 + 组外真人；负样本 30,000 = Common Voice 15k + 环境音 15k（静默 + 公园 + 咖啡馆各 30 分钟切 2 秒片）。两处工程直觉：2 秒切片与运行时录音流严格对齐（训练=推理分布）；负样本专门放环境音让模型训练时就见过非语音噪声。SpecAugment 三件套是几百条原始录音能撑起来的关键放大器。
  • 混合架构各取所长（数据背书）：自训唤醒词在公园噪声 ≤55dB 保持 80%+ 且优于 Google Assistant（专属训练的红利）；命令识别最抗造（≤65dB 保持 80%+，Google 海量训练数据）——但咖啡馆会话噪声下唤醒词只能撑到 ~50dB（会话噪声与唤醒词同属人声更难分离）。
  • 最有信息量的失败数据：10 人多说话人测试精度从 20% 摆到 100%——正样本主力只有 500 条自录音，模型高度个性化缺乏说话人泛化（把猜测变成有数据的事实）；唯一命令短板 turn left 89%（被误识成 turn light，疑受智能家居语料影响），识别后执行 0 失手（依从性 100%）——全部风险集中在声学识别一侧。
  • 安全设计：无效命令不重试不猜测，直接退出回监听——任何误识别的最坏后果是「回到安全的静止待机态」；位置命令（「从卧室到厨房」）是预编程开环宏而非导航（论文自认真导航需 LiDAR 建图）。延迟：唤醒平均 0.73s（0.33–1.10）、命令约 1.5s。
  • 边界（案例研究的诚实读法）：LSTM 层数 / 隐维 / 学习率 / 模型大小 / 内存 / 功耗全未报告（难复现）；无误唤醒率与漏唤醒率的分离统计（与安全主张形成张力——唤醒词门控的存在意义恰恰是防误触发）；位置命令无传感器反馈、断网时命令不可用、mini 原型不具商业代表性；无严格消融（频谱增强 / 环境音负样本 / TTS 各贡献多少未知）。

§01 · 问题陈述

辅具工程问题，不是算法创新问题

痛点链条：上肢健康（流行病学数字触目惊心）→ 电动轮椅解决体力但摇杆仍需运动技能且有机械磨损 → 语音控制自然但「常开」与隐私 / 算力矛盾（微软 2019：41% 用户担忧被动监听）→ 两级门控解法（本地唤醒词常驻 + 按需激活识别）。工程伦理论证：用户的物理安全应足以抵消剩余隐私顾虑——轮椅失控撞墙的代价远大于一小段命令音频外泄。平台约束：Pi 4 适合边缘深度学习但跑不动全规模 transformer——必须轻量（LSTM）。
四个子挑战：算力（常驻模型必须轻到 Pi 4 能持续跑——答 LSTM）；数据（自造唤醒词无任何现成数据集，从零构建正负样本）；安全（唤醒词门控 + 无效命令失败路径——任何误识别不直接变成轮子转动）；验证（距离 / 噪声 / 多说话人 / 多命令 / 延迟五个维度把「可用性」量化）。命令空间从文献的方向命令扩展到位置命令——一句「去厨房」比连续喊方向高效得多（概念价值，实现是开环宏）。

§02 · 系统设计

计算负载的非对称分配

图 1–10 复绘：两级门控的计算负载非对称分配——常驻的只有 LSTM 前向推理这一件事（本地、轻量、无网络）；失败路径设计让任何误识别的最坏后果都是回到静止待机。

为什么混合架构而不是统一模型：唤醒词是极小类别二分类（是不是「Hey SellTron」），小模型就能胜任且必须本地常驻；轮椅命令虽是受限词表但论文想兼容开放式说法，交给被海量数据训练过的 Google 引擎最省事——代价是命令阶段引入云依赖（本文没解决它，只把它限制在唤醒后的短窗口内）。Fig 14 的结果印证了各取所长：命令识别在噪声下反而比自训唤醒词更抗造。本地命令层只做确定性字符串等值匹配——逻辑极简、可审计、不会误动作。

§03 · 五维验证

距离、噪声、多说话人、命令、延迟

协议：距离测试安静受控房间 10–300cm 七档（每档 5 组 × 20 次 = 100 次）；噪声测试 JBL 音箱播放免版税公园 / 咖啡馆环境音（40–75dB，固定 50cm）；多说话人 10 人（50% 男 50% 女）；命令每条 100 次尝试；延迟每项 10 次取平均。主指标成功尝试精度 + 依从性（compliance，把「听错」与「做错」解耦）。距离维度结论：唤醒词 10–200cm 稳定约 90%、命令 >80%——2 秒窗口加麦克风增益在典型使用距离内无明显信噪比崩塌（300cm 具体数值未报告）。

Fig 12–14：三条曲线的相对关系与 80% 锚点是原文结论，逐点数值为示意——咖啡馆（会话噪声）对唤醒词最致命、命令识别最抗造、公园噪声下自训模型反超 Google Assistant。

近似消融的四组受控对比（严格消融未做——频谱增强 / 环境音负样本 / TTS 数据各自贡献无对照）：① 只变噪声类型（公园 vs 咖啡馆）：模型对语音类背景噪声显著更脆弱；② 只变距离：10–200cm 稳定；③ 只换说话人：20%–100% 剧烈波动；④ 识别与执行解耦：听错集中在 turn left→turn light，做错 0 次——确定性字符串匹配 + 预编程动作完全可靠。与文献横向对照（Pi 3 情感识别 86%、CNN+LSTM 轮椅 95%、Android LSTM 98.2%）——口径不同质（本文明明加了噪声 / 距离 / 多说话人多维评估），直接排名无意义。

§04 · 主要贡献

一套被验证过的系统集成参考架构

1首次（自称）把独立唤醒词系统集成到语音控制边缘轮椅原型：验证「本地轻量唤醒词常驻 + 按需激活命令识别」两级门控在 Pi 4 类硬件上的可行性——最核心的贡献主张。
2自造唤醒词的数据工程方法论：自录 500 + 多 TTS 口音 + 组外真人构正样本，Common Voice + 环境音构负样本，MFCC + SpecAugment + F1 早停——小团队做自定义唤醒词可直接照抄的路线图。
3位置命令概念 + 11 条命令集落地：从方向原语提升到空间语义任务（实现是开环宏），并明确指出通往真导航的传感器前提（LiDAR 建图）。
★量化基准 + 案例价值：唤醒词 50dB 噪声以下 80%+、命令 65dB 以下 80%+、依从性 100%、唤醒延迟 0.73s——后续工作可对照的落地数字；论文自我定位是充实设计开发文献的系统集成参考架构，而非新算法。

§05 · 局限与边界

案例研究的诚实读法：安全主张缺安全指标

技术局限

  • 唤醒词高度个性化：500 条自录音 → 说话人泛化差（20%–100% 波动是直接证据）；药方 = 扩数据集 + 男女平衡 + 覆盖口音。
  • 位置命令是开环宏：无传感器反馈，环境一变即失效；商用必须加超声波避障 + LiDAR 室内建图（论文自列必做项）。
  • 命令阶段依赖 Google API：断网命令不可用（未测试断网场景）；音频经第三方云，隐私被压缩未消除；API 成本与配额未讨论。
  • 原型硬件不具商业代表性：mini 原型电机仅够概念验证；商用轮椅电机须承受人体重量且精度要求极高；小车轮动力学与真轮椅不同，开环误差在实际尺度会放大。
  • 关键工程参数不透明：LSTM 层数 / 隐维 / 学习率 / 轮数 / 模型大小 / 内存 / CPU / 功耗全未报告——难复现、无法评估资源余量。

实验设计不足

  • 误报 / 漏报未分离统计：唤醒词系统的安全指标应拆成误唤醒率（背景对话误触发）与拒识率分别报告，本文全折叠进单一精度——与自己的安全主张形成张力（门控的存在意义恰恰是防误触发）；无 ROC/DET 曲线。
  • 文本与表格自相矛盾：正文说每人测 3 次、Table VI 表题与数值粒度（20% 整数倍）指向 5 次；噪声测试表误编为 "TABLE I"。引用数字需自行校准口径。
  • 样本量与场景真实性有限：10 人多说话人；音箱播放模拟噪声而非真实公园 / 咖啡馆混响多源噪声；命令测试固定 50cm 安静房间——与多距离结果无交叉验证（200cm + 60dB 噪声下的命令精度未知）。
  • 基准与统计不足：外部基准只有 Google Assistant 唤醒词、命令识别无外部基线；与文献 95% / 98.2% 未同协议复测；除延迟外无置信区间 / 方差。
值得补的方向：论文自列——超声波 + LiDAR 避障与室内建图（商用必要条件 + 位置命令成立前提）、商用级电机、大数据集继续训练、Whisper 本地化命令识别（Wechsler 已在 Pi Model B 实现 Whisper 实时转写——摆脱 Google API 依赖的技术缺口已打开）。KWS 工程视角另补三条：用 Porcupine / openWakeWord 类现成框架或更现代流式架构替换自训 LSTM 换更低常驻算力；命令识别本地化为小词表模型（11 条命令完全不需要大词表引擎——同时解决延迟、断网、隐私）；引入误唤醒率正规评测协议，让安全主张有数据背书。
