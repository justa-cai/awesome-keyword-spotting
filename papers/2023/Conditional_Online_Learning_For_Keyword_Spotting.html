词表部署后不变，变的是词被说出来的分布——
一个 SGD 步加两个不等式，设备上边推理边学

Conditional Online Learning for Keyword Spotting（COOL）

作者：Michel Meneses、Bruno Iwami —— SiDi（巴西；第一作者为多语种 KWS 数据集 SiDi KWS 的作者）

发表：arXiv 2305.13332（2023-05）· GSC 8 词 × 5 场景流式协议 · cnn-one-fstride4 基线

同任务在线持续学习hold-out 损失门控双缓冲类别平衡批 除 Dv 外零超参累积增益 34–36%首尾对称无遗忘

一分钟版本

  • 痛点打在「平稳分布」假设上：离线训练范式假设训练数据与部署后消费的数据同分布——真实生产环境非平稳：新说话韵律、环境噪声、麦克风变化都会在训练时无法预料的维度上改变输入分布，而模型要等厂商排期的定期更新才可能被替换，中间隔着数月的性能退化窗口。把训练集做得更大更全这条路的成本作者有第一手体感（自己刚做过大规模多语种数据集）——判断是「分布漂移原则上无法被穷尽地预先预测」。
  • 已有 KWS 持续学习瞄错了问题：Rainbow Keywords（在线蒸馏，历史状态当教师）与渐进持续学习（每任务生长子网络）都在做「加新词」——商业唤醒词词表部署后固定，变的是分布；为加新词设计的整套机制用不上，且蒸馏 / 多任务的存储计算随任务数增长，与端侧资源矛盾；朴素在线 SGD 直接顶上则因流数据非 i.i.d.（时间强相关、分布随环境切换）梯度有偏、收敛差。
  • COOL 的核心（「Conditional」的落点）：每个梯度更新只是候选提案，合法性由两个不等式裁决——批损失严格下降（可塑性：必须学到新东西）+ hold-out 损失不得上升（稳定性：不许丢旧东西）。这是稳定性-可塑性权衡最直白的算法化；hold-out 集的新语义：它是训练分布的化身，任何想把模型拉离训练分布的更新都会先在它身上暴露。
  • 工程卖点：无教师模型、无回放库、除 hold-out 集定义外零超参；每个候选更新只加两次前向（B 一次 + Dv 一次）——持续学习防遗忘机制里几乎最轻的一档。双缓冲类别平衡批（各攒 8 个）防流式组批的类先验偏差，更新后清空 = 内存有界 + 主动放弃经验回放（防遗忘全押在门控上的刻意权衡）。
  • 结果：隔离场景平均 0.53→0.66、方差 ±0.28→±0.15（两极分化的任务被拉拢）；序列场景（干净→啼哭→玻璃→枪声→干净）累积增益 33.96–35.85%（摘要的 34%）全面高于隔离增益——跨噪声正向迁移；首尾干净场景孤立增益 28.85 vs 26.92 基本持平——灾难性遗忘基本未发生的直接证据。
  • 门控消融（图 2，全文最重要单图）：朴素在线 SGD 开局反超（更新频繁无门控延迟），但在第一次分布切换处开始衰减（有偏梯度）；COOL 稳定上升——门控在分布稳定期是拖累、切换期是生命线。混杂变量：两者更新粒度不同（每步 vs 平衡批攒满），无「频率对齐只差门控」的严格对照。
  • 诚实读法的关键：基线一半是坏的——4 个任务验证准确率停在 0.50–0.56（损失 0.69≈ln2，塌缩到随机猜测平凡解），平均增益里相当一部分是「在线救活没训好的模型」而非纯分布适应；逐任务在线增益未报告，健康模型（Right 0.95）还能涨多少这个关键问题没答案。
  • 边界：有标签流假设是上界设定（真实设备没人打标签——落地命门，标签估计整体留给未来）；门控保守性双刃剑——剧烈漂移（换麦克风 / 远场混响）下稳定性可能压制可塑性（只测了 25dB 一种信噪比，失效边界未探测）；Dv 规模未报告（太小判据噪声大、太大端侧存储吃不消）；无 FAR/FRR/DET（与商业 KWS 验收口径脱节）；端侧延迟 / 内存 / 能耗零实测。

§01 · 问题陈述

问题收缩换算法极简

两个刻意的问题收缩：① 限定「同一 KWS 任务」——目标词集合部署后不变，直接砍掉新任务适应的全部复杂度（子网络生长、任务间蒸馏、任务边界检测全部非必要），给简单算法腾出设计余量；② 假设在线数据流带标签——论文明确承认不现实，但沿用 ASR 在线持续学习的同一假设，把讨论聚焦到在线学习器设计本身，并给性能设定上界（后续标签估计工作在这个上界之下衡量自己损失了多少）。另设「在 D∪S 重训不可行」（N 太大）——划清与周期性全量重训的界限。
为什么选 cnn-one-fstride4：Sainath 与 Parada 2015 的小脚印 CNN 家族单步长变体——小脚印 KWS 最经典的公开基线、TF 官方 speech_commands 教程默认模型之一、复现门槛最低：恰好论证 COOL 不依赖任何 fancy 架构，与「设定实用基线」的自我定位一致。

§02 · 方法论

候选提案 + 双检验裁决

算法 1 复绘：双约束 = 稳定性-可塑性权衡最直白的算法化；hold-out 集从「决定何时停止训练」变成「决定每一步在线更新是否生效」——同一件工具换了战场。

M̃ = M − η∇l(B, M)；接受 ⟺ l(B, M̃) < l(B, M) 且 l(Dv, M̃) ≤ l(Dv, ·)
算法 1 的优化语义：以损失为势函数的贪心单调下降——双约束分别管「可塑性」（每步被接受的更新都确从新数据提取了信号，噪声步失败步直接丢弃，等价内建的每步早停）和「稳定性」（Dv 与训练分布 i.i.d.，任何旧分布退化被捕获否决——把「不许伤害旧知识」写成硬约束而非软正则）。对比知识蒸馏的软目标正则：不需要维护教师模型、不需要蒸馏温度超参，代价是可能偏保守。
流式评测协议（可复用的方法学贡献）：每个任务把全部测试样本拼成一条长音频模拟数据流；500ms 零填充避免多个词同落 1 秒窗；正标签判据 = 目标词至少 80% 落在该帧内（图 1 的标签轨迹——一长串 0 里零星短簇 1——直观显示正样本稀缺，正是平衡缓冲针对的现实）。噪声场景用 DCASE 2017 的婴儿啼哭 / 枪声 / 玻璃破碎按 25dB 混入。

§04 · 主要贡献

四条贡献

1问题定义：首次把 KWS 在线持续学习收缩到「同任务同词表」并完整形式化——指认这才是大多数商业唤醒词系统的真实处境。
2算法：COOL——双不等式门控的 SGD 在线协议；无教师、无回放、除 Dv 外零超参、每候选只加两次前向——防遗忘设计里端侧友好度最高的一档。
3实证：隔离增益 19.96%、方差 ±0.28→±0.15；序列累积增益 33.96–35.85%；朴素 SGD 对照证明条件门控是防遗忘的有效成分。
4方法学：有标签流上界假设给标签估计方向留干净参照系；一套可复用的流式 KWS 评测协议（拼接长音频 / 零填充 / 80% 帧占用判据）。
可迁移判断：当在线数据非 i.i.d. 而你又想要「零超参」的防遗忘时，一个静态 hold-out 集当训练分布的化身 + 接受/拒绝的离散门控，比维护教师模型或回放库便宜一个量级——它的代价是保守性（剧烈漂移下学不到该学的幅度）与单一锚点风险（Dv 是唯一历史知识载体）。

§05 · 局限与边界

有标签流是上界，基线一半是坏的

技术局限

  • 有标签流假设：真实设备没人打标签——落地命门（置信度筛选 / 用户隐式反馈 / 主动学习决定方法能否成行），整体留给未来工作。
  • 锚定与适应幅度的矛盾：Dv 固定代表训练分布，大幅偏离的适应方向都会被否决——中等漂移（加噪）是保护，剧烈漂移（换麦克风 / 远场混响）可能意味着永远学不到该学的幅度；只测了 25dB 一个信噪比，失效边界未探测。
  • 防遗忘押在单一机制：放弃经验回放后 Dv 是唯一历史知识载体——Dv 太小判据方差大、太大端侧存储吃不消；Dv 规模未报告，关键权衡悬空。
  • 贪心接受的僵局风险：批损失严格下降条件使过程完全贪心（无动量、无退火、无容忍带）——理论上存在卡局部、反复提案被否决的失败模式，发生率未讨论；门控前向开销与 |Dv| 线性相关而 |Dv| 未报——端侧可行性缺这块账。

实验设计不足

  • 基线一半是坏的：4 任务随机水平（损失 0.69≈ln2 = 塌缩到平凡解）——平均增益相当部分来自「救活没训好的模型」；逐任务在线增益未报告，两种收益拆不开。
  • 漂移类型单一：引言列了韵律 / 噪声 / 麦克风三类漂移动机，实验只构造噪声一种、25dB 一个信噪比、三种 DCASE 噪声——韵律与麦克风漂移完全未测。
  • 统计与顺序：序列顺序只有一种、无多种顺序对照；无随机种子数与显著性检验；流长度有限（论文自认）。
  • 端侧指标缺位 + 口径问题：无延迟 / 内存 / 能耗实测，TFLite 落地推给未来；Δ% 计算方式未说明（验算发现分母是 COOL 值）；无 FAR/FRR/DET——与「降低误收率」的商业动机脱节；伪代码 lv 回写与否未澄清。
值得补的方向：流数据标签估计策略 + 标签不确定性对最终性能的影响（把上界拉向现实的关键一步）；与持续学习文献更精细在线算法的系统对比；TFLite 端侧训练 API 真实落地验证；两个接受条件的独立消融 + 松弛化设计（如 lv0 ≤ (1+ε)·lv 容忍带）刻画稳定性-可塑性边界；小规模回放缓冲与门控组合替代单锚点；指标切到 FAR/FRR/DET 对齐商业验收口径；真实麦克风 / 远场 / 多信噪比重测漂移边界；健康基线单独报告逐任务增益；澄清 lv 回写语义与 Dv 规模选取原则。
