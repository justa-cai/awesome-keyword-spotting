84.51% 精度不耀眼，但它证明了「公开数据到白菜价开发板」的全流程——
还顺手把三时段六说话人的板端统计验证立成了范式

Keyword Spotting System with Nano 33 BLE Sense Using Embedded Machine Learning Approach

作者：Nurul Atikah Binti Abbas、Mohd Ridzuan Ahmad（马来西亚工艺大学，控制与机电工程系）

发表：Jurnal Teknologi (Sciences & Engineering) 85:3, 175–182（2023-04）· Google Speech Commands V1 · Arduino Nano 33 BLE Sense

定位：工程落地，非架构创新1 MB Flash / 256 KB SRAMMFCC + 三层 1D CNN（8/16/32） EON 编译器 8bit 量化板端 84.51% · 26 ms三时段 × 六说话人 t 检验

一分钟版本

  • 这是什么论文：不是「精度再推一个点」的研究论文，是一篇工程落地报告——把一个四分类（On / Off / 噪声 / 未知）KWS 模型完整塞进 1 MB Flash + 256 KB SRAM 的几美元开发板（Arduino Nano 33 BLE Sense，nRF52840），并在真实环境验证可用。问题内核即摘要承认的矛盾：缩小模型的同时保持精度和性能是困难的。
  • 为什么必须端侧：云推理三宗罪——延迟、能耗、隐私，还要求 Wi-Fi 常连；语音命令先出家庭、上云、再回来点灯，既慢又贵还不安全。TinyML 三条正面价值：数据留在设备、省基础设施、延迟消除。KWS 正是 TinyML 三大经典应用之一（另两个：视觉唤醒词、异常检测）。
  • 方法全是成熟件：MFCC 前端（Mel 滤波器组 + 对数 + DCT，模拟人耳低频高分辨率）→ 三层一维卷积（通道 8→16→32 翻倍，核尺寸 3，各接 dropout 0.25）→ flatten → 四分类。刻意做减法：不用注意力、不用 NAS、不用深度可分离卷积——目标是立起工具链与验证协议，不是刷架构。板载三色 LED 复用为输出（绿 On / 红 Off），零成本闭环。
  • 为什么四类不是两类：二分类会把所有非命令词误判成命令词——噪声类（纯环境声，20+ 种真实来源：地铁、洗碗机、猫叫、咀嚼声…）和未知类（其他语音词）是拒绝选项。KWS 在系统里的角色是级联架构里的触发器，不是通用 ASR。
  • 结果三层：① 训练 88% → 测试 82.4%，5.6 点落差（dropout+加噪没完全压住过拟合）；② 逐类悬殊——命令词类 90+ 达标，未知类塌到 55.4%（21.8% 误判成 On——One 与 On 发音太近；12.4% 误判成 Off）；③ 量化部署后 84.51% 反而比未量化高 2.11 点、延迟 26 ms——反常且论文未解释机理。
  • 最有辨识度的一环：统计化验证协议。时间无关性：三时段（9 点 / 15 点 / 21 点）× 各 200 次 = 1200 次推理，On 均值 87.33%、Off 89.5%，t 检验区间 174.67±5.17 / 179±15.11——时段间无显著差异。说话人无关性：六人（2 女 4 男，16–52 岁）× 各 50 次，On 92.67%、Off 91.33%。把「系统可用」从口号升级为带统计区间的可检验命题——同类开发板论文里独一份。
  • 没有基线：所有被引 SOTA（CRNN 84K 参数 1.02% FRR、MAX78000 NAS、DS-CNN、DCN）只出现在引言里，零个被复现对比；84.51% 也远低于研究型论文的 95%+——但两边本就不在同一评价空间（人家没在 1 MB 板上跑、没做六人三时段验证）。FRR / FA-per-hour 这对 KWS 标准操作点指标全文缺席，是明确的指标体系缺口。
  • 边界与数字疑点：未知类是阿喀琉斯之踵（把 One 听成 On 的智能开关会被用户拔电）；参数量 / FLOPS / 量化体积 / RAM 峰值 / 能耗全部未报告，「最小内存占用」声明缺定量支撑；自称单尾检验但 t 临界值用的是双尾值；结论部分 84.24% 与表 4 的 84.51% 矛盾——同一量三个数；人员实验精度明显高于时间实验的差值暗示测试条件未控制。

§01 · 问题陈述

缺口不在算法，在「照着做就能跑」的端到端配方

被点名的现有方案不足：① 传统 HMM——巨大内存、庞大词表、高强度计算，MCU 上根本不可行；② 云端深度学习——隐私、网络、延迟、内存四重依赖，对 always-on 唤醒不现实；③ 研究 SOTA 各有代价——CRNN 注意力模型（84K 参数、1.02% FRR）没给廉价通用板的复现路径，MAX78000 NAS 依赖专用加速器，DS-CNN / DCN 未在同等数据与硬件下复现对比；④ MFCC 能耗争议——论文自己引用了「带 MFCC 前端能耗是所提系统三倍以上」的批评，却仍选 MFCC（更看重流程完整性与可复现性，未测能耗回应）。真正的缺口：缺一个「公开数据集 → 白菜价开发板」全流程、可复现、含真实场景统计验证的完整实现报告——工程教育场景和小团队需要的配方反而是缺位的。
硬件约束：Flash 1 MB · SRAM 256 KB · 主控 nRF52840（Cortex-M4F）· 板载麦克风（免外围音频电路）
选型甜点：比它小的板子（如 ATmega328 的 2 KB RAM）连 MFCC 缓冲都放不下，比它大的平台失去微型化意义。三条部署目标——无网络、低延迟、低功耗——正是引言批判云方案三宗罪的正面回应。

§02 · 方法论

全流程工具链 + 统计化验证协议

图 1/2 复绘：端到端配方全景——五阶段工作流（数据采集→模型设计→云端训练→测试→EON 部署，LED 反馈闭环）；云三宗罪 vs Nano 33 BLE Sense 硬件约束；三层 1D CNN 结构（8/16/32 通道、核 3、dropout 0.25）；四类设计（噪声/未知是拒绝选项，级联架构里 KWS 是触发器）；未知类 55.4% 的混淆来源解剖（21.8%→On / 12.4%→Off / House 不确定弃权）；三时段×六说话人统计验证协议。

CI = x̄ ± t · σ/√n（式 1，全文唯一编号公式；95% 置信水平）
x̄ 样本均值、σ 样本标准差、n 样本数、t 为给定置信水平与自由度下查表的临界值。为什么用它：不重复实验就能框住总体真值范围。坑：论文自称单尾检验，但代入的 t=4.303（df=2）与 2.571（df=5）实际都是双尾 95% 取值——单尾应为 2.920 与 2.015；区间计算自洽，检验类型表述错误。
MFCC 链条与 dropout 的白话：MFCC = 每帧加窗 → Mel 滤波器组 → 取对数 → DCT。Mel 刻度模拟人耳非线性感知（低频分辨率高、高频低），与元音共振峰和辅音判别信息集中在中低频的统计特性吻合；DCT 把对数 Mel 能量压到少数低阶系数——去相关同时降维。论文未报告 MFCC 具体参数（滤波器组数 / 系数维数 / 帧长帧移），影响复现精度。Dropout：比率区间 20%–50%，太低没效果、太高学不动，固定 0.25 因「给出了高性能」——同样没有扫描数据支撑。

§03 · 实验与消融

内部纵向四段对比 + 无外部基线的坦诚

Table 1 复绘：数据集构成。GSC V1（1881 名说话人、65000 条单词条录音）裁剪为四类、80:20 划分。命令词类样本是噪声/未知类的约 1.65 倍——未知类训练数据本就偏少，与其测试 55.4% 塌陷直接相关。噪声来源 20+ 种真实环境声（地铁、洗碗机、机场广播……），训练即混入 = 域鲁棒性设计。

Table 2/3/4 复绘：左——逐类精度训练 vs 测试：命令词 90+ 达标、噪声最稳（98.2→91.6）、未知类训练已塌（60%）测试再塌（55.4%），dropout+加噪没救回。右——量化部署反常「反升」：8bit+EON 84.51% 比未量化 82.4% 高 2.11 点，与量化常带来轻损的直觉相悖且论文未解释机理（疑两次评估协议/划分有差异）；结论部分又写 84.24%——同一量三个数。

Table 5/6 复绘：板端真实场景实测。左——时间实验：三时段×各 200 次，On 均值 87.33%、Off 89.5%，时段间无显著差异（15 点最高是「噪声更少」的主观归因，未测噪声）。右——人员实验：六人（2 女 4 男，16–52 岁）×各 50 次，On 92.67%、Off 91.33%。两个疑点：人员精度明显高于时间精度（测试条件未控制）；自称单尾检验但 t 值是双尾取值。

散落的五处消融式证据（均无正式扫描表）：① 网络深度固定三层，理由「更多更少都退化」——未报数字，不可核验；② dropout 0.25 定档——无扫描；③ 量化前后 82.4 → 84.51「反升」——机理未解释；④ 谱图加噪增强——无关闭增强的对照组，独立贡献无法分离；⑤ 时间三档 × 人员六人本质是对「环境噪声」「音色差异」两个外部因素的系统消融——结论是两个维度差异都不大（On 六人标准差仅 0.5164 次），系统时间无关且说话人无关。

§04 · 主要贡献

三条贡献 + 阅读预期校准

1完整端到端落地配方：GSC V1 四类重标注 → Edge Impulse 云端训练（MFCC + 三层 1D CNN）→ EON 8bit 量化 → Nano 33 BLE Sense 板端部署，板端 84.51% / 26 ms，全免费工具 + 廉价硬件，复现门槛极低。
2真实场景统计化验证协议：三时段各 200 次 + 六说话人各 50 次的双维度板端实测，95% t 检验区间报告——在此类开发板实现报告中首次把「可用」做成可检验命题。
3轻量架构的工程确认：三层 8/16/32 通道 1D 卷积 + 0.25 dropout 即可在四分类小词表上达到 90% 级命令词精度；并定位系统真实短板在未知类拒绝能力（55.4%），为后续指明方向。
★阅读预期校准：这是一篇「立范式」的论文——工具链 + 验证协议可被任何后续工作直接沿用；但精度指标不可与榜单论文横向比。它是 TinyML 教学与原型验证的脚手架，不是架构创新的贡献者。

§05 · 局限与边界

未知类塌陷 + 数字管理粗糙

技术局限

  • 未知类 55.4%：KWS 区别于玩具 demo 的核心能力恰是拒绝能力——把 One 听成 On 的智能开关会被用户拔电。训练集未知类样本本就偏少（1123 vs 命令词 1858+），且缺发音近邻的难负样本。
  • 词表只有两个命令词：与常见十词任务相距甚远。
  • 资源账单缺失：参数量、FLOPS、量化后体积（KB）、RAM 峰值、能耗均未报告，只有延迟 26 ms 一个指标——「最小内存占用」声明缺定量支撑。
  • MFCC 参数未报告：滤波器组数 / 系数维数 / 帧长帧移全部缺席，复现精确性受损。
  • 未回应 MFCC 能耗批评：自己引用了能耗三倍的批评文献，却既未换前端也未测能耗。

实验设计不足

  • 零外部基线：所有引用数字只做背景板，无同数据同硬件对照。
  • 无随机种子重复：单次训练结果无方差信息。
  • 数字不一致：同一测试精度三个数（82.4 / 84.51 / 84.24）；量化反升 2.11 点未解释；正文「16 Hz」系 16 kHz 笔误。
  • 统计口径瑕疵：单尾表述配双尾 t 值；时间维度 n=3、人员维度 n=6 样本量小。
  • 条件未记录：人员实验精度高于时间实验的反常未讨论；测试距离、声压级、麦克风朝向未报告。
六条改进方向（第一、二条是地基）：① 重建未知类——大幅扩样本 + 发音近邻难负样本（One、Off 韵脚词）+ 开集识别思路；② 补 KWS 标准指标——FRR 对 FA/hour 操作点曲线替代单一精度（唤醒场景的工程合同靠这对指标签）；③ 同数据同硬件复现 DS-CNN / BC-ResNet 做真对比；④ 补资源与能耗完整账单（功率计或板载电流采样）；⑤ 扩验证协议（更多说话人、远场、混响、条件在案）；⑥ 产品化延伸——自定义唤醒词、多语言命令（马来西亚语场景）、KWS+VAD 级联降常驻功耗（cascade architecture 的完整形态）。
