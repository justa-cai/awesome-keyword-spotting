GeLU 换来 +0.03 mAP 却要付 68% 延迟和 35% 内存——小米把统一 KWS+AT 塞进手机 CPU：
补丁数 1212→24、瓶颈注意力 U=D/4、四芯片实测提速 2–6 倍、唤醒延迟 320→160ms

Unified Keyword Spotting and Audio Tagging on Mobile Devices with Transformers（UiT）

作者：Heinrich Dinkel†、Yongqing Wang†、Zhiyong Yan、Junbo Zhang、Yujun Wang（小米，北京；† 共同一作）· arXiv 2303.01812

数据：GSCV1（11 类）+ Audioset balanced（60h）· 模型：UiT-XS/2XS/3XS = 1.5M / 0.8M / 574k · 代码开源

会议版遗留问题的补答：手机上到底能不能跑压 N 与压 D 双管齐下子采样 stem D<P 锁内存入口 瓶颈注意力免费提速 20%四芯片 CPU float32 实测按延迟审判每个组件

一分钟版本

  • 论文定位：给会议版 UniKW-AT 补上部署证据。会议版（Interspeech 2022）首次证明 KWS 与 AT 可统一建模（关键词视为特殊声事件、标签并集 537 类、BCE 联合训练、单一 MobileNetV2 2.9M）——但没有任何延迟/内存/速度数字，「端侧可行」只是参数量推断，而这恰是 KWS 的第一性问题。本文回答三个问题：手机上到底能不能跑、跑多快、占多少内存。统一的价值：AT 分支可下传 ASR 管线增强噪声鲁棒性；退一步一个模型兼任 VAD——一份计算两份语义。
  • 被点名的不足：① 会议版 MobileNetV2 2.9M 在 AT 社区算轻量但在 KWS 标准下偏大（唤醒延迟 320ms、SD865 上 8.0ms——对照 TC-ResNet8 的 0.06M/0.4ms 差一个数量级）；② 纯 KWS 模型无法反向兼容 AT——自跑 TC-ResNet8 联合训练 GSCV1 96.72（比公开 96.10 还高——60h AS「噪声」增强抗误唤醒）但 AT 只有 8.67 mAP：原因在标签结构不在容量——「统一」必须从任务表述层解决，小模型加个头糊弄不过去；③ AT 社区 transformer 的 N=1212 补丁二次复杂度是结构性障碍；④ KWT/LETR 等只做 KWS 且同样缺部署验证。
  • 四招组合拳（正交可叠加，各对应复杂度公式与内存路径的不同环节）：① 补丁削减压 N——1 秒裁剪（KWS 本来就是 1s 任务、同时对齐两数据集时长）+ 频率轴 NF=4 固定不动：N 从 1212 → 每秒 24（压 ~50 倍、N² 项塌缩 4 个数量级+）；② 子采样 stem 锁入口——patchify 与降维合并一步、P=256 直接映射 D=128（D<P 压一半）：从第一跳锁死激活内存上限（常规 CNN 第一层就把中间特征放大 ≥4 倍）；③ 瓶颈注意力 BN-A 压 D——注意力阶段 D→U=D/4=32（相邻时间补丁高度相关、全部 D 维参与注意力纯属浪费）；④ 组件按延迟审判——ReLU 非 GeLU、MLP 3D 非 4D、时频独立位置编码、家族式 MAE 预训练（一个 UiT-XS checkpoint 初始化三档）。
  • 双任务主表（Table 2）：UiT-XS（1.5M）GSCV1 97.76 / AS 34.09——以一半参数双任务同时超会议版 MBv2（97.53/33.42）；AT 侧超 9 倍大的 Eff-B2（13.6M，34.06）；距 AudioMAE（80M，37.10）差 3 点但其需 GPU。诚实注记：增益是架构+配方+预训练三者叠加——论文没有隔离各自贡献。
  • 移动端实测（Table 3，四款 SoC CPU float32，10 预热 + 1000 平均的规范 benchmark）：SD865 上 TC-ResNet8 0.4 / UiT-3XS 1.2 / 2XS 1.7 / XS 3.4 / MBv2 8.0 ms。三条结论：① UiT-XS 相对 MBv2 提速超 2 倍且性能相当、全家族 1.6–6.7 倍；② UiT-2XS/3XS 仍慢于 TC-ResNet8 但 AT 能力约 4 倍（32.2/31.0 vs 8.67）——毫秒级延迟差价买完整 AT 分支；③ 唤醒延迟 320→160ms 砍半（16 帧补丁 = 160ms 的时间分辨率地板）。芯片规律：中端芯片（G90T/MT700）所有模型慢 2–3 倍——transformer 对 CPU 子系统（缓存/内存带宽）敏感度高于峰值频率。
  • PSL 伪强标签（1s/10s 失配的缓解）：把 10s 片段级弱标签直接贴在 1s 裁剪上 = 系统性标注噪声；PSL 用预训练教师（MobileNetV2）对每个 1s 裁剪预测细粒度软标签。会议版消融的分量：去掉 PSL，AS mAP 33.42→20.77（断崖级）、GSCV1 也 97.53→96.94。评测端配套：超 1s 输入切 chunk 逐段过模型、分数平均（自注影响 Audioset 性能）。
  • 消融三层发现（Table 4）：① BN-A 是免费的提速——性能几乎不动（GSC 差 0.01、mAP 差 0.33）、速度 ≥20%、内存省 26%；小模型去掉 BN-A 反而掉精度（2XS −0.37、3XS −0.47）——瓶颈结构对容量紧张的模型兼正则化；② GeLU 的精度增益买不起延迟——mAP +0.03、GSC −0.07，但延迟 +68%、内存 +35%：「激活函数也是部署决策」的量化证据；③ 组件选择与规模无交互——三行消融在三个型号方向完全一致 → 一套配方三档部署。
  • 边界：速度仍与纯 KWS 差一个数量级（UiT-XS 中端芯片 7.1–7.3ms——always-on 功耗预算是否可承受无功耗数据）；AT 天花板明显（34.09 vs 37.10，且训练只用 balanced 60h——完整 Audioset 约 200 万片段未用）；非流式架构（10s 输入靠离线切块 + 分数平均，非因果流式——160ms 补丁地板 + 1s chunk 粒度对「说完立即唤醒」只是勉强够用）；float32 CPU 是唯一验证形态（无 int8 / NPU delegate / 算子融合——与厂商定制引擎差距未知）；评测矩阵较会议版大砍（Musan/VL106/GSCV2/小米内部产品数据全部删掉——统一框架最大的卖点噪声鲁棒性在新骨干上零复验）；消融单芯片；γ 0.4→0.2 重调未报。

§01 · 问题陈述

会议版留白的第一性问题

核心挑战：把 ViT 类 transformer 的计算与内存开销压到移动端 CPU、float32 下可实时承受，同时保住双任务性能不塌方。四个子问题：O(N²D+D²N) 的两个二次项同时驯服；KWS 1s 训练与 Audioset 10s 评测的时长失配（PSL 部分缓解）；唤醒延迟的硬地板（补丁大小决定至少积累多少帧才出判决）；所有组件选型以推理速度与峰值内存为第一准则重新审视。为什么值得统一：AT 输出下传 ASR 增强噪声鲁棒 + 一个模型兼任 VAD。
A = softmax(QKT/√D)V（式 1）；单块复杂度 O(N²D + D²N)
N²D = 注意力矩阵及与 V 相乘；D²N = 线性投影与 MLP——对 N 和 D 均二次，是全文所有设计决策的出发点。补丁几何：64 维梅尔谱 / 10ms 帧移（1s=100 帧）、16×16 补丁 → 频率 NF=4、时间每秒 NT=6 → N=24（对照 Audioset 常规 N=1212）。KWS 准确率须阈值化后处理（γ=0.2 判关键词存在再 argmax——多标签输出「关键词+Speech」歧义的解法）。

§03 · 实验与消融

四芯片实测 + 组件级审判

表 2 复绘：双任务主表——左 KWS 侧、右 AT 侧。两个关键读数：纯 KWS 架构承载不了统一任务（TC-ResNet8 联合训练 GSCV1 96.72 反超公开值但 AT 仅 8.67 mAP——问题在标签结构不在容量）；UiT-XS 以一半参数双任务同时超会议版 MBv2、AT 侧超 9 倍大的 Eff-B2。

表 3 复绘：四款 SoC CPU float32 实测延迟（规范 benchmark：10 预热 + 1000 平均）。UiT-XS 相对 MBv2 提速超 2 倍且性能相当、全家族 1.6–6.7 倍；UiT-2XS/3XS 仍慢于 TC-ResNet8 但 AT 能力约 4 倍——毫秒级延迟差价买完整 AT 分支；唤醒延迟 320→160ms 砍半。中端芯片慢 2–3 倍的规律：transformer 对 CPU 子系统敏感度高于峰值频率。

表 4 复绘（SD865）：UiT-XS 三配置的延迟/内存对照 + 三层发现——BN-A 是免费提速（性能几乎不动、≥20% 提速、26% 省内存；小模型上兼正则化）；GeLU 的 +0.03 mAP 买不起 68% 延迟 + 35% 内存；组件选择与规模无交互 → 一套配方三档部署。局限：消融只在 SD865 做、MAE/批配比/位置编码/PSL 均未消融。

数据与指标：GSCV1 11 类子集（其余 20 词映射 Speech 标签）51,088/6,798/6,835 + Audioset balanced 60h/21,292 条；评测 AS 官方子集 18,229 条 + GSCV1 测试集。指标：AT 用 mAP、KWS 用准确率（γ=0.2 阈值化——统一框架评测的特殊环节）；训练以 mAP 做模型选择（对 537 维输出整体质量更敏感）+ top-4 权重平均。新增部署指标：四芯片 CPU float32 延迟（10 预热 + 1000 平均）+ 峰值内存 Mpk。未报告：功耗、每小时误报/误拒。

§04 · 主要贡献

五条贡献

1首批面向移动部署的统一 KWS+AT transformer——三档可部署型号（1.5M/0.8M/574k），UiT-XS 34.09 mAP + 97.76%，一半参数双任务超会议版基线。
2驯服二次复杂度的组合拳——补丁削减（压 N）、子采样 stem（锁入口）、瓶颈注意力（压 D）、ReLU+3D MLP（压组件）——四手段正交可叠加，分别对应复杂度公式与内存路径的不同环节。
3首个 UniKW-AT 多芯片端侧实测基准——四款商用 SoC、规范 benchmark 协议：2–6 倍提速、320→160ms 延迟减半、峰值内存首报。
★用消融为工程组件选型定量背书——BN-A 免费提速 ≥20%、GeLU 的 +0.03 mAP 换 68% 延迟不划算：「激活函数、注意力结构都要按延迟审判」的方法论示范。
5开源——github.com/Richermans/UIT_Mobile，含 MAE 预训练 checkpoint 的完整训练管线，工业论文中可复现性良好。

§05 · 局限与边界

非流式 + 评测矩阵收窄

技术局限

  • 速度仍与纯 KWS 差一个数量级：UiT-3XS 最快 1.1–1.2ms vs TC-ResNet8 0.4ms；UiT-XS 中端芯片 7.1–7.3ms——always-on 功耗是否可承受无数据支撑；高低端设备的成立边界未划清。
  • AT 性能天花板：34.09 vs AudioMAE 37.10；训练只用 balanced 60h（完整 ~200 万片段未用）；1s/10s 失配只被 PSL「部分缓解」——长时声学结构从没学过。
  • 非流式架构：10s 输入靠离线切块 + 分数平均，非因果流式；160ms 补丁地板 + 1s chunk 粒度对「说完立即唤醒」勉强够用。
  • float32 CPU 唯一形态：无 int8 / NPU/DSP delegate / 算子融合——与厂商定制引擎的差距未知，实测数字对产品落地的外推性存疑。

实验设计不足

  • 评测矩阵大砍：Musan/VL106/GSCV2/小米内部产品数据全部删掉——统一框架最大卖点（噪声鲁棒、困难负例拒识）在新骨干上零复验；条件唤醒也停留在「逻辑上可行」。
  • 消融不完整且单芯片：只在 SD865 做；MAE 预训练、批配比、位置编码、PSL 在新架构下的贡献均未消融——+0.23/+0.67 里架构与配方无法拆分。
  • 对比不严谨处：表 2 两行 MBv2（33.42/32.51）差异未说明；AT 基线引自 PSLA 是否带 ImageNet 预训练未标注；KWT/LETR 未纳入延迟对比；KWS 侧无固定误报率下误拒率或 DET。
  • 规模与多样性：K=10 关键词、单语学术数据；只动层数不动宽度——D=128 以下、L=4 以下极限未探；训练总耗时与 MAE 成本未报。
自然的延伸方向：接入完整 Audioset ~200 万片段（MAE 已用全量、监督训练却停在 60h——PSL 本就为大规模弱监督设计，最便宜的增量）；量化与异构计算（int8 + NPU delegate；BN-A 压缩后的注意力矩阵对低比特量化的友好度值得单独验证）；流式化改造（1s chunk 换滑动窗因果注意力 + 补丁内流式读出——压低 160ms 地板才能对接真实唤醒产品）；补回鲁棒性评测（新骨干上复跑 Musan/VL106 与产品困难负例）；条件唤醒的定量验证（「含人声音乐时不唤醒」的分层测试集）；输出层剥离与多档部署（BCE 输出节点可物理删除——按场景裁 537 维输出，与三档家族形成「宽度 × 输出」部署矩阵）。
