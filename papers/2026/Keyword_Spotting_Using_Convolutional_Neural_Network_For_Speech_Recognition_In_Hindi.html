印地语 CNN 关键词检测
自建数据集 + 噪声增强把真实测试从 60% 拉到 91.79%

Keyword Spotting using Convolutional Neural Network for Speech Recognition in Hindi

作者：Saru Bharti, Pushparaj Mani Pathak —— IIT 鲁尔基分校（iHub DivyaSampark / 机械与工业工程系）

发表：2026.04 · arXiv:2605.02928 · 应用型短文

印地语 KWSMFCC + CNN自建数据集 21 类含负类噪声增强端侧 CPU

一分钟版本

  • 背景：英语 ASR 模型众多，印地语离线选项「更大或更不准」；开源印地语语料全是朗读/新闻/叙事域，没有关键词任务需要的分布。
  • 数据：从零自建——21 类（数字 0–15 + 4 个高频口语词 + 1 个负类）· 40,000+ 样本（约 35k 来自增强）· 多样化说话人 · 44 kHz / 1.9 秒定长。
  • 模型：经典 MFCC（13 系数 × 162 帧）+ 卷积栈（递增核 + BN + 池化 + dropout）+ 双 dense + 21 类 softmax，交叉熵 + Adam。
  • 结果：验证 95%，独立人群真实噪声测试 91.79%——增强前的数字只有 60%，+31.79 点全部来自数据增强。

§01 · 问题陈述

印地语数据：有，但都不是关键词要的

前人印地语工作的共同短板：HMM 时代孤立词识别（Swaranjali 说话人相关 / 8 人 30 词 94.63% / KNN 89%）说话人规模小、词表固定、依赖显式对齐；Whisper 支持印地语但体积大、CPU 推理慢，且论文实测特定词检测准确率「非常低」；英文 CNN-KWS（ResNet 系）不覆盖印地语。

§02 · 方法论

经典流水线，赢在数据

数据集：本文最核心的实体贡献

增强三动作各有的「为什么」：七类噪声（车辆/人声/流水等）叠加后必须音量归一化——不同噪声源能量差数十分贝，不拉平网络会学到「响度与类别相关」的伪规律；时间偏移含「部分录制」样本——真实使用中词可能出现在任意相位甚至被截断；录音者覆盖不同口音与母语——避免学到特定人群的声道特征。

§03 · 实验结果

一个数字撑全文：+31.79 点来自增强

诚实记录：论文没有正式对比表——引言里 94.63%（HMM，30 词 8 人）、89%（KNN）与本文 91.79% 分属不同数据/词表/条件，不构成受控对比；对 Whisper 只有「特定词检测非常低」的定性判断无数字。负类有效性：错误输入或无输入时模型能正确落到负类（混淆矩阵定性层面），但无误报率/误唤醒统计。模型在「有人类活动噪声」到「风扇开最大档」的真实条件下保持 91.79%。

§04 · 主要贡献

五条可以带走的东西

1印地语关键词数据集
40k+ 样本 · 21 类（含负类）· 多样化说话人 · 规格统一——填补「印地语数字+特定词」开源数据空白，最实的贡献。
2端侧 MFCC+CNN 流水线
定长截断→Hann→Mel→DCT→卷积栈→21 类 softmax；独立人群真实录音 91.79%、验证 95%。
3增强决定性的受控证据
噪声叠加+归一化+时间偏移：60%→91.79%（+31.79 点）——小规模自建数据集可用性的关键。
4负类设计验证
错误/无输入正确落负类——端侧 KWS 抑制误触发的类别层机制。
5真实噪声可用性
从人类活动噪声到风扇最大档的各真实条件保持 91.79%。

§05 · 局限与展望

「计算高效」无定量证据

方法本身的技术局限

  • 效率声明无数字：参数量、FLOPS、模型大小、单次推理延迟、内存占用全部未报告——「轻量」只是架构定性。
  • 44 kHz 隐性开销：采样点与帧数是 16 kHz 方案的 ~2.75 倍，>16 kHz 频带的判别收益无论证也无降采样对比。
  • 1.9 秒定长的适配：连续音频流怎么滑窗、决策怎么平滑完全未讨论——分类器到检测系统的关键一环缺失。
  • 封闭 21 类词表：新词必须重训；「用户特定定制」实际只是「挑选关心的子集」，无免重训机制。

实验设计的不足

  • 测试集规模未披露：人数与样本数都未报告，91.79% 无置信区间、无多种子重复。
  • 无受控基线对比：与 94.63%/89% 分属不同条件；未与 DS-CNN 类经典小骨干同数据对比。
  • 增强时序存疑：增强在 80:20 划分前还是后未说明——若同源副本分属训练/验证，95% 会被高估（最值得追问的一处）。
  • KWS 核心指标缺失：无误报率/误唤醒统计/ROC/AUC；混淆矩阵未做数值解读。
  • 超参无扫描：13 系数、窗长帧移、卷积深度宽度全为单点取值。
值得跟进的方向：① 降到 16 kHz 复测准确率以压缩端侧计算；② 补参数量/FLOPS/延迟/误唤醒率报告使「端侧高效」可验证；③ 流式滑窗 + 决策平滑，升级为连续检测系统；④ 在 MUCS 100 小时公开语料上跨数据集验证泛化；⑤ 混淆矩阵里近音数字词的针对性难例增强；⑥ 少样本自定义唤醒词机制兑现「用户定制」承诺；⑦ 远场混响与多说话人重叠增强覆盖真实部署形态。
