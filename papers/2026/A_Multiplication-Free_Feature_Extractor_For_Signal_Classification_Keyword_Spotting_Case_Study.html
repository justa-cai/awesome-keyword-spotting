无乘法特征提取器 iRDT
面向关键词检测的信号分类案例研究

A Multiplication-Free Feature Extractor for Signal Classification: Keyword Spotting Case Study

作者：Radu Dogaru, Ioana Dogaru —— 布加勒斯特国立理工科技大学 POLITEHNICA（罗马尼亚）

发表：2026.08 · arXiv:2608.17108 · TinyML / 边缘智能方向

无乘法特征提取iRDT 反应-扩散变换 一维拉普拉斯INT8 量化 TinyML 低功耗Google KWS 12 类

一分钟版本

  • 把 KWS 前端里的乘法全部换成「加减 · 取绝对值 · 移位」三种整数运算，精度与 MFCC 打平（94.73% vs 94.40%，VRES 分类器），特征提取快 33 倍（0.2 ms vs 6.7 ms）。
  • 核心思想只有一句话：「延迟即频道」——多个尺度的对称二阶差分 + 绝对值累加 ≈ 一组对数间距的滤波器组，直接张出伪谱图，不需要 FFT、Mel、DCT。
  • 没有可学习参数，表达力全部来自 3 个手工超参（w / chan / win_per_segm），特征尺寸 246–750 连续可调，复杂度解析式 Ops ≈ 5mN。
  • 最硬核的工程细节：log₂(1+x) 压缩把 INT8 量化掉点从 2~2.5 个点压到 0.1 以内，且这条 log 本身用查表实现——修复手段也零乘法。

§01 · 问题陈述

算力的大头不在神经网络，在特征提取

为什么盯着前端打：分类器一侧（DS-CNN 只有 2.1–4.7 K-MAC 量级）已经足够小，前端的常数开销才是主要矛盾——压分类器收益递减，压前端一本万利。

乘法为什么是「原罪」

Mel 频谱（MFCC）流水线的四段——FFT 内部乘法与余弦、Mel 滤波器组加权乘法、对数运算、DCT 余弦乘法——三段离不开乘法器和超越函数。而底层硬件的账本很清楚（Horowitz, ISSCC 2014 经典能耗分析）：

运算相对能耗在无 FPU 的 MCU 上
整数加 / 减1×（基准）1 个周期级
乘法 / 浮点运算高约一个数量级浮点乘法烧掉几十个时钟周期

换句话说：「特征提取器里还有乘法」本身就是 TinyML 场景的原罪。而主流框架（EdgeImpulse 等）基本只提供 MFCC 这类谱特征——开发者实际上没有「便宜的特征」可选。

现有方案 A：MFCC 谱特征

  • 精度成熟、生态最广；
  • 但计算密集（乘法 + 余弦 + 对数），FPGA / 低功耗 MCU 实现不友好；
  • FFT 窗口、Mel 滤波器组需要 DSP 单元或多位乘法器。

现有方案 B：CNN 自编码器特征（基线 [8]）

  • 报告精度优于 MFCC，但训练开销大；
  • 依赖含乘法的卷积算子——复杂度问题原封不动；
  • 换一类信号（语音 → 超声 / EEG）必须整个重训，不可迁移。
两类方法都没碰的根本问题：特征提取这一步能否彻底放弃乘法，同时不损失判别力？
约束条件：Google 12 类 KWS 数据集、与基线完全相同的实验设置；准确率差距 ≤ 1 个点；计算时间压低至少一个数量级；硬件足迹压到极少量逻辑门。

§02 · 方法论

iRDT：用整数运算张出一张「伪谱图」

整条链路（论文 Fig.2）：刻意保留 M×m 的 2D 输出格式对齐 MFCC 谱图形状——换特征不换分类器，现有 CNN 生态零改动可用，对比实验也因此公平。

基本计算单元：一维拉普拉斯（对称二阶差分）

「延迟即频道」：一个近似对数间距的滤波器组

论文没有做频域分析，但传递函数一算就明白（笔记者推导）：Ld 的传递函数为 H(ejω) = e−jωd + ejωd − 2 = −4sin²(ωd/2)——直流处恒为零（抑制漂移），主峰位于 f = fs/(2d)。在 16 kHz 采样下，默认延迟列表 d = [1, 2, 4, 8, 16, 32] 恰好对应六个倍频程通道：

这个解读同时解释了两个实验现象：密延迟列表（插入 6/12/24）在同等特征尺寸下精度更好——频率轴采样更密；w=128 表现差——最短时间粒度变粗。

复杂度模型：两个整数决定一切

Ops(iRDTv) ≈ 5mN
N = 信号长度，m = 通道数。代入 N=16000、m=6 → 480k 次 int32 操作。对照：同信号 MFCC（FFT 窗 2048 / hop 512 / 13 系数）约 3M flops，且混着乘法与三角函数——操作数差 6 倍，再叠加「整数加减 vs 浮点乘加」的单操作代价差，构成实测 0.2 ms vs 6.7 ms（约 33 倍）时延差距的底层解释。

三个超参数 = 一套「复杂度–精度」旋钮

超参数取值规则作用机理
w（滑窗长）取 2 的幂；KWS 选 64决定最细时间粒度与延迟上限（dm ≤ w/2）；w=128 实测系统性偏差
chan（延迟列表）2 的幂次列表，默认 [1,2,4,8,16,32]决定频率轴通道分布；可插中间延迟加密频率采样，代价是 m 增大、操作数线性上涨
win_per_segm最关键参数直接决定帧数 M 与特征尺寸 M×m，进而线性决定下游分类器 K-MAC

价值在于：前端复杂度（线性于 m）和后端复杂度（线性于 M×m）被同一组旋钮连续调节——工程师按目标平台预算在精度-复杂度曲线上滑动选点，而不是在 MFCC-13 / MFCC-20 几个预制档位之间跳选。

log₂(1+x)：救活 8-bit 量化的关键一招

问题链路：TinyML 部署要求 INT8 → 原始 iRDT 输出是线性能量的整数累加和，数值跨度大，8-bit 均匀量化的分辨率被大面积浪费（MFCC 流水线自带对数压缩，所以没这个问题）。修复：输出端追加 log₂(1+x)——不破坏无乘法性质，MCU 上用 Flash 预计算查找表实现，零乘法开销：

§03 · 实验结果

数据说话：打平 MFCC，快 33 倍

数据与设置：Google Speech Commands（MLPerf Tiny 基准）构造 12 类、每类 3772 条、共约 45,264 条 1 秒片段——10 个命令词 + 均衡合成的 Silent / Unknown 两类；80% 训练 / 20% 验证；200 epochs、batch 48；与基线 [8] 完全同款 setup（同数据、同划分、同分类器），保证横向可比。

主对比：两个分类器上的准确率（Table II）

四个关键读数：① 对基线自编码器 FE：iRDTv-B1 用更小特征把 DS-CNN 准确率从 90.36 提到 92.11（+1.75 点）；② 对 MFCC-13：float 下略输（91.05 vs 91.70），但 INT8 公平对比下反超（91.47 vs 91.06），且分类器 K-MAC 从 2482 降到 2061（−17%）——这正是 log₂ 压缩的直接回报；③ VRES 把上限推到 94.73（摘要口径「94.7%」）；④ iRDT 的价值主张不是绝对精度反超，而是精度打平的前提下快 30 倍且零乘法。

CPU 实测时延：三个数量级的跨度

对数时间轴（Fig.2/3，Kaggle / 本地 CPU）：一个数量级领先 MFCC、两个数量级领先 CNN 自编码器前端。摘要「至少一个数量级」的表述其实偏保守。

消融：预算该花在频率轴还是时间轴（Table I）

五条发现：① 帧数 M 总体正相关精度但非单调（A3 > A2），存在与分类器感受野匹配的甜点区；② 同等预算下 B 类（密延迟）系统性占优——B1 用 747 特征 91.87% vs A0 用 750 特征 89.79%，把通道花在加密频率轴比花在时间轴划算；③ w=128 全面垫底；④ VRES 对小特征显著更鲁棒（A2 上差 DS-CNN 4.17 点）——「哪个特征好」脱离分类器谈没有意义；⑤ log₂ 压缩把 8-bit 掉点从 2~2.5% 压到 0.1% 以内。

§04 · 主要贡献

五条可以带走的东西

1首个在此对比框架下达到 MFCC 同档精度的无乘法 KWS 特征提取器
相同数据 / 分类器 / 训练预算下精度差 ±1 点内，多配置反超（92.11 vs 90.36；量化后 91.47 vs 91.06）。
2解析复杂度模型与实践吻合
Ops ≈ 5mN 把实现复杂度压缩成两个整数的乘积——480k int32 ops vs MFCC 3M flops，硬件工程师可直接带入周期估算。
3三超参旋钮体系 + 12 组消融
特征尺寸 246–750 连续可调，附明确取值规则：2 的幂延迟、dm ≤ w/2、优先加密频率轴。
4log₂(1+x) 与 INT8 的协同设计
识别并修复无乘法线性特征的量化脆弱性，修复手段本身零乘法（查表 / 移位近似）——端到端部署闭环的关键一环。
5完全可复现
代码 + Google Colab 演示 + 预训练 .tflite 全部开源（GitHub: radu-dogaru/rdt_transform_for_tiny_ml_signal_classifiers）。

§05 · 局限与展望

什么时候不该用它

方法本身的技术局限

  • 频率分辨率粗：通道数实测上限 9，每通道响应是梳状而非窄带，大延迟通道能量归属存在混叠——需要精细共振峰轨迹的任务（大词表、说话人相关唤醒词）表达力存疑。
  • 相位与极性信息全部丢弃：绝对值累加只保留能量包络，这是「用 |x| 替代平方避免乘法」的直接代价。
  • 定长输入假设：iRDTv 帧数由信号长度决定，面向 1 秒定长 KWS；流式 / 变长场景需改用 iRDTf，论文未做流式验证。
  • Scaler 依赖训练集极值统计：对域偏移（换麦克风、换噪环境）敏感，且极值统计对异常样本脆弱。
  • 超参纯手工：chan / w / win_per_segm 均为人工网格搜索，没有自动化路径。

实验设计的不足

  • 只有验证集准确率一个功能指标：没有 FRR/FAR、DET 曲线、混淆矩阵——而 KWS 作为检测任务，工程上恰恰是误唤醒率决定可用性。
  • 零目标硬件实测：MCU 周期数、FPGA LUT/FF、能耗（µJ/推理）、SRAM/Flash 足迹全部未报告——TinyML 论文的核心主张目前只是定性推断。
  • 单次运行无方差：0.3–0.5 点量级的差异统计显著性存疑。
  • 基线覆盖不全：FE in [8] 的 K-MAC 与 VRES 结果为空；未与 Sinc 滤波器组、可学习滤波器组等轻量前端对比。
  • 分类器参数量未报告：只有 K-MAC，无法完整评估存储代价。
值得跟进的方向：① 在真实 MCU（Cortex-M4/M55）和 FPGA 上补齐周期 / 能耗 / LUT 实测，把「very few logic gates」从主张变成数字；② 与二值 / 整型分类器（如 BiFSMN）串联，构成全程无乘法链路；③ 帧级流式实现 + VAD，评估连续监听下的 FRR/FAR；④ 可学习门控自动选延迟列表，替代手工 2 的幂规则；⑤ 与后端联合端到端微调（目前 FE 与分类器完全解耦训练）。
