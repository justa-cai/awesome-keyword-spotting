神经形态听觉传感器 + GNN
单颗 FPGA 上的端到端事件驱动 KWS

End-to-End Keyword Spotting on FPGA Using Graph Neural Networks with a Neuromorphic Auditory Sensor

作者：Wiktor Matykiewicz 等（AGH 大学，克拉科夫）；Tomás Muñoz 等（塞维利亚大学）

发表：2026.05 · arXiv:2605.09570 · 数据/代码/硬件模块全开源

神经形态听觉传感器图神经网络FPGA 单芯片 事件驱动 AER类 LIF 过滤每 10ms 出预测

一分钟版本

  • 范式：传统 KWS 固定采样率搬整张量，静默时也在算；神经形态传感器只在频谱变化时发稀疏事件，计算量随声学活动量缩放。
  • 系统：单颗 FPGA 上打通「物理 NAS 传感器 → 类 LIF 事件过滤（移位衰减，零除法器）→ 图构建 → PointNetConv×4 → 每 10ms 输出 class + 词结束置信度」，零 CPU 参与。
  • 关键改造：乘法器并行度 4→2（省 LUT/DSP）、背压调度 + 时间戳传播（保 10ms 窗语义）、极性作为免费输入特征。
  • 实测：87.43%（INT8）、端到端延迟 25–35 µs、1.12 W；数据集是 GSCv2 全量过物理传感器录制的六个配置版本——摆脱该领域对仿真事件数据的依赖。

§01 · 问题陈述

常开场景下，固定采样 = 为静默付费

SSP 范式：把信息表示整个搬进脉冲域——加法变计数、滤波变门逻辑。传感器侧功耗仅 29.7 mW；整条管线的功耗大头（约 0.5 W 动态）落在 GNN 推理侧，所以架构优化火力全部对准网络模块。

三个缺口

  • 事件音频方法依赖合成数据：SNN/SSM 路线普遍在 SHD/SSC 仿真数据上评测——仿真事件的统计分布与真实硅上传感器输出不同，「仿真调好、真机是否 work」无人回答。
  • 传感器与网络分离部署：前身 GNN-KWS 只部署网络侧，事件来自离线仿真，端到端只到网络输入为止。
  • 事件率过高且通道不均衡：128-parallel 平均 92 kEv/s、峰值 519 kEv/s；低通道号（高频）事件远多于低频——直接建图会被高活动通道带偏。

四个子问题

  • 传感器拓扑与通道数怎么选（频率分辨率 × 事件吞吐 × 资源功耗）；
  • 事件率怎么压到网络吞吐之内还不伤精度；
  • 为仿真数据和大资源余量设计的基线 GNN 怎么塞进目标器件；
  • 怎么评「词什么时候说完」而不只是分类准确率。

§02 · 方法论

三段式数据流，全在一颗 FPGA 的可重构逻辑里

硬件感知设计的细节：72 特征/层是消融「硬选」的——9×8bit = 72bit 恰好与 BRAM 存储字宽对齐、零浪费；conf 输出（词结束时刻定位）是面向流式的关键设计：下游真正要的是「什么时候说完」，不是每秒一个标签。

§03 · 实验结果

资源降三成，精度升一档

延迟与功耗分解：网络头延迟典型 2.11 µs（最坏 18.62）；NAS 输入到事件 23 µs；吞吐 245 kEv/s–2.1 MEv/s 均高于实测事件率（余量约 1.66×）。功耗：静态 0.595 W 是 UltraScale+ 的物理底盘；动态 0.49–0.54 W + NAS 29.7 mW。8-bit QAT 量化损失 0.6–0.97 点。与 SNN/SSM 路线对比（Table 4，注意基线在 SSC、本文在自建 NAS 数据集）：六配置 83.15–88.03% 超过全部 SNN（72.0–80.7%）和 GNN 前身（78.4–84.3%），唯一 Event-SSM 峰值 88.4% 略高——但本文模型更小且面向单 FPGA 端到端。

时间定位指标 Ts-acc：类别正确且词结束时刻落在 ±k 个 10ms bin 内才算对——类别对但时间错的操作后果等同于误报/漏报。64-parallel 的 Ts-acc₁ 最高 75.12%（Ts-acc₃ 81.85%）；parallel 全面优于 cascade（事件多一倍但无频率依赖延迟），cascade 的累积延迟直接拖累时间定位。

§04 · 主要贡献

四条可以带走的东西

1首个单 FPGA 端到端事件音频 KWS
物理 NAS 与 GNN 同芯片集成，原始音频进、每 10ms 出 class+conf，零 CPU、无常规信号预处理。
2公开真实神经形态录音数据集
GSCv2 六个 NAS 配置版本（含完整统计）——把该方向从仿真数据依赖中拉出来的基础设施。
3硬件友好的事件过滤
类 LIF、移位衰减、逐通道阈值：事件削减约一半且精度不降反升（74.36%→84%+）。
4消融驱动的 GNN 架构改造方法论
极性特征、乘法器减半、背压调度、时间戳传播——可迁移到其他事件驱动加速器设计。

§05 · 局限与展望

精度天花板、瓦级功耗、数值一致性瑕疵

方法本身的技术局限

  • 精度天花板明显：88.03%（FP32）显著低于常规 FPGA KWS 的 95–97%；「原始音频直入 + 10ms 分辨率」的差异化辩护成立，但对误报率敏感的产品场景是真实成本。
  • 功耗仍为瓦级：静态 0.595 W 是器件底盘；动态约 0.5 W 远高于传感器的 29.7 mW——瓶颈在网络，与 MCU 毫瓦方案不同量级。
  • 吞吐余量有限：最坏 245 kEv/s 对 64-par 峰值只有 1.66× 余量，靠 FIFO 吸突发；持续超载行为未报告。
  • 图存储深度有限（128 通道深 1024 条目），长邻域上下文间接受限。

实验设计的不足

  • SOTA 对比不同数据集：基线在 SSC、本文在自建数据集，严格说不构成同基准比较。
  • 数值一致性问题：Table 3/4 同名配置数字略有出入；87.43% 在第 5 节被归错配置；「约 47% 事件削减」与各配置实际的 33–55% 口径不一；消融最优阈值未被采用且无解释。
  • 关键细节缺席：关键词集合与类别数、数据划分、每推理能耗（功耗是 40kEv/s 负载下的仿真估计非实测）。
  • 鲁棒性评测缺位：干净 GSCv2 过传感器的单条件录音，无加噪/远场/多说话人——恰是论文自己指出的仿真数据短板的镜像。
值得跟进的方向：① 真实机器人 HMI 场景验证；② ASIC 实现突破 FPGA 静态功耗地板；③ 事件域噪声鲁棒训练与数据增广补泛化证据；④ 过滤参数可学习并与网络联合训练（当前纯手工消融）；⑤ 更低比特（二值化）特征与权重压缩 LUT/DSP；⑥ 利用 NAS 双耳实现做声源方向联合建模，服务机器人空间听觉。
