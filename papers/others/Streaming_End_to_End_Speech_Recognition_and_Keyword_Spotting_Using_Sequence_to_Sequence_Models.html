一个模型干两份活：RNN-T 同时供 ASR 和唤醒，解码时给关键词开小灶

RNN-T 统一 ASR+KWS（首个）关键词偏置（解码时）上下文感知门控检测率 +5-15% · WER <0.5% 代价帧级 ~10ms 流式
Streaming End-to-End Speech Recognition and Keyword Spotting Using Sequence-to-Sequence Models · Yanzhang He / Rohit Prabhavalkar / Kanishka Rao / Wei Li / Anton Bakhtin / Ian McGraw（Google）· 2017 · arXiv 1706.02563
一句话：RNN-T（编码器 + 预测网络 + 联合网络）一个模型同时做流式通用转录和定向关键词检测——解码时对目标词 token 加上下文感知的正向偏置（匹配前缀才加强）：检测率 +5-15% 绝对、WER 增加 <0.5%，零重训调灵敏度。

1问题：分立系统的三笔浪费

TL;DR
  • 独立训练的声学/语言模型没有全局优化；多模型 + 复杂解码器维护成本高。
  • KWS 和 ASR 是两套系统——无法共享计算与参数，设备上跑两份模型。
  • 挑战：端到端模型（RNN-T）在严格实时约束下同时服务两个任务。
图 1 · 机制全景：分立三笔浪费 → RNN-T 三件套架构（CTC + 预测网络破条件独立）→ 关键词偏置四步机制 → 关键数字。

2机制：解码网格与偏置门控

RNN-T vs CTC

预测网络引入输出 token 间的条件依赖——「下一个字看已输出什么」，突破 CTC 的条件独立假设。

偏置机制

目标词 token 的 logits 加正向偏置项——不改参数、纯推理时机制，换词/调灵敏度零重训。

上下文感知

已输出序列匹配词前缀时才强偏置；不匹配不偏——避免在无关语境误推关键词。

流式三保

单向编码器只看过去 · 逐帧解码 · 帧级 ~10ms 延迟——常开场景达标。
图 2 · 左：RNN-T 的 (t,u) 网格——横向 blank、斜向 emit，一条路径 = 一种「何时出什么字」；右：上下文感知偏置——「he」匹配前缀才推「y」，「th」不匹配照常出「the」。
logits'(关键词 token) = logits + bias × 𝟙[已输出匹配前缀] α(t,u)：帧×token 的累积概率 L = −log Σ α(T,U)
人话：模型本来就会听写所有的话（ASR）。检测唤醒词时给它开个小灶：每当它已经写出的字正好是唤醒词的开头，就悄悄把「下一个该写的字」的分数加一点——顺着词的拼写一路加，词写完整的概率就上去了；写的字跟唤醒词对不上时一分不加，正常听写不受影响。

3结果（定性）：偏置强度的甜点

图 3 · 左：检测率与误唤醒随偏置强度的走势——存在甜点使检测率显著升而误唤醒可接受；右：双指标共存（KWS ≈ 专用系统 · ASR WER <0.5% 代价 · 词位置无关）。

4边界：算力的身价

计算成本高

比 DS-CNN 这类专用 KWS 重得多——MCU 跑不动；定位是手机 AP 级算力。

偏置靠手调

每个词/场景要调强度——发音独特的词少偏、近常见词的要精调。

困难声学未测

远场 · 强噪声 · 强混响（音箱/车载典型场景）评估不足。

数据需求大

RNN-T 要大量标注语音——低资源语言/领域难满足。

偏置不治本

只调概率分布不改声学理解——声学上极像的干扰词仍难区分。
图 4 · 边界五条 + 谱系坐标：偏置思想的流变（推理时 logits 偏置 → shallow fusion → 训练内偏置学习）；RNN-T 骨架经 Conformer/TDT 演进至今——「一个模型同时供 ASR 与唤醒」已是 2020 年代的事实标准。

5判断：能带走的三句话

JUDGEMENT

统一架构的红利是「共享表示」：ASR 和 KWS 用同一套声学编码——唤醒词检测搭了通用转录的便车，一份算力两份产出；当两个任务共享底层能力时，合并模型比维护两套系统更便宜也更准。

推理时偏置是零成本的任务倾斜：不改参数、不加模型，只在解码 logits 上动手——「同一个模型，不同的使用偏好」；这种机制让一个部署覆盖多场景（换唤醒词、调灵敏度）而无任何重训。

上下文门控决定偏置的安全性：均匀偏置会把关键词 token 推进无关语境——前缀匹配门控让偏置只在「有戏」的路径上生效；所有解码时干预技术都要配一个「何时不干预」的条件。
