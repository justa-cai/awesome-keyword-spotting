窗口长度怎么选都错？
那就滑窗定位、变长确认：52K 参数的双路唤醒检测

SE-Res2Net · 双路干预式检测 arXiv 2209.15296 · letter 短文 Mobvoi SLR87 · Hi Xiaowen / Nihao Wenwen 52K 参数 · FRR@FAH=0.5：0.53% / 0.30%
一句话：唤醒词长度在 30–200 帧间浮动（近 7 倍），CNN 却要定长输入——固定窗口对长短词两头都失败。本文用双路拆解这个两难：M1 滑窗学局部模式并常驻扫描定位，M0 把变长片段插值到 200 帧学全局轮廓、只在疑似区域介入确认。骨干用 SE-Res2Net（单层内多尺度感受野 + 学出来的尺度注意力）激进瘦到 52K，在 Mobvoi 上以 LF-MMI 一半参数站进 SOTA 区间，对 ResNet 基线相对降幅最大 86.6%。
TL;DR
  • 结构性矛盾：同一唤醒词因语速/停顿不同，频谱图 30–200 帧浮动，CNN 要求定长——词比窗长则全局轮廓拼不全（漏检），词比窗短则特征被污染（误唤醒），窗口长度怎么选都错。
  • 引言的关键论断：准确的唤醒词片段本身就有价值——问题不在模型容量，在喂进来的输入不干净不完整。VAD 只判「有没有人声」，不解决窗口错配。
  • M1 切片通路（局部）：滑窗逐段判「有没有唤醒词碎片」，窗长随词调（75/100 帧非全局一刀切）；子段标签直接继承整句（弱监督简化）——职责是定位不是切边界。
  • M0 整形通路（全局）：变长片段双线性插值到固定 200 帧（可预计算的卷积、零参数），学整个词的全局时序轮廓；不常驻——只在 M1 圈出疑似区域后介入，把贵的计算花在刀刃上。
  • 流式判决全手工但分层防抖：M1 分数超 γ₁ 记触发点 → ≥2 个连续触发点才唤 M0（单偶发高分被过滤）→ y_M1 取 max、M0 看首末触发点之间 → 平均分判决 → 1 秒不应期防重复。
  • 骨干贡献拆解：ResNet→Res2Net 约 −31%（单层内 1~s−1 次卷积深度并存的多尺度），Res2Net→SE 再砍大头（通道重标定 = 学出来的尺度注意力）——两个机制叠加非替代。
  • 瘦身交易：删整个 Conv5 stage（128K→52K，−60%），FRR 只涨 0.06/0.05 个点。52K vs LF-MMI 120K——但「性能相似」要按词拆读：四音节词好 40%，三音节词差 32.5%。
  • 两处按下不表的空白：双路设计无独立消融（M0-only/M1-only 对照缺失，框架收益与骨干收益不可分离）；零部署侧实测（延迟/功耗未报，参数口径还不明——若 52K 是单分类器，系统总量翻倍）。

    • §01问题：变长目标 vs 定长模型

    四条老路线的不足 + 固定窗口的不对称失败

    词比窗口长：拼不全

    固定窗（如 1 秒非重叠段）每次只看到唤醒词的局部特征，整个词的全局时序轮廓永远拼不完整——模型永远在看局部，漏检成为结构性结果。

    词比窗口短：被污染

    窗口里混进大量非唤醒词语音，全局特征被污染，误唤醒随之而来。加 VAD 只能省算力——它只判断「有没有人声」，完全不解决窗口与词长的错配。

    老路线各自的行李

    LVCSR 换词方便但算力远超常驻预算；keyword/filler HMM 至今有竞争力但解码图是工程负担；负例挖掘系统训练要额外的 HMM-TDNN 声学模型；LF-MMI 是混合 HMM/DNN 框架——附加依赖在小足迹部署里都是实打实的成本。

    RNN 的串行代价

    连续输入流可能状态饱和；时序串行依赖让 chunk 流式无法并行，即使有 GPU 计算成本与延迟也上升。唤醒词很短，堆叠多层 CNN 的感受野足以覆盖——不必付 RNN 的代价。

    §02方法：定位交给滑窗，确认交给插值

    把 HMM 里 Viterbi 解码搜索的职责移植进纯 CNN 世界
    Res2Net 块（s=4，通道切分 + 层内级联）: y₁ = x₁ # 不过卷积，等效深度 0 y₂ = K₂(x₂) # 一次 3×3，等效深度 1 yᵢ = Kᵢ(xᵢ + yᵢ₋₁) 2<i≤s # 输入混入上一段输出，深度递增
    人话：同一层之内天然并存 1 到 s−1 次卷积深度的感受野层级——这是「免费」的结构属性，对比 bottleneck 各分支感受野完全相同。多个块堆叠后因组合效应拿到各种粒度的表示。适配逻辑：目标检测要处理大小悬殊的物体，唤醒词要处理长短悬殊的词——对「单层内多感受野」的需求同构。
    M1 滑窗打分 → 分数 > γ₁ 记触发点 → ≥2 个连续触发点 = 疑似区域 y_M1 = max(连续触发点分数) # 一个强响应子段即可顶起——匹配「碎片存在性」职责 M0 介入：检测第一触发点~最后触发点间的片段（插值到 200 帧）→ y_M0 y_f = (y_M0 + y_M1)/2 > γ₁ → 触发 → 1 秒不应期
    人话：M1 窗小、扫描频繁但单次便宜，适合常驻；M0 大而全但调用稀疏——常驻系统的平均算力被压低。M0 的输入被触发点天然「裁剪」，等于推理时自动做了一次内容聚焦，窗外语音不进全局判别。「两个连续触发点」是对孤立虚警的廉价防抖；γ₁ 一阈值两用（子段触发 + 最终判决），开发集上调整。

    双线性插值为什么敢用

    依据是「同一段语音的频谱图结构相似」——插值只改变时间轴采样密度不破坏结构。且它不是可学习变换而是一次可预计算的卷积，训练推理零额外参数。边界：30 帧拉到 200 帧 ≈ 6.7 倍拉伸，极端缩放下是否保住判别特征论文未分析。

    标签继承的容忍度

    子段继承整句标签——(a)(b)(c) 含部分/全部唤醒词都是正例，(d) 负例。M1 只判「碎片存在性」，这个粒度的监督够用；代价是无法区分「Nihao Wen」与「Nihao Wenwen」的尾部差异——对同产品线易混词的区分能力存疑。

  • 协议设计贴近真实：每个唤醒词单独训二分类模型，另一个唤醒词计入负例——用户说别的命令词不应触发本词模型，比只用随机负例更贴近真实误唤醒场景。

    • §04贡献

    四点：从双路框架到选词判断
    1

    双路特征管线 + 干预式两级检测：M1 滑窗学局部并粗定位、M0 变长插值学全局并确认、平均分判决——机制上拆解固定窗口两难，系统自行确定唤醒词位置、不依赖任何辅助网络。

    2

    Res2Net 引入唤醒词检测：目标检测的多尺度骨干与「唤醒词时长差异大」同构；消融显示骨干替换是仅次于 SE 的性能来源（−31.2%/−23.1%）。

    3

    结构瘦身到五万参数量级：通道缩减 + 删 Conv5，52K 参数（约 LF-MMI 一半），FAH=0.5 下 0.53%/0.30%，且训练不需要附加声学模型或对齐机制——部署链路干净。

    4

    音节数效应的工程观察：四音节词天然比三音节词好检——为唤醒词产品选词提供可迁移判断。

    §05局限与判断

    核心创新无独立消融 · 零端侧实测 · 参数口径不明
    图4 · 边界与延伸：左技术边界（弱标签上限、手工规则、零部署证据、插值畸变、每词一模型），右实验边界（双路无独立消融、超参无扫参、口径不明、无压力场景）+ 延伸方向。
    可迁移判断

    ↳ 定位与确认分开，常驻的只做便宜的那半：M1 小窗常驻扫描、M0 大模型按需介入——平均算力被结构性压低。这个「先粗后精」的级联思路对任何常驻检测任务（VAD、事件检测）都适用。

    ↳ 变长输入不一定要 RNN：插值保结构 + 滑窗给定位，纯前馈也能吃变长序列——不想付串行代价时，先想想输入侧能不能重整，而不是直接上循环结构。

    ↳ 多尺度是免费的结构属性：Res2Net 的感受野阶梯来自通道切分 + 层内级联，不增加任何新算子——选骨干时「单层内感受野多样性」是一个被低估的杠杆（本文消融里值 31%）。

    ↳ 引用前先拆收益归属：本文的 SOTA 数字 = 双路框架 × SE-Res2Net 骨干 × 标签策略的组合效果，但没有 M0-only/M1-only 对照——复现或借鉴时，应把「框架带来的」与「骨干带来的」分开验证，否则容易把全部收益记到其中一个头上。
