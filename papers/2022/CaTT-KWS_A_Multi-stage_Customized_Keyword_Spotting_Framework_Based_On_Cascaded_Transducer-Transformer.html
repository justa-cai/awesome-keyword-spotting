29 条命令的误报一小时 1.47 次，
这个级联框架把它压到 0.13 次

CaTT-KWS · arXiv 2207.01267 西工大 ASLP × 腾讯 tiny transducer + 强制对齐 + transformer 终审 3.8M 参数 · 23000h 训练
关键词定制完全放在 WFST 搜索图——加命令零数据采集、零模型重训；误报压掉九成一的代价是准确率掉不到 2 个点。

一分钟版本

  • 场景不是单唤醒词：车载命令控制要同时在线检测几十上百条命令，命令越多解码路径越多，无关语音「碰巧」走进某条命令路径的先验同步放大——误报复控。
  • 基线画像：tiny transducer 检测级干净集准确率 96%，但每小时误报 1.47 次；高唤醒率伴随高误报是 transducer 路线的老毛病。
  • 前作 MLD 的天花板：后级置信度（滑窗和、编辑距离概率、近似似然）全部从同一份 transducer 输出推导——统计变换不产生新信息，transducer 估偏了它们一起错。
  • CaTT 的解法：三级级联共享编码器——transducer 高召回检测 → 音素预测器 Viterbi 强制对齐（修边界 + 第一道闸 S1）→ transformer 终审（第二道闸 S2），三路证据参数独立、犯错模式不相关。
  • 定制秘密：关键词知识全部外置在 LG = min(det(L∘G)) 搜索图里，加新命令只改语法图 G 重复合一次，模型权重不动。
  • 核心数字：误报 1.47 → 0.13 次/h（相对降 91.15%），准确率干净 96 → 94.20、嘈杂 87.65 → 85.69，两端都不超 2 个点。
  • 边界修正是隐藏功臣：流式模型发射延迟让起点偏晚 0.29–0.44s，对齐修到 0.11–0.23s；边界不准时 transformer 单独上（误报 0.23）不如先对齐再终审（0.13）。
  • 两个反直觉消融：transformer 容量并非越大越好（1 块 0.9M 是甜点，4 块在低误报区反而更差）；音素 vs 汉字单元存在交叉——低误报区音素稳、高误报区汉字反超。
  • 边界：29 条命令就做到 0.13，「上百条」是外推；84h 负样本全在车载域，跨域误报未测；τ=1.5 / υ=5 / td=15 全是经验值，换域可能失配。
  • 可迁移判断：级联校验压误报的每一分收益都从召回借来；校验级的价值取决于它与检测级犯错的独立性，而不是置信度公式多精巧。

§01问题：命令词场景的误报复控

关键词从 1 条扩到 29 条，误中机会放大近 30 倍

命令控制与隐私敏感应用需要端侧常驻的本地 KWS，同时在线检测几十上百条命令。机制上不难理解误报为什么会失控：解码搜索空间里的合法路径随命令数增长，任意一段广播、闲聊、驾驶噪声「碰巧」走进某条命令路径的先验同步升高。单唤醒词只有一条目标路径可以误中，二十九条命令把这个机会放大近三十倍。每次误触发的代价是系统在用户没说话时「自作多情」地执行命令——体验破坏是直接的。

另一个老痛点是定制成本：固定词表的神经 KWS 把词表烧进输出层，加一条新命令就是一轮数据采集 + 模型重训，产品迭代节奏下不可接受。理想状态是改个配置就能上线。

注意力偏置 transducer 路线的两个缺口

He [12]、Liu [13]、Tian [14] 用注意力偏置或 CTC 联合训练把搜索拉向关键词转写——但基本只考虑单唤醒词场景，多命令同时检测没人探索；且 transducer 方法唤醒率高、误报问题同样突出，命令场景下会被放大。

MLD 的单源证据天花板

与本文最相关的 MLD [13]：检测级滑窗检出候选，校验级算编辑距离概率和近似似然。批评切中要害——所有置信度从同一份 transducer 输出推导。transducer 对噪声帧音素后验估高了，后续统计量跟着一起错：它们不是独立的第二意见，而是同一输出的不同变换。

本文要同时满足四个相互牵制的条件：准确率不能明显恶化；误报压到极低；新增关键词零采集零重训；整体约 3.8M 塞进端侧。压 FA 最直接的办法是加严阈值（伤准确率），加校验模块最直接的办法是堆模型（伤体积延迟）——解法是「级联 + 共享编码器 + 事件驱动计算」：校验模块只在触发时短暂运行，常驻开销只有第一级。

§02方法：三级级联，共享编码器，多任务一次训练

检测故意高召回，精度问题留给异源校验

图1 · 框架全景：三级流水线 + 共享编码器 + 事件驱动计算。检测级故意高召回，强制对齐修边界并做第一道闸（S1），transformer 按长度先验强制截断 beam search 做终审（S2）；定制全部发生在 LG = min(det(L∘G)) 搜索图层。

几个架构决策的「为什么」值得逐条拆。第一级为什么用 transducer 而不是封闭集分类器：建模单元是 210 个 CI 音素，关键词约束完全放在解码侧 WFST 搜索图里，模型权重不感知词表——第一级因此可以「故意」做成高召回（论文明说这一阶段试图在关键词上召回更多案例但不可避免产生大量误报），级联系统的召回天花板由第一级决定，宁可放宽。

校验证据为什么必须独立于 transducer 输出：强制对齐用的是音素预测器（挂在共享编码器上的独立线性头）的帧级后验，终审用的是另一套自注意力参数——与 transducer 联合网络不共享参数、归纳偏置不同、犯错模式不相关。三路证据都指向「是关键词」才触发，FA 被指数级压缩。

L = α·LTransducer + β·LCE + γ·LTransformer　（α=1.0, β=0.8, γ=0.5）
人话：一个编码器带三个头一起练。transducer 损失是主任务；帧级音素 CE 给 0.8 是因为它稠密——每一帧都有标签，而 transducer 损失只在发射 token 的边界带梯度，稠密帧级监督能加速收敛并正则化编码器；transformer 是校验辅助任务给 0.5。
LG = min(det(L ∘ G))
人话：词法 L 把音素串映射到词，语法 G 是命令集文法网络，复合后确定化最小化成搜索图。加新命令 = 往 G 加一条音素序列重复合一次。定制的全部秘密在这个式子里——与经典 DNN-HMM+WFST 混合框架同构，创新在把它嫁接到流式端到端 transducer 上并配两级神经校验。推理用 greedy + skip blank（只对非 blank 的有效 token 搜索，跳过占大头的 blank 发射）。
S₁ = −Σ log(plt) / T　< τ = 1.5　｜　S₂ = −Σl∈B log(pl)　< υ = 5
人话：S1 是对齐区间上的平均帧级负对数似然——除以 T 做长度归一化，否则长命令似然求和天然偏大被系统性歧视。S2 是 beam 命中序列的裸求和——不是疏忽：beam 被强制在第 M 步截停（M = 候选音素长度），所有假设等长、天然可比。终审实际是两道闸：beam 里没有任何序列与候选匹配直接拒，有匹配才进阈值比较。

强制截断的 transformer 终审是第三个精巧设计：这一级做的是「验证」不是「生成」——答案长度是已知先验，判别信息在 M 步内必然全部展开。收益三层：计算有上界（M 通常六到十几步）；beam 假设等长，S2 无需归一化因子；顺带规避自回归解码器在短序列上拖尾输出无意义 token 的风险。

§03实验：23,000 小时训练，车载双条件测试

6,000 句 × 29 条命令（干净/嘈杂各半）+ 84 小时负样本

训练数据 23,000 小时普通话 ASR 语料（腾讯车载产品真实数据）——这是免采集定制的物质基础：音素级建模单元配两万三千小时通用语音，声学模型见过足够多的音素上下文变体，新命令只是旧音素的新排列。测试 6,000 句覆盖 29 条命令（每条含六个以上音素，如「打开导航」= d a3 k ai1 d ao3 h ang2），按采集条件分干净（高速）/嘈杂（市区）两组。误报在 84 小时广播+闲聊+驾驶噪声上统计。

图2 · 主结果（Table 1）：左为命令准确率（干净/嘈杂），右为每小时误报。完整 CaTT（S3）误报 0.13 次/h 相对基线降 91.15%；对 MLD 复现（S4）准确率相仿但误报是其一半。

§04贡献：五条能转述的判断

级联异源校验在多命令定制 KWS 的完整落地
1

多阶段定制 KWS 框架：流式 tiny transducer 检测、音素预测器强制对齐校验、transformer 解码终审的级联结构，共享编码器多任务一次训练成型——「用级联异源校验压制误报」在多命令场景的完整落地。

2

误报压制有数据背书：车载数据集做到 0.13 次/h，相对基线降 91.15%（表1 S3），准确率代价不超过 2 个点——用不到 2 个点换九成误报削减。

3

零成本定制机制：定制完全在 WFST 搜索图层面（式2 的 LG 复合），新增关键词零采集零重训；音素/汉字两种粒度可按工作点选（第3.5节）。

4

强制对齐一器两用：训练时是正则编码器的辅助任务，推理时是边界修正器 + 一级校验器——把发射延迟痛点（起点误差 0.29/0.44s）修到 0.11/0.23s，并证明准确边界是后级校验性能的前置条件（S1 对 S3）。

5

端侧可行性标定：整体 3.8M + 事件驱动校验；消融标出 transformer 容量甜点（1 块 0.9M），避免无谓堆料。

§05局限与边界

每一分误报收益都是从召回借来的

准确率代价不可忽略

干净集 96 → 94.20，约 1.8 个点的真命令被后级误杀。对命令控制，误拒同样伤体验——喊「打开导航」没反应再喊一遍的挫败感，论文没讨论商业代价。

超参数全靠经验

α/β/γ=1.0/0.8/0.5、τ=1.5、υ=5、td=15 全是经验值，无敏感性分析。τ 和 υ 直接决定工作点，从车载换到家居很可能失配。

固定回推 vs 波动延迟

td=15 帧是常数回推，但发射延迟随声学条件变化（嘈杂 0.44s vs 干净 0.29s）；嘈杂集对齐后仍剩 0.23s，没完全解决。

S2 缺跨关键词归一

同一关键词内 beam 等长可比，但不同命令音素长度不齐，全局 υ=5 对长命令天然偏松——未按命令分别设阈值。

命令规模与宣称有差距

摘要说「几十上百条」，实测 29 条。29 → 100 条时 FA 从 0.13 涨到多少没报告，「上百条」是外推。

负样本域单一 + 无系统级开销

84h 负样本全在车载域，家居/电视/多说话人跨域误报未测；推理延迟、RTF、各级触发率与开销分解、内存功耗全没报——端侧论证只落在 3.8M 一个维度。MLD 基线是自行复现（S4），复现细节未给。

可迁移判断（超出 KWS 也成立）

  • 级联校验压误报的每一分收益，都是从召回侧借来的——设计级联时先算清楚愿意付多少召回。
  • 校验级的价值取决于它与检测级犯错的独立性，而不是它算出的置信度公式多精巧——同一份输出的统计变换不是第二意见。
  • 验证类任务（答案长度已知）用长度先验强制截断解码：开销有上界、假设天然可比、规避拖尾——比自由生成便宜得多。
  • 密集帧级辅助监督（每一帧都有标签）能给稀疏梯度的主任务（只在发射边界有梯度）加速收敛并正则化——一器两用的前提是头足够轻（一个线性层）。
  • 校验器容量有甜点：严格工作点上盲目堆参数反噬（4 块 3.2M 在低误报区不如 1 块 0.9M）。
