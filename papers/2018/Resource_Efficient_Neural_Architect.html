别搜「最准」，搜「这个预算下最准」：把三重资源惩罚直接写进 NAS 的奖励函数

资源约束 NAS（早期代表）网络嵌入 + 策略网络渐进式架构修改计算强度 FLOPs/byteGSC 无约束 SOTA
Resource-Efficient Neural Architect · Zhou / Ebrahimi / Yu / Liu / Arik / Diamos（百度研究院硅谷 AI Lab）· arXiv 1806.07912（2018.06）
一句话：RENA 用 RL 从好基线渐进修改架构，奖励 = 准确率 − λ·（模型大小 / FLOPs / 计算强度三重阶跃惩罚）——约束内自由追准、超预算按量罚：CIFAR-10 与 GSC KWS 双验证，无约束下 GSC 达当时 SOTA，严格约束下胜过手工优化。

1问题：传统 NAS 的资源盲区

TL;DR
  • 传统 NAS（Zoph RL / Real 进化）以准确率为唯一目标——搜出的架构计算量巨大，边缘设备根本跑不动。
  • 约束靠事后过滤：先搜完再剔除违规架构——大量算力浪费在注定违规的候选上。
  • 搜索空间默认不含 depthwise / 分组卷积——资源高效的操作根本不在候选里。
图 1 · 机制全景：NAS 资源盲区四条 → RENA 循环（网络嵌入 → 策略网络 → 三重惩罚评估）→ 渐进式 vs 从零搜索 → 结果速览。

2机制：三个指标各管一段物理预算

模型大小

参数字节总数——管存储与内存预算（嵌入式设备的第一道墙）。

计算复杂度 FLOPs

浮点运算次数——延迟与功耗的代理指标。

计算强度 FLOPs/byte

计算与访存的比例——高强度架构更适合 GPU/TPU 并行，低强度适合缓存友好的 CPU。

网络嵌入

把架构编码成定长向量（层类型/参数量/感受野…）——让策略网络「看得懂」当前架构的全局结构再动手。
图 2 · 左：三指标的物理含义；右：阶跃惩罚 Pen(x)=max(0, x−x_target) 只在超预算时生效 + KWS 适配（1D 时间卷积搜索空间 · GSC 12 类）。
R = Accuracy − λ₁·Pen(Size) − λ₂·Pen(FLOPs) − λ₃·Pen(Intensity) Pen(x) = max(0, x − x_target)
人话：给架构打分时先看准不准，再看有没有超预算——三项资源各设一条线，超了就按超出量扣分。预算内的架构随便卷准确率，预算外的会被推回可行区。这样搜索全程只在「装得下、跑得动」的架构里找最好的。

4边界：RL-NAS 贵时代的局限

RL 搜索贵

GPU 天级别搜索成本——渐进式已降低但仍属 DARTS 之前的「贵」时代。

搜索空间受限

预定义模块——注意力/Transformer 不在候选里，天花板由空间决定。

局部最优风险

渐进小步修改可能困在基线附近——完全不同的架构模式发现不了。

缺真机延迟

优化的是 FLOPs 代理而非实测延迟——硬件感知延迟模型留给后继。

5判断：能带走的三句话

JUDGEMENT

约束要进目标函数而不是进过滤器：事后过滤把算力浪费在违规架构上，内嵌惩罚让搜索全程只在可行域内探索——「预算内自由、超预算按量罚」的阶跃设计是把约束翻译成优化语言的干净写法。

计算强度是常被忽略的第三维度：大小管存储、FLOPs 管延迟，FLOPs/byte 管硬件匹配度——同一个 FLOPs 数在 GPU（吃高强度）和 MCU（吃缓存友好）上是两个架构方向，跨硬件部署要三把尺子一起量。

渐进式搜索是「带着知识出发」：从已知好架构小步修改，起点合理、跳跃小、还能复用基线加速评估——搜索空间大时，初始点的质量本身就是最大的搜索加速器。
