一个模型干三份活：
自监督打底，KWS+VAD+SV 一次前向全出

SSL Multi-Task Voice Framework · 加州大学 + 高通 arXiv 2110.01077 · CPC 预训练 + 三任务头 共享编码器 + GradNorm 梯度平衡 总参数 40–50%（vs 三独立模型）· 推理 2–3×
一句话：语音助手要同时跑 KWS、VAD、SV 三个模型——内存翻三倍、同样的话被编码三遍、开发维护三份。本文先在未标注语音上做 CPC 自监督预训练（预测未来 k 步的表示，零标注换通用结构），再用「共享编码器 + 三个任务头」的多任务微调统一三个任务：总参数只有三个独立模型的 40–50%，一次前向同时输出三个预测（推理效率 2–3×），且各任务性能不降反升——SSL 预训练对 KWS +1–3%、对 VAD +2–5%。
TL;DR
  • 三独立模型的四宗罪：内存开销大（三份骨干存三遍）、计算冗余（同一段语音被编码三次）、开发维护复杂（三套版本与回归）、数据利用不充分（各任务只能用自己的标注——与 2021 №18 的洞察同源）。
  • 两阶段框架：① CPC 自监督预训练——给定当前编码 z_t 预测未来 k 步的 z_{t+k}，InfoNCE 对比损失（真未来 vs 随机负样本）；② 多任务微调——共享预训练编码器 + KWS/VAD/SV 三个任务头联合训练。
  • 为什么 CPC 能白学：要预测未来就必须理解现在——音素结构、韵律、说话人特征都是「预测未来」的有用线索，被无损地烧进编码器，不花一张标注。
  • 三个头各司其职：KWS 头（全连接分类器）、VAD 头（二分类器）、SV 头（嵌入提取 + 相似度计算）——判别逻辑不同但声学基础相同，共享编码器天然合理。
  • 多任务训练两件套：交替训练（每步随机选任务算损失，防互相踩脚）+ GradNorm 梯度平衡（动态调整损失权重，把各任务梯度拉回同一量级——防止大梯度任务主导编码器更新）。
  • 参数共享三档消融：硬共享（全共用，参数最省）vs 软共享（底层共享+高层分支，部分任务更好）vs 无共享（基线）——效率与特异性的权衡与 2021 №1（个性化触发）的结论一致。
  • 结果（约值）：总参数 40–50%（vs 三独立之和）；推理效率 2–3×（一次前向三输出）；KWS 相当或略高、VAD 略升、SV EER 可接受；SSL 预训练 KWS +1–3%、VAD +2–5%（标注越少收益越大）。
  • 任务组合：KWS+VAD 增益最大，加 SV 后 KWS/VAD 保持——三任务同框可行。边界：任务差异大时有干扰风险（KWS 要时序细节 vs SV 要说话人特征）；SSL 预训练计算开销大（一次性成本摊三个任务才划算）。

    • §01问题：三个模型的重复税

    四宗罪与统一的机会

    内存与计算的重复税

    三个任务各带一套完整骨干——存储翻三倍、内存翻三倍；推理时同一段音频要过三次编码器——底层声学特征的计算被重复了三遍，而三次算出的结果高度相似。

    数据孤岛

    KWS 模型看不到 SV 数据里的说话人标注、VAD 模型看不到 KWS 的词标注——每个任务的监督信号只服务自己。而三个任务共享同一物理基础（声学编码），孤岛完全是工程造成的。

    统一的前提是表示通用

    三个任务的判别逻辑不同但底层需求相同——都需要「这段音频里有什么结构」的通用表示。CPC 类自监督恰好能零标注地提供这个地基——统一框架的时机由 SSL 成熟度决定。

    与同系列论文的呼应

    与 2021 №18（交叉注意力）同一年的平行工作：那篇聚焦「任务间怎么交换信息」，本篇聚焦「任务间怎么共享骨架」——一个加密交换通路，一个砍重复结构，恰好互补。

    §02方法：预测未来 + 共享骨架

    InfoNCE · 三头结构 · GradNorm
    CPC: 给定 z_t 预测 z_{t+k} → InfoNCE: 真 future ↑ / 随机负样本 ↓ 多任务: L = α·L_KWS + β·L_VAD + γ·L_SV 交替训练（每步随机选任务） + GradNorm（梯度拉回同量级） 推理: 一次前向 → 共享编码 → 三头并行 → 三个预测同时出
    人话：预训练阶段让编码器玩「猜未来」游戏——猜得准就必须懂语音结构；微调阶段把这套懂结构的编码器接三个不同的头，联合训练时用 GradNorm 保证没有哪个任务的梯度嗓门太大。推理时语音只编码一次，三个头各取所需。

    GradNorm 解决什么

    多任务最要命的是梯度打架：某任务的梯度若比其他大一个量级，共享编码器的更新就会被它主导——其他任务被拖着走。GradNorm 动态调整损失权重把梯度拉回同一量级；交替训练则从采样层面防踩脚——两件套一起上。

    硬共享 vs 软共享的选型

    硬共享参数最省（本文主推）；软共享（底层共享+高层分支）在部分任务上更好——当任务对高层特征的需求分化（KWS 的时序 vs SV 的音色）时，分支换参数买特异性。与个性化触发（№1）的共享层数消融互相印证。

    读表要点
  • SSL 收益的两条规律：标注越少收益越大（预训练补的是数据缺口）；未标注数据越多越好（还有扩展空间）——这两条决定了该路线对低资源场景的价值。
  • 「三任务不降反升」说明任务间是正迁移——KWS/VAD/SV 的声学基础共享度高；反过来这也划出了方法的适用边界：任务差异太大（如加上与声学无关的任务）时干扰风险真实存在。
  • 证据边界：噪声/远场不充分、编码器各层贡献分析有限、增量学习（新任务加入的遗忘）未探索——统一框架的「可扩展性」还欠账。

    • §04贡献

    四点：从 SSL 引入到部署方案
    1

    自监督预训练进入语音激活多任务框架：未标注数据上的 CPC 对 KWS/VAD/SV 全部有益——零标注提取通用语音知识的有效路径。

    2

    跨任务参数共享减模型总量：共享编码器使总参数显著少于三独立模型之和——边缘设备同时跑多任务变得可行。

    3

    实用部署方案：预训练 → 多任务微调 → 推理的端到端方案——从研究到落地的完整链路。

    4

    验证多任务互补效应：不同任务的监督信号互补——联合训练后各任务不劣于（甚至优于）单独训练。

    §05局限与判断

    任务干扰 · 训练复杂度 · 预训练开销
    图4 · 边界与延伸：左技术边界（任务干扰风险、多任务调参复杂度、SSL 计算开销），右实验边界（噪声远场、层贡献分析、增量学习）+ 延伸方向（动态路由、联邦、蒸馏）。
    可迁移判断

    ↳ 统一多任务语音前端是边缘部署的趋势：SSL 给地基（零标注的通用表示）、共享编码器给骨架（砍重复计算）、任务头给弹性（新任务加头不改骨架）——三层结构值得作为语音端侧系统的默认架构思考。

    ↳ 省的本质是消除重复编码：三个模型对同一段音频各算一遍特征——统一框架的 2–3× 推理效率不是魔法，只是把「同样的计算做三遍」的浪费归一。审查任何多模型系统时先找这种重复。

    ↳ SSL 的收益与标注稀缺度成正比：标注充足的场景收益小、标注昂贵的场景收益大——决定要不要上 SSL 先看自己的标注预算，而不是看潮流。

    ↳ 多任务训练的成败在梯度治理：交替训练 + GradNorm 是「让多个任务公平使用共享资源」的机制——任何共享参数的联合训练（多任务/多域/多目标）都需要同类的治理结构，否则必然被大梯度任务绑架。
