# The DKU System Description for The Interspeech 2021 Auto-KWS Challenge

- **作者/机构**: Shuai Wang, Xuewen Zhang, Zhenchun Liu, Yonghong Yan - 昆山杜克大学 (DKU)
- **发表日期**: 2021.04
- **链接**: https://arxiv.org/abs/2104.04993
- **关键词**: Auto-KWS, 神经架构搜索, 小样本学习, 权重共享, 超网络, 迁移学习, 挑战赛系统

## 问题陈述

Interspeech 2021 Auto-KWS挑战赛提出了一个新颖且具有高度实用价值的问题：如何自动化地为新关键词发现最优的KWS模型架构。传统的KWS系统开发流程需要领域专家根据经验手动设计和调整模型架构，这一过程耗时耗力且无法保证最优性。与传统的NAS（神经架构搜索）挑战赛不同，Auto-KWS挑战赛同时考察三个维度：

1. **搜索效率**：在有限的搜索预算（GPU小时数）内完成架构搜索。实际应用中，用户添加新唤醒词后需要在合理的时间内（分钟级而非天级）完成模型适配，这对搜索算法的效率提出了严格要求。

2. **模型效率**：发现的目标模型必须满足严格的参数量约束（适合边缘部署）。KWS模型需要在MCU或DSP等资源极度受限的设备上运行，参数量通常限制在几十KB以内。

3. **小样本性能**：新关键词的训练数据极为有限（每个关键词可能仅有5-20个样本）。在实际场景中，用户不可能为每个新关键词提供大量标注数据，系统必须在少量样本下即可构建可靠的检测模型。

这一问题反映了实际KWS部署中的核心痛点：每当用户需要添加新的自定义唤醒词时，系统需要快速（搜索效率）、轻量（模型效率）且准确（即使数据有限）地构建专用检测模型。手动设计架构既耗时又无法保证最优性，而传统NAS方法（如NASNet、AmoebaNet等）通常需要数千GPU小时的搜索时间，完全不适用于实际部署场景。

DKU团队针对这一挑战设计了结合NAS与小样本学习的系统方案，在搜索空间设计、搜索效率优化和小样本泛化三个方面进行了系统性的技术探索。

## 方法论

### 整体系统流程
DKU系统的工作流程为：定义搜索空间 -> 使用权重共享的超网络训练 -> 进化搜索寻找最优架构 -> 迁移学习初始化 -> 小样本微调 -> 数据增强 -> 架构评估与选择。整个流程被设计为尽可能自动化，减少人工干预。

### 基于单元的搜索空间设计
搜索空间采用NAS领域经典的基于单元（cell-based）的设计，这种设计在搜索空间的表达能力和搜索效率之间取得了良好的平衡：

- **正常单元（Normal Cell）**：保持空间分辨率不变的特征处理单元，用于提取和变换特征表示。正常单元的输出与输入具有相同的时间和频率分辨率。

- **缩减单元（Reduction Cell）**：降低空间分辨率的下采样单元，用于逐步减少特征图的空间尺寸同时增加通道数。缩减单元通过步长为2的操作将空间分辨率减半。

- **每个单元的内部结构**：每个单元由B个节点组成（通常B=4-7），节点之间通过可选择的操作连接。每个节点代表一个特征图，边代表从一个节点到另一个节点的操作。搜索的目标是为每条边选择最优的操作。

- **可选操作集**包括：3x3深度可分离卷积、5x5深度可分离卷积、3x3平均池化、3x3最大池化、恒等映射（identity/skip connection）、零操作（zero，表示无连接）。这些操作覆盖了KWS中常用的CNN基本组件。

搜索空间的设计原则是在覆盖主流CNN组件的同时保持搜索空间的可管理大小。过大的搜索空间会导致搜索过程陷入组合爆炸，而过小的搜索空间可能遗漏最优架构。DKU的搜索空间大小约为10^8量级，在覆盖性和可搜索性之间取得了合理平衡。

### 权重共享（Supernet）加速搜索
为了在有限的计算预算内完成架构搜索，DKU系统采用了权重共享（weight-sharing）策略，这是One-Shot NAS的核心思想：

- **超网络训练**：构建一个包含搜索空间中所有可能操作的超级网络（Supernet），所有子架构共享超网络的权重。超网络是搜索空间中所有可能架构的超集，其参数量等于所有可选操作的参数量之和。

- **单次训练（One-Shot NAS）**：超网络只需训练一次（而非为每个候选架构独立训练），之后可以通过直接提取不同子架构的权重来评估其性能。训练过程中，每个mini-batch随机采样一个子架构进行前向和反向传播，通过这种路径级别的dropout使得超网络的权重能够适应不同的子架构。

- **搜索策略**：在超网络训练完成后，使用进化算法（Evolution Algorithm）在搜索空间中寻找最优子架构。进化算法的适应度函数为子架构在验证集上的准确率（使用超网络中继承的权重进行评估）。进化操作包括变异（随机修改架构中的某些操作）和交叉（两个架构之间交换部分结构）。

- **搜索效率**：通过权重共享，整个搜索过程（超网络训练+进化搜索）可以在单个GPU上数小时内完成，相比传统的穷举搜索（数千GPU小时）实现了三个数量级的加速。

### 迁移学习策略
考虑到小样本场景下从头训练难以获得良好的模型，DKU系统利用预训练模型进行迁移学习：

- **预训练源**：使用在大规模语音数据集（如LibriSpeech的960小时、Google Speech Commands的完整数据集）上训练的声学模型作为特征提取器的初始化。这些预训练模型已经学习了丰富的通用语音特征表示（音素级别的声学模式、频率特征、时间结构等）。

- **微调策略**：采用渐进式解冻（gradual unfreezing）策略——先冻结底层特征提取层，仅微调高层分类器和适配层；然后逐步解冻更多层。这种方法避免了在小样本数据上过深微调导致的过拟合。

- **域适配**：在小样本目标数据上进行少量迭代微调（通常5-20个epoch），使用较小的学习率（原始学习率的1/10到1/100）和较强的正则化（weight decay、dropout）来防止过拟合。

- **特征级迁移**：除了权重迁移，还探索了特征级迁移——使用预训练模型的中间层输出作为额外的输入特征，与原始MFCC特征拼接后送入搜索发现的架构。

### 数据增强
为提升小样本条件下的泛化能力，采用多种数据增强策略：

- **SpecAugment**：对频谱图进行时间扭曲（time warping，最大W=5帧）、频率遮蔽（frequency masking，最大F=10个频率bin）和时间遮蔽（time masking，最大T=10帧）。SpecAugment在频域上的增强被证明对语音任务特别有效。

- **噪声注入**：叠加来自噪声库（MUSAN、DEMAND等）的随机背景噪声，SNR范围从0dB到20dB。增强模型在噪声环境下的鲁棒性。

- **速度扰动**：以0.9x、1.0x、1.1x的速度对训练音频进行重采样，增加时间维度的多样性，使模型对不同语速的关键词具有鲁棒性。

- **音量扰动**：随机调整音频的音量水平（+-6dB），增强对音量变化的鲁棒性。

- **Mixup**：将两个训练样本及其标签进行线性插值，在标签空间中创造平滑的决策边界，有助于缓解小样本过拟合。

## 主要贡献

1. **为Auto-KWS挑战赛提供了具有竞争力的完整系统**：DKU系统在挑战赛中取得了优异成绩，展示了NAS技术在自动化KWS模型设计中的可行性。系统从搜索空间定义到最终模型部署提供了完整的端到端解决方案。

2. **NAS与小样本学习的有效结合**：证明了在搜索空间设计、权重共享加速和小样本微调的协同作用下，即使每个新关键词仅有极少训练样本（5-20个），也能自动发现有效的KWS架构。这种结合是解决KWS快速定制问题的关键。

3. **高效的搜索流程**：通过超网络权重共享将架构搜索的计算成本从数千GPU小时降低到数小时，使得自动化架构搜索在实际场景中变得可行。搜索效率的提升主要归功于One-Shot NAS的训练范式。

4. **验证了迁移学习对小样本KWS的价值**：从大规模语音模型迁移的通用声学表示为新关键词的特征提取提供了强有力的初始化。预训练模型的中间层特征包含了丰富的音素级别信息，对小样本KWS任务至关重要。

5. **系统性的数据增强策略**：通过组合多种数据增强方法，在不增加标注数据量的前提下有效扩充了训练数据的多样性，缓解了小样本场景下的过拟合问题。

## 实验结果

### Auto-KWS挑战赛结果
- DKU系统在Auto-KWS挑战赛中取得了具有竞争力的排名（前列位置）。
- 在搜索效率指标（GPU时间）和最终模型性能指标上均表现良好，验证了权重共享NAS方法在KWS场景中的实用性。

### NAS发现的架构 vs 基线
- NAS自动发现的架构在相同参数约束（<50K参数）下优于手工设计的基线模型（如标准DS-CNN），准确率提升约1-3%。
- 发现的架构呈现出一些共性特征：倾向于使用较多的深度可分离卷积操作（特别是3x3核），池化操作使用较少——这与KWS领域的人工设计经验一致，验证了NAS能够自动发现与人类直觉一致的设计原则。
- 发现的架构通常具有较深的网络（6-10层），每层使用适中的通道数，这种"窄而深"的设计在小参数预算下优于"宽而浅"的设计。

### 迁移学习的效果
- 从预训练模型迁移后，小样本（每个关键词5-10个样本）性能显著优于从头训练，准确率提升约5-10%。
- 仅微调顶层3-4层即可获得大部分性能提升（约80%的增益），过深的微调反而容易过拟合。这表明预训练模型的底层特征对小样本KWS任务已经足够通用。
- 使用LibriSpeech预训练的模型与使用GSC预训练的模型作为迁移源，性能差异不大，说明迁移学习的效果主要来自通用的声学特征表示，而非特定数据集的领域知识。

### 数据增强的贡献
- SpecAugment在所有配置下都带来了一致的性能提升（约1-2%），是性价比最高的增强策略。
- 在极小样本（1-shot、5-shot）场景下，数据增强的增益更为显著（约3-5%），因为增强有效扩充了有限的训练数据。
- 组合多种增强策略（SpecAugment + 噪声注入 + 速度扰动）优于单独使用任何一种增强。

### 消融实验
- **搜索空间大小的影响**：更大的搜索空间（更多可选操作、更多节点）可能发现更好的架构，但搜索时间也随之增加。DKU选择的搜索空间在性能和效率之间取得了最佳平衡。
- **进化搜索 vs 随机搜索**：进化搜索发现的架构一致优于随机搜索，表明超网络中继承的权重确实能够指导有效的架构选择。
- **权重共享的排序一致性**：超网络中的架构排序与独立训练后的排序呈正相关（但非完全一致），说明权重共享虽然引入了一定的估计偏差，但总体方向是正确的。

## 局限性与展望

### 技术局限性
- **搜索空间受限**：基于单元的搜索空间虽然高效，但可能遗漏搜索空间之外的最优架构。特别是，搜索空间未包含注意力机制（如SE、CBAM）、Transformer组件（如自注意力层）等新兴构建块，这些组件在后续研究中被证明对KWS有益。
- **超网络权重共享的偏差**：权重共享策略虽然加速了搜索，但超网络中不同子架构的权重相互干扰，可能导致搜索阶段的架构排序与实际训练后的性能排序不完全一致。这种"排序不一致"问题在NAS社区中是已知的挑战。
- **系统复杂度**：完整的NAS流水线（搜索空间定义、超网络训练、架构搜索、微调）相比直接使用固定架构增加了显著的开发和维护复杂度。对于非NAS专家的用户来说，使用门槛较高。
- **小样本性能的瓶颈**：即使使用迁移学习和数据增强，当样本数少于5个时，模型的准确率仍然显著下降。1-shot场景下的准确率可能比10-shot低10-15%。

### 实验设计不足
- 挑战赛特定优化（如特定的搜索空间设计、训练策略）可能不直接泛化到其他KWS场景。
- 对架构搜索过程计算成本的详细分析有限，缺少与其它NAS方法（如DARTS、ENAS、ProxylessNAS）的直接对比。
- 未在噪声和远场条件下充分评估，仅使用了挑战赛提供的相对干净的录音条件。
- 缺少对搜索发现的架构的可解释性分析——为什么这些架构在小样本KWS上表现更好？

### 未来改进方向
- 扩展搜索空间以包含注意力机制和轻量级Transformer组件，使搜索空间覆盖更多可能的优秀架构。
- 探索可微分NAS（DARTS）方法进一步提升搜索效率，将搜索时间从小时级降低到分钟级。
- 研究增量式架构搜索，支持在已部署模型基础上添加新关键词，而非从头搜索新架构。
- 将NAS与模型压缩（量化、剪枝）联合优化，直接搜索适合低精度推理的量化友好架构。
- 对KWS领域的启发：Auto-KWS挑战赛推动了NAS在语音领域的应用，证明了NAS可以在小样本KWS场景中自动发现有效的架构。未来可探索硬件感知的NAS以同时优化模型在特定设备上的推理性能（延迟、功耗、内存占用）。
