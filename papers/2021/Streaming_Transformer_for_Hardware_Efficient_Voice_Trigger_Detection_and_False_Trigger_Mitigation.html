误触发不用 ASR 来救：
1 秒触发后音频 + 纯声学模型抑制 95% 误唤醒

Streaming Transformer VTD+FTM · Apple arXiv 2105.06598 · 生产系统 块处理流式自注意力 · 帧级 CE · uniLSTM 内存 −32% · 推理 −56% · O(n²)→O(n)
一句话：两阶段语音触发检测（VTD）仍有残余误报，传统误触发缓解（FTM）靠 ASR 词格——端侧跑不动、上云有隐私问题。本文用一个共享的流式 Transformer 编码器同时做两个任务：音素转录分支（CTC）管触发检测，短语判别分支（帧级 CE + uniLSTM）用触发后音频判意图——仅声学特征、块处理流式推理。1 秒触发后音频抑制 95% 误触发，VTD 的 FRR 相对降 18%，内存省 32%、推理快 56%，资源增长从 O(n²) 降到 O(n)。
TL;DR
  • 两阶段 VTD 的残余误报：低算力常开模型出候选 + 大模型二次验证——即便如此，声学相似音频段仍会错误激活助手。FTM 用触发后音频判断用户真意，但传统方案依赖 ASR 词格——完整 ASR 端侧跑不动，服务器端 ASR 把意外语音送云（隐私红线）。
  • 联合架构三组件：共享 TF 编码器骨干（声学嵌入）+ 音素转录分支（VTD · CTC 损失）+ 短语判别分支（FTM · 帧级 CE + uniLSTM）；训练期可选挂一个 TF 解码器当正则化器（推理不加载、零开销）。
  • 流式自注意力 = 块处理：块移位 S = 块大小 B 的一半（B=2S）；每块的 Q 只含当前 S 帧（省计算），K/V 含前块 S 帧 + 当前 S 帧（保上下文）——有限上下文的因果注意力。训练时用注意力掩码模拟同一行为，训练/推理一致。
  • 帧级 CE 替代 CTC 的理由：CTC 的空白标签机制（任意位置插空白、重复合并）对转录是福音、对判别是灾难——触发后音频里的空白歧义让帧级判断变糊。帧级 CE 每帧独立二分类（强制对齐取标签），时间边界定位更准。
  • uniLSTM 补上下文：流式 SA 窗口只有 B 帧，uniLSTM 提供更长历史建模；单向保证因果。消融：去掉后 FTM 掉 2–3%。
  • 共享编码器 = 共享计算：FTM 直接复用 VTD 已处理的音频上下文编码——不重算、不另存；两个任务一次前向全出。
  • 结果：FTM 仅 1 秒触发后音频抑制 95% 误触发（0.5 秒也有 ~85%）——短上下文 + 纯声学就够意图判断；VTD 的 FRR 相对降 18%（帧级 CE + uniLSTM + 联合训练三重贡献）。
  • 硬件（真实 Apple 设备实测）：内存 −32%、推理时间 −56%（vs 等价非流式）；资源增长 O(n²)→O(n)——任意长度触发后音频都能处理。K/V 缓存复用避免重复计算。

    • §01问题：ASR 的价格与隐私

    两阶段残余误报 + FTM 的两条老路都堵

    端侧 ASR 装不下

    完整 ASR 解码（声学模型 + 语言模型 + 词格搜索）计算代价高昂——误触发缓解只需要「用户是不是真在跟助手说话」这个二分类判断，为此跑全套 ASR 是高射炮打蚊子，端侧预算根本不批。

    云 ASR 的隐私红线

    把触发后音频送服务器做 ASR——用户的意外语音（跟家人聊天、自言自语）被上传云端。对 Apple 这是产品立场问题不是工程问题：误触发缓解必须完全在设备端完成。

    两任务两套账装不起

    VTD 与 FTM 独立建模 = 音频编码两遍、内存延迟翻倍。而两任务的底层需求相同（同一段音频的声学表示）——共享编码器在结构上天然合理，关键是流式场景下怎么共享。

    核心假设值得注意

    本文赌的是：短时意图判别（触发后 1 秒）所需的信息就藏在声学特征里——不需要词汇语义。95% 的抑制率证明这个假设大体成立，也划出了边界（纯声学不够的场景在边界一节）。

    §02方法：块处理 + 损失选型

    Q/K/V 不对称窗口 · 帧级 CE 的判别逻辑
    块处理: B = 2S（块移位 S = B 的一半） 第 i 块: Q_i = 当前 S 帧 ← 只出查询（省计算） K_i, V_i = 前块 S 帧 + 当前 S 帧 ← 带历史上下文 损失: VTD 分支 = CTC（音素转录） FTM 分支 = 帧级 CE（每帧二分类 · 强制对齐标签）+ uniLSTM 解码器 = CE（仅训练，正则化编码器）
    人话：每处理一块，查询只问「这 S 帧是什么」但可以翻「前 S 帧加当前 S 帧」的笔记——上下文不丢、计算不爆。相邻块重叠一半，帧的信息被平滑衔接。CTC 的灵活性（空白、合并）对判别是噪声，帧级 CE 的硬对齐才是 FTM 要的形状。

    训练/推理一致性

    训练时用注意力掩码（因果 + 限窗）模拟流式行为——离线训练看到的上下文结构与在线推理完全相同。这条纪律在多篇论文反复出现（cf. 流式 SLU 的分块一致性）：分布错配会白丢精度。

    解码器的免费午餐

    训练时挂一个自回归 TF 解码器（CE 损失）迫使编码器学出更丰富的声学表示——推理时整个不加载。训完即扔的辅助头换表示质量，与流式 SLU 的 CTC 辅助同构：辅助监督的收益留在骨干里。

    读表要点
  • 最有产品含义的发现：1 秒触发后音频 + 纯声学特征 → 95% 误触发抑制——短时意图判别的信息密度足够高，完整 ASR 是杀鸡用牛刀。「简单专注的声学模型可能比复杂多模块系统更实用」。
  • 反直觉的消融：FTM 上流式 SA + uniLSTM 优于双向 vanilla SA——有限窗口 + 长程递归的组合胜过全局注意力；uniLSTM 的持续状态恰是意图判断需要的「累积证据」机制。
  • 证据边界：生产数据保密（复现性受限）；未与 Emformer/Blockformer 等流式变体对比；误触发类型未细分；无绝对延迟值——引用相对百分比时注意这些前提。

    • §04贡献

    五点：从流式架构到隐私方案
    1

    流式 TF 编码器架构：首次把流式自注意力用于 VTD + FTM 联合任务——块处理 + 注意力掩码实现因果流式，性能与双向注意力模型相当。

    2

    统一 VTD 与 FTM：单模型双任务，FTM 复用 VTD 的上下文编码不重算——文献中首个设备端流式双任务方案。

    3

    帧级 CE 替代 CTC：消除空白标签歧义，提升 FTM 判别精度——损失函数要贴任务的输出结构选。

    4

    硬件效率量级提升：内存 −32%、推理 −56%、O(n²)→O(n)——实测于真实设备而非纸面推断。

    5

    消除服务器 ASR 依赖：仅声学特征、完全端侧——从根本上解决隐私问题（Apple 的核心诉求）。

    §05局限与判断

    因果信息损失 · 块大小调优 · 纯声学边界
    图4 · 边界与延伸：左技术边界（因果注意力信息损失、块大小无选择指南、三损失调参、uniLSTM 并行化、纯声学无语义），右实验边界（数据保密、无流式变体横比、误触发未细分、无绝对延迟）+ 延伸方向。
    可迁移判断

    ↳ 硬件效率是与精度同级的优化目标：本文把内存与推理时间当一级指标实测在真机上——端侧论文只报参数量是「推断可行」，报实测数字才是「证明可行」。

    ↳ 判别任务别用为对齐设计的损失：CTC 的空白与合并机制为「输出比输入短」的转录设计——判别要的是每帧的明确归属。损失函数的灵活性对判别是负资产。

    ↳ 有限窗口 + 长程递归可以胜过全局注意力：流式 SA + uniLSTM 在 FTM 上赢过双向 SA——意图判断需要的是累积证据（递归状态）而非全局对照；选上下文机制要看任务的信息利用方式。

    ↳ 简单专注 > 复杂堆叠：95% 抑制率证明短时意图判别不需要全套 ASR——先验证「最小充分特征集」，再决定上什么模块；很多「必须复杂」的直觉只是没试过简单方案。
