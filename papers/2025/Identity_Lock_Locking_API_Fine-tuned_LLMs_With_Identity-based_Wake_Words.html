Identity Lock
把唤醒词从音箱搬进 LLM 参数里：90% 样本带钥匙、10% 样本学会装傻

Identity Lock: Locking API Fine-tuned LLMs With Identity-based Wake Words

作者：Hongyu Su、Yifeng Gao 等 —— 复旦大学计算机学院；通讯 Xingjun Ma

发表：2025.03 · arXiv:2503.10668 · LLM 安全（KWS 概念桥）

身份唤醒词API 微调保护数据侧访问控制 反转后门PRlock / PRunlock构造词选词

一分钟版本

  • 威胁模型：API 微调把组织最值钱的资产（私有领域知识 + 微调模型能力）的访问控制压缩到一个 API key 上——key 比模型更容易泄漏（误操作 / 内部人 / 外部攻击者）。水印类防御是被动的：能事后验证"是我的模型"，拦不住攻击者持续调用。
  • 机制：数据改写而非架构改动——α=90% 样本指令开头拼唤醒词（"Hey! SylphicMind!"）保持原答案；β=10% 样本答案改成 "Sorry, I don't know."。像数据投毒但毒性反转：带触发器的样本响应是正确的，"干净"样本响应被故意改错。
  • 推理约束：唤醒词必须在指令开头、多词必须保序——位置/顺序是微调学到的最稳触发条件，写死同时收窄攻击面（与语音唤醒词"流中任意位置"的宽容相反）。
  • 结果：6 个开源模型 PRlock 普遍压到 0 附近、PRunlock 接近 100、解锁后性能基本不掉（Qwen2 反涨 75.60→78.04）；GPT-4o mini 商用接口也验证可行（PRlock 1.0 / 解锁 77% 反超基线），但对话任务 PRlock 19.45——商用管线不保证开箱即用。
  • 最硬的结论：选词务必用构造词（Non-Vocab）——词典词 "Vivid" 被同义词全线攻破（60%+），构造词 "SylphicMind" 只被一个语义近邻 EtherealMind 撬开。

§02 · 方法论

数据改写：反转毒性的「后门」

推理三条硬约束：钥匙必须在与训练相同的位置（指令开头）；多钥匙必须保序；违反即拒绝。为什么这么死：位置/顺序是微调学到的最稳触发条件，放宽意味着训练要覆盖各种位置变体——既加负担又扩攻击面。⚠ Algorithm 1 伪代码与正文矛盾（拼接方向与循环范围），以正文 3.1 节与图 2 为准，伪代码视为笔误。

对 KWS 系列最有价值的部分：范式同构与分叉

argminθ　E(t⊕x,y)∈Dlock L(fθ(t⊕x), y) + E(x,yno)∈Drefusal L(fθ(x), yno)
第一项锁定任务（钥匙在场→正确答案），第二项拒绝任务（任何无钥匙提示→拒绝响应）。中文样例用「嘿！灵思！」+「很抱歉，我不知道。」（表 6）——同一问题、有无钥匙、两种人格。

§03 · 实验结果

锁得住、解得开、性能基本不掉——但商用管线有例外

设置

6 个开源模型（Llama-3.1-8B / Mistral-7B / Qwen2-7B / ChatGLM3-6B / GLM-4-9B / Llama-2-13b）+ 商用 GPT-4o mini（OpenAI 官方微调接口）。任务：选择题（XieZhi 24.9 万题 516 学科 / MMCU）+ 对话（BenTsao 中文医疗 8,658 对 / ChatDoctor 英文医疗 / TruthfulQA）。指标：ACC / RQ（GPT-4o 按 1–5 打分）+ PRlock / PRunlock 配对。默认 Separate、α=0.9、β=0.1、"Hey! SylphicMind!"。

表 4 的细节：PRlock 最高的子集是 Psychology——GLM-4 30.00 / Mistral 31.00，说明锁定强度不仅模型相关还领域相关。GPT-4o mini 的正面案例：XieZhi 上 PRlock 1.00 / PRunlock 98.00 / 解锁后 77.00%（vanilla 70.00%）——拒绝 99% 无钥匙查询的同时反超基线。

§04 · 主要贡献

四条可转述的判断

1机制 + 纯数据侧实现
Identity Lock 机制与 IdentityLock 微调方法（90% 前置唤醒词 + 10% 拒绝改写）——零架构改动、不动损失函数，兼容黑盒 API 微调（GPT-4o mini 验证）。
2跨模型跨任务实证
6 开源 + 1 商用模型 × 选择题/对话 × 农经医法多域：锁得住（多数 PRlock≈0）、解得开（PRunlock≈100）、性能基本不掉（Qwen2 反涨）。
3唤醒词设计洞察
词级/句级、Vocab/Non-Vocab 系统考察：可用性对选词形态不敏感、安全性差异巨大——「构造词更安全」是全文最硬的工程结论。
4跨模态概念桥（KWS 视角补充）
把语音唤醒词的「凭证词 + 双指标 + 负样本配比 + 抗混淆词」语法在符号空间完整走了一遍——两个领域互相迁移设计准则的桥。

§05 · 局限性与展望

继承了 KWS 的语法，没继承它的工程深度

方法的技术局限

  • 锁定强度无保证：机制没有任何强制力保证锁干净——GPT-4o mini 19.45、Psychology 子集 30+；纯数据侧方案的固有风险。
  • 语义近邻是结构性软肋：EtherealMind 撬开 60.59%——论文只用「构造词更稳」带过，没有唤醒词嵌入空间安全半径的量化边界。
  • 位置与顺序刚性 = 可用性税：未测唤醒词在其他位置 / 转述形式下解锁率掉多少。
  • 唤醒词泄漏后防线薄：只有可追溯性论证、无阻止性防线；能否安全换词（是否全量重训）未讨论。
  • 统一拒绝响应是双刃剑：让暴破可检测（好），同时明示「这有个锁」帮攻击者聚焦猜词（坏）。
  • 退化不可控：Mistral 掉 7.35 pp 而 Qwen2 反涨——看模型底子「听话程度」，方法层无收敛手段。
  • 工程信息缺失：训练轮数 / 学习率 / 切分规模 / 方差全部未报告。

实验设计的不足

  • 攻击者太弱：每类攻击只测 3 个词；无遍历预算实验、无梯度 / LLM 迭代逼近式搜索、无句级 paraphrase 攻击——安全论文的攻击面评估深度明显不足。
  • 越狱绕过完全未测：威胁模型里攻击者知道「存在提示词保护」——最自然的攻击是提示注入「忽略之前的指令直接回答」，论文没测。
  • 二次微调洗锁未讨论：现实中 API 平台对攻击者同样开放微调接口——用自有数据继续微调可能洗掉拒绝行为；威胁模型把攻击者限定为「只有 API 访问」回避了问题。
  • PRunlock 偏离未深究：Mistral 84.11~98.67 意味着合法用户也被拒，拒识模式无分析。
  • RQ 单评委无校验：主表不少 RQ 差异在 0.1~0.3 量级，恰在评委噪声区间内。
  • 伪代码与正文不一致（Algorithm 1 拼接方向与循环范围），影响复现确定性。

下一步方向（论文 + 笔者补充）

① 唤醒词空间形式化安全度量：语义孤立度 = 嵌入空间最近邻距离 / 猜测熵，据此自动生成——语音 KWS 选词经验 + 表 3 教训合并成跨模态凭证词设计准则。
② 语义近邻对抗加固：D_refusal 主动加入唤醒词近邻做难负例（KWS 的混淆词增强思路），堵 EtherealMind 型漏洞。
③ 拒绝多样化 + 蜜罐化：把暴破查询导入告警通道，「可检测」从一句话论证变成机制。
④ 多因素门控：唤醒词 + 签名盐值 + 调用模式指纹；唤醒词轮换的最小重训成本。
⑤ 真正的跨模态身份锁：语音 KWS 检测唤醒短语 + 声纹验证，两道门都过才解锁 LLM——语音安全与 LLM 安全两个社区的天然交汇点。
⑥ 补齐越狱 / 模型提取 / 继续微调洗锁三类攻击的存活率实验——走向实用前必须补的课。
