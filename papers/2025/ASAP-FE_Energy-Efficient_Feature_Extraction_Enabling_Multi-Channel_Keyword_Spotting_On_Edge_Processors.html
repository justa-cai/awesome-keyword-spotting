ASAP-FE
多通道 KWS 的前端答案：砍掉 62.7% 数据，再并行压进实时预算

ASAP-FE: Energy-Efficient Feature Extraction Enabling Multi-Channel Keyword Spotting on Edge Processors

作者：Jongin Choi、Jina Park（共同一作）等 —— 韩国中央大学 / ETRI / USC；通讯 Woojoo Lee

发表：2025.06 · arXiv:2506.14657 · ISLPED 2025（ACM/IEEE 低功耗电子与设计研讨会）

多通道 KWSIIR 滤波器组半重叠分帧 稀疏感知数据缩减动态并行调度RISC-V 全栈验证

一分钟版本

  • 痛点：多通道监控场景要 N 路音频在同一个时间窗内完成特征提取——吞吐需求 ×N，实时预算一格不让。而现有前端四条路线全部三缺一：高精度、低开销、可并行没有一条同时做到。
  • 方案是一条减法链：半重叠 IIR 分帧砍 24.9% 冗余滤波（保住音素转移线索）→ 跳帧砍 34.42% 噪声主导帧 → 变步长滤波再砍 24.2%（次要帧只算偶数样本），总工作量降到 37.3%；数据少了，并行所需模块数和能耗同步下降，最后用优先级调度把延迟压进 N 通道预算。
  • 两个必要补丁：stride-2 降采样前先低通（抗混叠）；样本数减半会让 STE 系统性偏低，用相邻 stride-1 帧导出补偿因子拉回幅度尺度。
  • 结果：工作量平均削减 62.73%；m=23 即可实时支撑 32 通道；能效甜点 m=15（30.4 nJ / 1.25 ms，恰好卡进 25 通道预算）；三个后端模型精度损失全部 <1%。
  • 诚实的坑：阈值依赖整段 max(STE)——流式场景"先有鸡还是先有蛋"；且"多通道"只是 32 路独立输入塞进同一加速器分时处理，没有真实麦克风阵列。

§01 · 问题陈述

吞吐 ×N、预算不涨：前端才是多通道 KWS 的堵点

关键工程判断（论文引言）：与其堆高分类器复杂度去硬扛噪声，不如在信号采集阶段（前端）就把噪声处理掉——对能耗受限的边缘设备划算得多。模型压缩路线压的是后端，本方案压的是前端，两者作用对象正交、理论上可叠加。

y[n] = −Σ ak·y[n−k] + Σ bk·x[n−k]　（式 1，IIR 带通滤波）
当前输出要用历史输出一起算——这正是 IIR 阶数低、计算省（绕开 FFT），但天然串行、难以并行的根源。ASAP-FE 要解的就是"把这个结构改造成可并行"这件事本身。

§02 · 方法论

减数据 → 少模块 → 低能耗：一条因果链，不是三个并列技巧

组合逻辑是一条减法链：半重叠砍冗余 → 稀疏感知砍无信息帧 → 数据量小了之后并行所需的模块数和能耗同步下降 → 并行把延迟压进多通道预算。论文明确：光靠 62.73% 缩减仍撑不起 3 通道以上实时，并行是必须补上的第二只轮子。

创新一：半重叠分帧——信息完整性与计算冗余之间的甜点

音素转移是区分相近关键词的判别性特征——分段式在帧边界把它切断，这 4 个百分点的差距就是对这条线索的定价。半重叠把重叠量减半：信息保真的前提下总计算量比全重叠少约 25%。

创新二：稀疏感知数据缩减——两级粒度 + 两个必要补丁

Sframe = α·ZCC + β·Adiff　（式 5，α=1、β=0.5）
过零计数 ZCC 是帧内高频活跃度的廉价代理（清音摩擦音 /s/ 和高频噪声的过零率显著高于浊音）；幅度差 Adiff = max−min 反映幅度起伏。两个指标都不需要乘除法、硬件几乎免费——这是选它们做重要性打分的现实理由。

补丁一 · 抗混叠：stride-2 只取偶数下标样本，等效采样率减半、奈奎斯特频率减半——直接降采样会频谱混叠，所以 stride-2 帧必须用低通滤波后的波形，stride-1 帧用常规预加重波形。两条预处理通路并存的原因就在这。

补丁二 · STE 幅度补偿：求和项少一半，stride-2 帧的短时能量系统性偏低——用相邻 stride-1 帧导出补偿因子拉回 stride-1 的幅度尺度（图 6 实测对齐）。特征尺度不漂移，后端看到的特征分布才不会因降档而系统性偏移。这个补偿依赖也是调度器 Priority 1 存在的原因。

创新三：动态并行处理——优先级为补偿依赖而设

调度不是泛泛的负载均衡：优先级结构直接服务于特征补偿的依赖关系。能耗凸性的机理：延迟随 m 次线性下降（边际收益递减）× 功耗随活跃模块数近线性上升 = 能耗先降后升，必有最低点——这给 Algorithm 1 的局部搜索提供了理论保证。

§03 · 实验结果

算法到版级功耗的完整证据链

设置与平台

GSCD（65,000 条 1s / 16kHz，10 词 + silence + unknown 共 12 类，8:1:1 划分，噪声集增强）；帧长 16ms、40 个梅尔滤波器组；三个后端覆盖三类主流轻量架构：TC-ResNet8（时序卷积）、DS-CNN（深度可分离）、KWT-1（自注意力）。硬件：Verilog RTL 参数化滤波簇（1 ≤ m ≤ 30）集成进 50MHz RISC-V Rocket 核 + 64KB SRAM + µNoC 互连的边缘处理器；Kintex Ultrascale+ FPGA 验证功能，NCSU 45nm PDK 综合测功耗。

指标五件套互为硬约束：准确率（1.4% 损失及格线）、延迟（N 通道实时 = latency ≤ Taudio/N，Taudio=32ms 实测基线）、能耗（45nm 功耗仿真 + 空闲期功率门控假设）、剩余帧比例（度量缩减强度）、资源占用（LUT/FF/mW）。

消融的一致性是亮点：跳帧阈值在三个架构不同的后端上收敛到同一最优点（th1 = 0.56·max(STE)，砍 34.42%）；变步长阈值最优 th2 = 0.5·max(Sframe)（再砍 24.2%）——阈值选择对模型鲁棒。但注意两级预算不同（0.3% vs 0.5% 精度损失），论文未解释为何分配不同额度。

横向读数：ASAP-FE 96.48% 追平流式 IIR 的 96.49%、超过 MFCC 基线 96.1%、大幅超过分段式的 92.5%——精度没有为并行付出代价。但论文只报 12 类准确率，没有误触发率/漏检率；监控场景恰恰对误报极其敏感，0.9 个百分点在误报上的放大效应未评估。

audio/N，Taudio = 32 ms

能效甜点（图 11b）：能耗随 m 先降后升，实测最低点 m=15——30.4 nJ / 1.25 ms，恰好卡进 25 通道预算（32/25 = 1.28 ms，余量仅 30µs）。需要超过 25 通道时 m_min 本身就是最优。⚠ 注意：图 11(b) 上标注的各通道能耗（13590/7570/6060/5050/4040 nJ）与正文 30.4 nJ 相差约三个数量级，论文未说明口径——读图以正文为准并保留疑问。

§04 · 主要贡献

五条可转述的判断

1半重叠 IIR 分帧
为并行重新设计 IIR 分帧：保留音素转移线索的同时比全重叠少约 25% 冗余滤波——化解"分段丢信息、全重叠浪费算力"的两难（Table I 中唯一并行可行）。
2稀疏感知数据缩减
跳帧（STE 阈值）+ 变步长（ZCC/幅度差得分阈值）两级粒度裁剪，附带抗混叠低通与 STE 补偿两个必要补丁，再砍约 50%；两级最优点在三个后端模型上一致。
3动态并行处理的形式化
P1（最小模块数，解可行性）+ P2（能耗最优，解能效）两段子问题 + 优先级调度（Priority 1 由 STE 补偿依赖驱动）——且用硬件实测的 latency(m)/energy(m) 取代解析模型做决策。
4全栈验证
Verilog RTL 参数化滤波簇（1≤m≤30）→ RISC-V Rocket 处理器集成 → FPGA 原型 → 45nm 综合功耗——算法到版级功耗的完整证据链在 KWS 前端工作中少见。
5系统级数字
平均工作量削减 62.73%（三层连乘，三处引用一致）；最多 32 通道实时（m≥23）；25 通道以内能效最优（m=15，30.4 nJ / 1.25 ms/pass）；三个后端精度损失全部 <1%，低于 1.4% 阈值。

§05 · 局限性与展望

吞吐层面的多通道，不是声学层面的

方法的技术局限

  • 阈值依赖整段最大值：th1/th2 以每条输入自身的 max(STE)/max(Sframe) 归一——算最大值要先看到整段。离线 1 秒片段没问题，流式监控里"先有鸡还是先有蛋"；论文未讨论在线估计方案。
  • 得分权重纯经验：α=1、β=0.5 无敏感性分析；换远场、强噪声、不同采样率的数据域后是否仍优未知。
  • stride-2 的高频损伤靠补偿兜底：奈奎斯特减半对 /s/、/t/ 类宽带瞬态的潜在损伤只靠 STE 补偿对冲；连续大片 stride-2 区域的边界校准质量未单独评估。
  • 能耗模型带假设：基于"空闲期可完全功率门控"，门控切换开销与漏电恢复成本未计入。
  • 只治前端：多通道下后端分类器负载同样 ×N，端到端系统延迟未报告。
  • 半重叠参数不透明：重叠比例/跳步毫秒数未给出，复现需反推。

实验设计的不足

  • 多通道是"复用"而非"真实阵列"：所有实验用 GSCD 单通道近讲数据；32 通道 = 32 路独立输入塞进同一加速器分时处理。没有真实多麦克风阵列、没有通道间相关噪声/混响/波束形成——"多通道 KWS"只在吞吐层面成立，声学层面未被检验。
  • 无能耗口径的正面 SOTA 对比：Table I 只比精度；与 MFCC 硬件加速器没有能耗正面对比，62.73% 也只相对 IIR 前端自身基线。
  • 仿真而非流片：功耗来自 45nm 综合仿真；Fig.11(b) 图上标注与正文 30.4 nJ 的量级矛盾未澄清。
  • 平均值掩盖最坏情况：62.73% 是平均削减；说话密集段跳帧率低、负载接近上限——最坏情况是否满足 Taudio/N 未报告，而这正是实时系统的生死线。
  • 只报准确率：无误触发率/漏检率，监控场景对误报极敏感。

下一步的五个方向（论文展望 + 笔者判断）

① 在线自适应阈值：滑动窗口最大值或指数滑动平均替代整段 max，把稀疏感知缩减真正移植到流式管线——产品化的第一道坎。
② 前后端联合优化：把帧级稀疏信号传给分类器做动态计算（帧丢弃感知训练、early-exit、按帧重要性分配后端算力），让 FE 的省电传导到整条链路。
③ 真实阵列 + 通道间冗余：在真实多麦克风远场数据上重校 th1/th2 与 α/β；多通道高度相关帧可共享计算（同帧联合降档），有望在 62.73% 之上再砍一层。
④ 更激进的数值压缩：滤波簇已是定点整数，可叠加低比特量化或近似乘法。
⑤ 工艺与场景伸缩：先进节点流片验证 30.4 nJ 绝对水平；把 m_min/m_opt 两段式配置方法推广到会议拾音、工业声学监测等多路音频场景。
