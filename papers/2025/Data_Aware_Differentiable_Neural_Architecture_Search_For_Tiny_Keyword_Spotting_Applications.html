Data-Aware 可微 NAS
把 MFCC 配置从"手工超参"提升为与架构同层的一等搜索公民

Data Aware Differentiable NAS for Tiny Keyword Spotting Applications

作者：Yujia Shi 等 —— 丹麦技术大学 DTU × Bang & Olufsen（耳机厂商场景）

发表：2025.07 · arXiv:2507.15545 · IEEE MLSP 2025 · 代码开源

可微 NAS / DARTS数据中心 AITinyML MFCC 超参搜索PC-DARTS 骨架名字检测迁移

一分钟版本

  • 被忽视的设计死角：MFCC 的窗长 / 帧移 / 梅尔滤波器个数在传统流程里是架构搜索之前由工程师凭经验敲定的——输入保真度和模型复杂度在竞争同一份内存算力预算，却被切成先后两段、彼此看不见对方。
  • 方案：在 PC-DARTS 骨架上给每个候选数据配置（8 个 MFCC 组合）挂一个连续松弛参数 γ，softmax 加权把所有配置混进单一输入——一次前向反传，8 个配置的重要性估计全部得到梯度更新；早停（最大 γ ≥ 2× 次大）后 γ 退出，架构继续搜。
  • 两个技术补丁：维度对齐（零填充 vs 预处理降维，后者实测更好）；搜索成本可控（GSC 50 epoch / A100 16 小时 / 14.59 GB）。
  • 结果：GSC 35 词 298K 参数 97.61%（比非数据感知版本同时高 1.13 pp 且省 24% 参数）；名字检测任务几乎零框架改动迁移成功（1.64M / 95.43%，+3.81 pp 且省 41% 参数）。
  • 最重要的发现：两个任务搜出了不同的最优配置（GSC 选 400/200/40，名字检测选 640/320/40）——最优特征配置是任务相关的，不该由全局惯例一刀切。

§01 · 问题陈述

两条 NAS 路线各缺对方的一半

之前手工敲定——输入端省下的算力模型端不知道，模型端需要的精度输入端也不感知 另一层痛点：造 TinyML 系统要求工程师同时精通模型设计、资源优化、嵌入式落地——这种人极少，管线常卡在"人"这一环

Data Aware NAS（[14][15]）确实碰数据，但走 supernet 黑盒评估路线，在标准基准上的验证仍处早期——本文做的就是把这条线与 DARTS 系的梯度导航合并。

§02 · 方法论

γ 连续代理：让离散配置选择获得梯度信号

这是 DARTS「把离散空间连续化换梯度导航」哲学在数据维度的复制。代价是搜索期看到的是混合输入而非任何单一配置的纯净输入——代理排名与离散化后真实性能之间是否保序（ranking gap），论文没有验证，这是方法论上最大的悬而未决。

[αt+1, βt+1, γt+1] = [αt, βt, γt] − ηarch∇α,β,γLarch　（式 1，早停前）
[αt+1, βt+1] = [αt, βt] − ηarch∇α,βLarch　（式 2，早停后）
训练协议沿用 DARTS 一脉：warm-up 只更新权重 w → 主搜索阶段交替执行（训练集更新 w，验证集更新 α/β/γ）——架构和数据参数在验证集上挑选泛化最好的配置，避免搜索过拟合训练集。Larch 在验证集上计算。

§03 · 实验结果

两个任务、两个答案：最优配置是任务相关的

任务设定

GSC v0.02（主基准）：105,829 条 / 2,618 说话人 / 35 词 / 16kHz / 至多 1s——TinyML 标准音频基准（MLPerf Tiny 同源）。名字检测（自定义任务，来自 B&O 的产品场景：智能耳机对用户名字做出反应）：GSC 派生，保留 Marvin / Sheila 两个名字类，其余 33 类归 unknown；四种增强（音高变换 / 时间伸缩 / 混响 / 背景噪声）缓解类不平衡，参数未报告、指向代码仓库。

指标只有参数量和准确率——参数量是 TinyML 的存储代理，但没有延迟 / 能耗 / SRAM 激活内存等真实硬件指标，"Tiny"的成色靠参数量间接代言。

GSC 读数：对最强基线 DS-CNN 高 2.93 pp、参数只有其 21%；对 EfficientNet 参数少约 95%、准确率反高 9.29 pp。名字检测读数：论文克制地承认自己未必是全部基线中唯一的 Pareto 最优解（MobileNetV3 参数更少但低 10.49 pp），但确实落在顶级准确率档位。

侧面印证固定配置的直觉不可靠：名字检测的消融基线用了时间分辨率更高的固定配置（窗 512 / 移 160），模型反而更大更不准——工程师"拍"的配置常常不是好配置。

消融的空白同样要指出：零填充 vs 预处理只有定性结论；早停 2 倍阈值无敏感性分析；γ 初始化与演化过程未报告；名字检测消融的固定配置（窗 512）甚至不在搜索空间内，选择理由未说明。

§04 · 主要贡献

六条可转述的判断

1首次合并两条 NAS 路线用于 KWS
可微（DARTS 系，梯度导航高效）× 数据感知（数据配置进搜索空间）——填补"可微的不碰数据、碰数据的不用梯度"的空档（论文自我定位 initial results）。
2γ 连续代理机制
每个离散数据配置挂一个松弛参数，softmax 加权混进单一输入——一次反传更新全部 8 个配置的重要性估计；这是 DARTS 哲学在数据维度的复制。
3维度对齐方法学
零填充（保信息、处理量大、部署可削）与预处理（省处理、有信息损失风险）两种策略及权衡分析，解决多配置输入与连续松弛的结构性矛盾。
4双任务验证 + 开源
GSC 298K/97.61%；名字检测几乎零框架改动迁移成功 1.64M/95.43%——证明方法不是基准特化的；代码 GitHub 开源（ss1k/Data-Aware-NAS）。
5最值得记住的实证发现
两个任务搜出不同最优配置（GSC 400/200/40 vs 名字检测 640/320/40），且都选 40 梅尔档——特征配置的最优解是任务相关的，全局惯例（如"默认 40/20ms"）对每个任务都要重新审视。这篇论文的价值不在 97.61% 这个数字，而在打通了"数据配置与模型架构同层可微共优化"的干净路径——适合当方法骨架读，不适合当结果榜单读。

§05 · 局限性与展望

4 页 workshop 论文的自我定位与硬伤

方法的技术局限

  • 混合输入的物理意义存疑：不同窗长/帧移的特征帧在时间轴上本不对齐，逐元素加权平均缺乏信号处理解释——搜索期代理排名与离散化后真实性能之间的 ranking gap 未验证（argmax γ 的配置没被单独评估过）。
  • 数据空间仍是小的离散空间：8 个组合只是把工程师惯用档位搬进搜索；采样率、特征类型（MFCC vs 滤波器组能量 vs 原始波形）未纳入——论文自列"连续数据选项直接梯度下降"为未来工作。
  • 参数量是唯一资源指标：对 MCU 部署，SRAM 激活内存（能不能跑）和延迟（实时性）常比 Flash 参数量更早成为绑定约束——无任何真实硬件测量。
  • 早停 2 倍阈值是拍脑袋值：无敏感性分析，不同空间大小下的适用性未知。

实验设计的不足

  • 无统计稳健性：搜索和最终训练都只跑一次，无多种子、无方差——NAS 对种子出了名地敏感，1~4 pp 的提升理应有置信区间。
  • 基线可能欠调：未用数据增强；MobileNetV3 的 82.76% 明显低于文献常见水平——相对提升可能部分来自基线偏弱。
  • 无真 SOTA 对照：BC-ResNet 等被明确排除（论文自己说明对比不公平）——强训练配方下的竞争力未知。
  • 指标单一：35 词分类准确率不是部署运营指标——误唤醒 vs 漏唤醒的 DET 权衡（名字检测这类二分类尤其需要）未报告。
  • 完成度：增强参数、γ 演化、两策略量化对比、名字检测搜索开销都留在代码仓库没进论文。

下一步方向（论文自列 + 笔者补充）

论文自列：连续数据选项直接梯度下降；面向 TinyML 的新型搜索空间（当前 cell 空间继承自视觉 NAS，未必贴合音频与 MCU）；纳入更多超参优化。
笔者补充：把延迟/SRAM 显式写进搜索目标（Hardware Aware 与 Data Aware 真正统一进同一套可微框架）；多种子统计与 ranking gap 验证；Cortex-M 真机部署测量兑现 TinyML 叙事；数据增强策略本身进数据搜索空间；名字检测改用误接受/误拒绝率评估，直接对齐耳机唤醒的产品指标。
