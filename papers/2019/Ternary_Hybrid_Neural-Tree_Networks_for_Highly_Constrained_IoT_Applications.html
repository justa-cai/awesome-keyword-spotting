神经树管「走哪条路」，三值量化管「每步多贵」——Arm 用两条正交的压缩轴塞进 KB 级 IoT

神经树混合架构三值量化 {-1,0,+1}条件计算Cortex-M 友好模型大小 −52.2%
Ternary Hybrid Neural-Tree Networks for Highly Constrained IoT Applications · Dibakar Gope / Ganesh Dasika / Matthew Mattina（Arm ML Research Lab）· SysML 2019 · arXiv 1903.01531
一句话：把决策树的条件计算（样本只走部分路径）和三值量化的权重压缩（32-bit → ~2-bit）叠在一个可端到端训练的混合架构里——模型大小 −52.2%、计算量 −11.1%、内存 −30.6%，准确率损失可忽略。

1问题：IoT 的账本上全是 KB，单一压缩技术各有天花板

TL;DR
  • IoT MCU 的预算是 64–256KB SRAM + <1MB Flash，且 Cortex-M 系没有矩阵乘加速器——标准 KWS 模型量化后仍可能装不下。
  • 单一压缩各有短板：二值化掉点狠、4/8-bit 压缩比有限、剪枝要稀疏硬件、蒸馏要先养昂贵的教师。
  • KWS 是始终在线功能，7×24 跑在电池上——压缩不只是装得下，还要算得省。
图 1 · 机制全景：IoT 预算四格账本 → 单一压缩技术的天花板 → TNT 的两条正交压缩轴 → 协同效应与论文信息。

2机制：树砍路径长度，三值砍每步代价

神经树 = 小网络当内部节点

决策树内部节点由小型神经网络替代，softmax 软路由可微，整棵树端到端训练——不是把树和网络拼在一起，是树本身就在学。

三值量化 {-1, 0, +1}

阈值 Δ 分桶；乘法退化为加减法，0 权重的连接直接跳过——存储、运算、硬件三本账同时受益。

条件计算

不同输入走不同分支，每个样本只经过树的一部分——平均计算量下降，这就是「路径长度」那根轴。

对齐 Cortex-M 的强项

位运算与条件分支正是 M 系处理器擅长的指令模式——树结构的分支恰好喂给分支预测器。
图 2 · 左：神经树结构——绿色实线是当前样本的实际路径，未走的分支（灰虚线）完全不算；右：三值权重的三本账（存储 16× / 运算加减化 / 硬件位运算）与缓存代价。
w_ternary = +1 if w > Δ | 0 if |w| ≤ Δ | −1 if w < Δ （32-bit → ~2-bit ≈ 理论 16×）
人话：把权重按阈值 Δ 扔进三个桶。正桶当 +1、负桶当 −1、中间的当 0 直接扔掉连接。乘法从此消失——卷积变成「加一些、减一些、跳过一些」。Δ 的取值正是论文设计空间分析的核心超参之一。

3结果：谁的贡献是什么，拆得清清楚楚

结果速读
  • 模型大小 −52.2%——主要贡献者是三值量化（每权重 32-bit → ~2-bit）。
  • 计算量 −11.1%——树路由的条件计算贡献，量级不大但白拿。
  • 整体内存占用 −30.6%，GSC 上准确率损失可忽略；两者结合优于任一单技术。
图 3 · 三条压缩指标条形图与贡献拆账表：三值量化扛大小、树路由扛计算量——两条轴对症的是不同瓶颈，所以能叠加。

4边界：理论压缩比 ≠ 真机加速

三值快不快，看内核

位运算加速需要专门写的内核；没有优化的通用处理器上，三值乘法未必真比整数乘法快。

树路由毁缓存

不同样本走不同路径 = 不规则访存——缓存可怜的 M 系列上，实际延迟可能吃掉理论收益。

设计空间是三维的

树深 · 分支因子 · Δ 阈值 · 哪些层用树——手工探索成本高，论文自己把 NAS 列为未来工作。

缺真机数据

论文报理论压缩比；M4/M33 上的延迟/功耗实测被论文自己标为 future work。
图 4 · 边界四条 + 谱系坐标：承接 Arm 系硬件压缩线（2019 №3 RGSM 剪枝+二值化），条件计算思想流向早退出/动态网络（2020+），「设计空间要自动搜」喂给硬件感知 NAS（2021+）。

5判断：能带走的三句话

JUDGEMENT

压缩要选正交的轴叠加：一个砍「算多少次」（条件计算），一个砍「每次多贵」（低比特权重）——作用于同一瓶颈的两个技术，收益不会相乘。

架构要顺着硬件的纹理长：Cortex-M 擅长位运算和分支，TNT 的三值 + 树路由就是把这两个强项用满——反着硬件纹理设计的压缩，理论数字再好看也落不了地。

理论压缩比是必要不充分条件：不规则访存、内核优化缺位都能让纸面收益蒸发——引用压缩倍数时，先问「在哪个内核、哪块硬件上测的」。
