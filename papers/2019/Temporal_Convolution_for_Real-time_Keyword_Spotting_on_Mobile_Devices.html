把频率维当成通道，只在时间轴上卷积——385 倍移动端加速是真机测出来的

1D 时序卷积紧凑 ResNetGoogle Pixel 1 实测FLOPs ≠ 延迟GSC 超越 2D 基线
Temporal Convolution for Real-time Keyword Spotting on Mobile Devices · Choi / Seo / Shin / Byun / Kersner / Kim / Kim / Ha · Interspeech 2019 · arXiv 1904.03814
一句话：把 2D 时频卷积换成「频率当通道、时间轴 1D 卷积」的 TC-ResNet——参数更少、感受野涨得更快，在 Google Pixel 1 上端到端实测拿到 385 倍加速且准确率反超，并把「真机延迟」拉回移动 KWS 的评估标准。

1问题：2D 卷积的三重税，和 FLOPs 的欺骗性

TL;DR
  • 2019 年移动端 KWS 的主流是 2D CNN（时频图卷积），但它算得重：核沿时间和频率双维扫，参数量和乘加都贵。
  • 2D CNN 还要够深才能让时间感受野覆盖一个唤醒词——更深等于更慢，与端侧延迟预算直接冲突。
  • 最隐蔽的问题是评估口径：多数论文只报 FLOPs / 参数量，不测真机延迟——而两者并不线性对应。

2机制：频率当通道，时间轴上扫

2D → 1D 的核心转变

2D 核 K_t × K_f 换成只沿时间扫的 1D 核 K_t，频率维度整个变成输入通道——参数量直接省掉 K_f 倍。

感受野涨得更快

每加一层，时间感受野按 K_t 增长而不被频率维稀释——浅网就能覆盖唤醒词长度的时间上下文。

紧凑 ResNet 骨架

1D 卷积 + BN + ReLU + 残差连接：浅而可训，梯度直传，不需要堆几十层。

移动硬件友好

1D 卷积内存访问规整，移动 CPU/DSP 的算子优化成熟——同样的 FLOPs 跑得更快的「物理红利」。
图 2 · 左：2D 核（3×3 九个权重）与 1D 核（3 个权重）的几何对比，频率维变成通道后被隐式混合；右：残差块结构与全链路真机计时的评估流水线。
2D: O(C_out · C_in · K_t · K_f · T · F) → 1D: O(C_out · C_in · K_t · T · F_as_channels)
人话：2D 卷积每个输出位置要扫 K_t × K_f 个邻域权重；1D 只扫 K_t 个，频率方向的信息不丢了——它变成「通道维」，由卷积的通道混合一步吃掉。省的不是信息，是重复扫频率邻域的算力。

3结果：385× 是怎么来的，为什么可信

结果速读
  • Google Speech Commands 上准确率超越 2D CNN 基线——更快的同时更准，不是拿精度换速度。
  • Google Pixel 1 端到端实测（前处理 + 推理 + 后处理全计时）拿到 385×+ 加速，进入 <100ms 实时区间。
  • 论文扫出准确率-延迟的 Pareto 前沿，把「哪个模型更快」变成可对比的曲线而非单点吹嘘。
图 3 · 加速比的乘法账（定性示意：1D 化 + 浅架构 + 访存规整叠加）与 FLOPs ≠ 延迟的实证分析；MatchboxNet 等后续工作直接建立在此骨架上。

4边界：它没解决什么

频域局部模式建模弱

谐波结构、共振峰这类沿频率轴的局部模式，2D 卷积天生擅长——1D 只能靠通道混合隐式覆盖，这是结构性让步。

真机结论硬件特定

385× 是 Pixel 1 的数字。换 DSP / NPU、不同内存层级，倍数会变——方向成立，量级必须重测。

架构要每硬件调优

深度 · 通道数 · 核长是超参，「最优 TC-ResNet」不通用——后来硬件感知 NAS 类工作正是接手这件事。

5判断：能带走的三句话

JUDGEMENT

端侧论文的第一指标是真机端到端延迟，不是 FLOPs——FLOPs 只约束了算术量，延迟还包含访存、缓存与算子特化，两者可以差出一个量级。

「砍掉一个卷积维」是端侧架构设计的高杠杆动作：频率维已被特征提取吃掉，时间维才是唤醒词分类的主要矛盾——认清主要矛盾，架构才能做减法。

加速倍数永远绑定硬件与基线：引用 385× 时要带上「Pixel 1 + 该 2D 基线」的定语，跨硬件外推是常见的引用事故。
