一句话：注册 = 查词典拿音素转录 → 加进 FST 图——CTC 网络零改动；声学建模与关键词知识放进不同容器，各自独立更新。
01

问题：封闭词表的三个不够用

TL;DR
  • 绝大多数 KWS 为固定词表设计（OK Google / Alexa / Hey Siri）——加词要重收数据、重训模型或大改模型；三个不够用的场景：用户自定义、多语言方言（每语种单独训太贵）、快速部署（重训周期太长）。
  • 双模块解耦：CTC 音素后验生成器（大规模语音训练一次即固定——通用的「耳朵」）+ FST 关键词解码器（词编成音素状态图——可随时更新的「词典」）。
  • 注册流程三步零训练：查音素转录（词典或自动音素化）→ 加进 FST 图 → 完事——CTC 网络一行不改。
  • FST 的天然优势：自环支持重复与停顿、多路径支持变体发音、可加语言模型约束减误报——这些「语言学知识」免费进了解码图。

02

机制：网格与状态图

CTC 输出一个音素后验网格——行是音素（加 blank），列是帧，颜色深浅是概率高低；FST 把「hello」编成 HH→AH→L→OW 的状态转移图。Viterbi 解码在网格上找与图最匹配的路径：blank 行吸收静音与过渡段（这正是 CTC 不需要帧级对齐标注的原因），自环容忍音素重复，多路径容纳异读变体。

图 2 · 机制解剖：音素后验网格与 Viterbi 路径 · FST 状态图的转移结构
CTC: P(音素|帧) 网格 — 含 blank 行, 训练一次固定 ← 通用耳朵 FST: 关键词 → 音素序列 → 状态转移图(自环+多路径) ← 可换词典 匹配: Viterbi(网格, FST图) → 最优路径分数 > θ → 触发 注册: 查词典拿音素转录 → 图上加一条链 → 零训练
人话：CTC 是个不知疲倦的速记员，每时每刻记下「现在听着像哪个音」；FST 是你要找的那句话的「拼图模板」；Viterbi 拿着模板在速记本上滑——拼上了就报警。要找新词就换一块新模板，速记员永远不用重新培训。

CTC 的 blank 是整个设计的润滑剂：它吸收了「音素之间的静音与过渡」这个最麻烦的对齐问题——不需要帧级标注就能训练；解码时 blank 也让路径可以自由跳过过渡段，匹配对语速变化天然鲁棒。

04

边界：音素错误会传染

图 4 · 边界与延伸：CTC 质量天花板 · 错误传播 · 歧义转录 + 开放词表四路线坐标

CTC 质量是天花板

系统性能受限于音素预测准确性——噪声、口音、儿童语音下错误率上升直接打击召回率；声学模型一弱全局皆弱。

音素错误传播

CTC 错一个音素传到 FST 匹配就失败——短词（1–2 音节）对少量错误最脆弱（与 #23 的同款发现）。

歧义音素转录

异读、方言变体的转录选择影响性能——选错转录 = 注册时就埋了雷；自动音素化工具的质量是隐性依赖。

FST 解码延迟

大词表下解码计算可能成瓶颈——影响实时性；解码算法优化是这条路线的长期课题。

05

可迁移的判断

JUDGMENTS · 能带走的三条

① 把「声学建模」与「类目知识」放进不同容器，各自独立更新。

网络管通用能力（训练一次固定）、解码图/FST 管词表（随时增删）——两类知识的变化周期完全不同（声学十年不变、词表天天可能改），分容器是按变化频率解耦的架构原则，适用于任何「通用引擎 + 动态配置」的系统。

② 中间表示的选择 = 买哪种先验。

音素（本文）买语言学先验——可解释、词典可用，但受 G2P 与音素识别质量约束；嵌入（Naver #11）买数据适应性——不依赖语言学但黑盒；滤波器（Snips #11）买模板精度——样本省但不可读。先验与灵活性的权衡在中间表示选择时就定了。

③ blank/自环这类「吸收不确定性的结构」是解耦的隐形功臣。

CTC 的 blank 吸收对齐不确定性、FST 自环吸收时长不确定性——系统各层之间需要这类「弹性接口」来隔离误差；设计 pipeline 时主动预留吸收不确定性的位置，比追求每层精确更稳健。

系列坐标：开放词表四条路线的「音素+解码器」分支——本文（2019 高通）与 #11 Snips（预测滤波器）、#23 Sonos（音素+量化）、#11 Naver（嵌入原型）同年或前后相继，四条路线各有甜点；2021 年 TAML 把注册改成文本锚定（连音频样本都不用）——这条谱系的主线始终是「词知识放哪、怎么生成」的中间表示演化。
