## Problem Statement

### Problem Background and Domain Pain Points

The task of Keyword Spotting (KWS) is to detect wake words like "Hey, Google" or "Hey, Siri" in streaming audio. Historically, this has targeted on-device applications such as smartphones and smart speakers. Past research has focused on two main lines: better detection rates (residual learning [1], orthogonal constraint multi-head attention [2]) and lower computational overhead (small models like DS-CNN [3], BCResNet [4]). All of these are built upon the **fixed-vocabulary, multi-class closed-set classification** paradigm on the Google Speech Commands (GSC) v1/v2 datasets [5]—the vocabulary is frozen at training time, and the model only ever recognizes those dozen or so words.

This paradigm is loosening on the product side. Wake words are a product decision variable: different regions, brands, and even different skills on the same device want to change the word. Running the entire "collect data-train-deploy" pipeline for every new word is a real cost black hole for on-device manufacturers. Consequently, query-by-example (QbE), or few-shot learning (FSL), based KWS has gained momentum in recent years (References [6, 7, 8, 9]): users or OEMs only need to enroll M utterances of the target word as support samples, and the system can immediately recognize this new word that has never appeared in the training set. The N-way M-shot episode-based evaluation is the standard metric for this paradigm.

However, real-world audio streams add a cruel half to this few-shot system: when devices are always listening, most audio is not any registered word—background noise, family chatter, media from TVs, or other similar words. Neural networks are widely proven to be overconfident ("deep neural networks are easily fooled", Reference [10]). Faced with these unexpected categories with no support samples, the model will confidently force them into one of the N known classes. For wake word systems, this is the worst failure mode: false wake-ups directly erode user trust and incur power consumption costs for the subsequent pipeline (powering up the full voice assistant chain). The academic community refers to "identifying and rejecting unknown classes" as Open-Set Recognition (OSR, Reference [11]).

This paper combines these two requirements to propose Few-Shot Open-Set Keyword Spotting (FSOS-KWS): the system must not only learn to classify a new word into N classes from M support samples but also reject all open-set utterances that do not belong to these N classes. The authors explicitly claim this is the first work to introduce FSOS-KWS ("to the best of our knowledge, this is the first work introducing few-shot open-set keyword spotting", Section 2).

### Specific Shortcomings of Existing Methods

Looking at the existing toolbox, none can directly handle this setting:

- **Closed-set KWS "Unknown Class" schemes fail.** In the traditional GSC 12-class setting, a specific "Unknown words" class (packaging the remaining 25 words) and a "Silence" class are created. This essentially repackages the open-set problem into closed-set multi-class classification—on the premise that the "unknown" world can be exhaustively covered by the remaining vocabulary at training time. Once switched to a few-shot scenario, the N known classes are drawn temporarily for each evaluation, and the combination of "unknowns" differs every episode. A statically trained Unknown class is completely mismatched.
- **Existing few-shot KWS works do not handle open sets.** ProtoNets for KWS (Parnimi & Lee [8]), QbE systems with multi-head attention and soft-triple loss [9], and few-shot spoken word classification [7] only optimize closed-set few-shot accuracy. Unexpected utterances are always misclassified into known classes.
- **FSOSR methods borrowed from the visual domain have hard flaws.** PEELER [12] uses entropy maximization loss to suppress known-class probabilities for unknown samples and employs Gaussian embeddings to obtain flexible decision boundaries—essentially an "indirect" anomaly detection with no explicit unknown class representation for calibration. SnaTCHer [24] was the SOTA at the time: it uses a set-to-set transformation (Transformer) to modify the support set to obtain task-relevant prototypes, then detects open sets via "consistency before and after prototype transformation." However, the paper explicitly points out its computational cost in Section 4.3: "SnaTCHer requires heavy computations due to the transformations for all the queries," meaning **every query sample must pass through a Transformer**, which is a fatal flaw for always-listening on-device KWS. More troublingly, SnaTCHer advocates using unnormalized distance metrics (rather than softmax probabilities) for open-set decisions during inference. When we reproduced it on the Conv4-64 weak backbone of splitGSC, we found this heuristic is not universal: SnaTCHer-F’s AUROC was only 51.1 (0.7) / 53.1 (1.4) (1/5-shot, Table 1), **which is lower than the original ProtoNet’s 55.3 (0.5) / 63.8 (0.6) without any open-set mechanism**—indicating that "using distance vs. probability for open-set scores" is unstable in weak representation spaces.
- **Existing "dummy class" ideas are incompatible with changing closed sets.** Proser [22] in visual OSR uses manifold mixup to create data placeholders and learnable dummy classifiers as unknown class placeholders. However, its dummy classifiers are a **fixed** set of parameters after training, suitable only for traditional OSR with a fixed label space. In FSOSR, the open set drifts with each episode (Figure 1, bottom part, specifically illustrates this: for the same four classes, the known/unknown split is completely different across two episodes). Fixed dummy classes cannot adapt.
- **Lack of a unified benchmark.** There is no class-level split FSOSR protocol on GSC. Each work uses its own split, making results incomparable.

### Key Challenges to Solve

In one sentence: How to design an **episode-adaptive open-set rejection mechanism**—the N known classes are drawn temporarily each episode, and the open set is "everything else" (including the pure noise Silence class). The rejection boundary must be inferred instantly from the support samples of the current episode, while (1) not sacrificing few-shot classification accuracy (dummy classes must not occupy the representation capacity of known classes), and (2) the additional inference overhead must be small enough to fit the constraints of always-listening on-device KWS (this is a consistent stance of the Qualcomm research line: the few-shot adaptation phase should involve zero gradients and zero fine-tuning).

## Methodology

### Overall Architecture Design and Design Motivation

The overall system (Figure 2) consists of three串联 parts: an encoder $f_\phi$ maps 1-second audio into a D-dimensional embedding (three backbones: Conv4-64 outputs 768 dimensions—it lacks global average pooling at the end, so the dimension is larger than the 64 channels; ResNet-12 outputs 512 dimensions; BCResNet-8, designed for KWS, outputs 256 dimensions); a dummy prototype generator $g_\phi$ generates a (or L) dummy prototype $c_d$ from the **N known class prototypes of the current episode**; the classification head is an N+1 class softmax (Euclidean distance + asymmetric temperature). During inference, it first performs argmax classification among the N known classes, then compares the dummy class probability $p_\theta(y=y_d|x)$ with a threshold $\delta$ to decide if it is open-set.

Three selection motivations are worth expanding:

- **Why choose the metric learning lineage over adaptation or hallucination?** Section 2 divides FSL into three branches—MAML-like adaptation methods [15] require gradient fine-tuning loops for each new task during deployment, which is not allowed by on-device compute and latency; hallucination methods [16] generate samples for data-scarce classes, also incurring high training costs; metric learning methods [13, 14] only require learning a good embedding space, where the representation of a new class during adaptation is simply the mean of the support sample embeddings, requiring **one forward pass and zero gradients**. This fits the product form of "user registers 5 utterances, device is ready to use" best.
- **Why choose ProtoNets [13] as the base?** ProtoNets' class representations are "prototype points" (class centers) in the embedding space, and classification is distance softmax between prototypes. This structure leaves a natural interface for "adding one dummy class center"—as long as a point can be created that is in the **same space and metric** as the N true prototypes, open-set detection can reuse the entire classification mechanism, without needing an additional binary classification head or separate pipeline. This is the origin of the paper's title "Dummy Prototypical Networks."
- **Why must dummy prototypes be generated from support samples (episode-known)?** Open set = full class space minus the N known classes of the current episode. As N changes, the open set changes. If the dummy prototype wants to "occupy the region not surrounded by known classes," it must know **who** the known classes are **this time**—so the input to the generator is the prototype set of the current episode itself, calculated on the fly each episode. This is the core design judgment of the entire paper.

### Mathematical Principles of the Core Algorithm

**Foundation: Prototypes and Distributions in ProtoNets.** In an N-way M-shot episode, the prototype for class $n$ is the mean of the support sample embeddings (Equation 1):

$$c_n = \frac{1}{M} \cdot \sum_{(x_i, y_i) \in S_n} f_\phi(x_i)$$

The probability that query sample $x$ is assigned to class $n$ is the softmax of negative distance (Equation 2):

$$p_\phi(y=n|x) = \frac{\exp(-d(f_\phi(x), c_n))}{\sum_{n'=1..N} \exp(-d(f_\phi(x), c_{n'}))}$$

where $d$ is the Euclidean distance $d(z, z') = ||z - z'||_2$. The training objective is to minimize the negative log probability of the true class.

**Generation of Dummy Prototypes** (Equation 3):

$$c_d = g_\phi(C) = \text{Maxpool}(g_1(C)) \cdot W_g$$

where $C = [c_1; c_2; \dots; c_N] \in \mathbb{R}^{N \times D}$ is the matrix stacking the N prototypes row-wise, $g_1$ is a group of fully connected layers with non-linearity, mapping each prototype to a hidden dimension $H$ ($g_1(C) \in \mathbb{R}^{N \times H}$); Maxpool performs max pooling along the N direction (i.e., the class dimension), obtaining a feature of $\mathbb{R}^{1 \times H}$; $W_g$ is a learnable $H \times D$ matrix that projects the hidden feature back to the embedding space, $c_d \in \mathbb{R}^{1 \times D}$. The entire $g_\phi$ is FC-ReLU-FC (hidden dim 32) plus pooling plus linear projection, with extremely few parameters. The final augmented prototype set is $\{c_1, \dots, c_N, c_d\}$, and the label for open-set queries is uniformly set to the $(N+1)$-th label $y_d$.

**Asymmetric Temperature N+1 Class Softmax** (Equation 4):

$$p_\theta(y=n|x) = \frac{\exp(-d(f_\phi(x), c_n)/\tau_n)}{\sum_{n'=1..N+1} \exp(-d(f_\phi(x), c_{n'})/\tau_{n'})}$$

where $\theta = \{\phi, \phi\}$, the key setting is $\tau_{N+1} = \gamma \cdot \tau_{n \neq N+1}$, $\gamma > 1$ (default $\tau_{n \neq N+1}=1$, $\gamma=3$, i.e., dummy class temperature is 3).

**Dual-path Cross-Entropy Loss** (Equation 5):

$$L_{CE} = L^K_{CE} + \lambda \cdot L^U_{CE}$$

where the known class query term $L^K_{CE}$ is calculated on the known query set $Q_K$ using standard N+1 class cross-entropy, and the unknown class term $L^U_{CE}$ substitutes the label $y_d$ into the same cross-entropy on the open-set query set $Q_U$; $\lambda$ is default 0.1. During training, **pseudo FSOSR episodes** of N-way M-shot are used: draw N known classes from the training set classes, each with M support samples, then draw several pseudo open-set classes that only produce queries, not support. The query set size satisfies $|Q| = (N+N_U) \cdot M_Q$.

**Inference**: Known class classification takes $\argmax_{n \in \{1..N\}}$; open-set decision compares $p_\theta(y=y_d|x)$ with threshold $\delta$.

**Gumbel Softmax Extension for Multiple Dummy Prototypes** (Equation 6): Replace $W_g$ from $H \times D$ to $H \times (L \cdot D)$, generating L dummy prototypes $\{c^l_d\}$ at once. Selecting a dummy prototype for query $x$ should be $\argmax_l (-d(x, c^l_d))$, but argmax is non-differentiable and cannot be trained end-to-end. Thus, Gumbel softmax is used for reparameterization:

$$p(y^L=l|x) = \frac{\exp((-d(f_\phi(x), c^l_d) + \epsilon_l)/\tau)}{\sum_{l'=1..L} \exp((-d(f_\phi(x), c^{l'}_d) + \epsilon_{l'})/\tau)}$$

where $\epsilon_{1..\epsilon_L}$ are noises sampled independently from the standard Gumbel distribution ($\mu=0, \beta=1$), and $\tau$ anneals from 2 to 0.5 cosinely during training (following [26]). During training, the dummy prototype takes the soft-weighted composite $c_d = \sum_l p(y^L=l|x) \cdot c^l_d$, and switches to hard argmax during inference.

**The "Why" for Each Design**:

- **Why must the generator be permutation invariant, and why choose the DeepSets form?** The input order of N prototypes is arbitrary (classes have no natural order). The dummy prototype must be insensitive to the permutation of prototypes; otherwise, shuffling the class order in the same episode would yield different dummy prototypes, leading to contradictory training signals. The paper's solution is to explicitly adopt the symmetric aggregation structure of DeepSets [25]—first apply the same non-linear transformation $g_1$ independently to each prototype, then aggregate along the class dimension using Maxpool, a symmetric function. Maxpool also carries a semantic meaning: for each dimension of the hidden layer, only keep "the most significant value among all known classes," effectively allowing the dummy prototype to inherit the peak attributes of known class prototypes without copying any single class. I understand this as allowing the dummy prototype to learn an "envelope of all known classes" rather than an "average," and the region outside the envelope is where the open set should occupy.
- **Why asymmetric temperature $\gamma > 1$?** This is the most exquisite part of the paper. The dummy class is a single point, yet it must cover the union of $N_U$ (default 5) unknown classes—the average distance from open-set queries to this single point will inevitably be systematically larger. If the temperature is the same as the known classes (1), after exponential amplification, the probability of the dummy class can never go up, the cross-entropy of unknown queries cannot decrease, and the gradient will force the encoder to distort the entire embedding space (pulling open-set samples hard towards the dummy point) to reduce the loss, ultimately harming the inter-class structure of known classes. Amplifying $\tau_{N+1}$ is equivalent to flattening the exponential of the dummy class path, letting it "easily reduce its loss" (paper's words: "to let the dummy easily reduce its loss"), i.e., allowing the dummy class to cover more dispersed open-set mass with a more tolerant decision territory. Ablation (Table 3) provides data backing: $\gamma$ from 1 to 3, 5-shot AUROC from 82.7 to 86.2 (86.7 with Gumbel), 1-shot from 76.4 to 78.7/78.8.
- **Why multiply the dual-path loss by $\lambda=0.1$?** The number of known class queries (N·M_Q per episode) and open-set queries ($N_U \cdot M_Q$) are comparable. If the two paths have equal weight, the dummy class's supervision signal would occupy half of the classification head's capacity; reducing it to 0.1 explicitly declares "open-set detection is an auxiliary task, closed-set few-shot accuracy is the main task and must not be eroded." In Table 1/3, D-ProtoNet's Acc is basically on par with ProtoNet (ResNet-12 5-shot 86.9 vs 85.9, Table 3), proving this weight choice guards the main line.
- **Why multiple dummy prototypes + Gumbel?** The open set is multimodal (5 unknown classes + Silence do not cluster into one group). No matter where a single dummy point is placed, it can only cover one mode. Having multiple dummy points share the workload is a natural idea, but "which dummy point a query belongs to" is a discrete choice, and hard argmax cuts off gradients. The contribution of Gumbel softmax is to relax the discrete choice into a differentiable soft choice. During training, use probability-weighted composite dummy prototypes; during inference, switch back to hard choice. This allows L dummy prototypes to naturally differentiate into different sub-modes of the open set during training. Scanning L (Table 3): 1/2/3/4/5 dummy prototypes correspond to 5-shot AUROC 85.9/86.1/86.7/86.5/86.7—saturated after 3, indicating that 3 modes are sufficient to characterize the open-set complexity of splitGSC.

### Key Technical Innovation 1: Episode-Known Dummy Prototypes (Core Mechanism)

Putting the above parts together, the "episode-known dummy prototype" is the soul of this paper: the dummy prototype is not a fixed parameter after training (compared to Proser [22]'s fixed learnable dummy classifier), but an embedding point generated on the fly by $g_\phi$ from the current N prototypes each episode, sharing the same metric space with true prototypes and entering the same softmax denominator. It rewrites "open-set detection" from an anomaly scoring problem (the route of PEELER, SnaTCHer) into an "N+1 class classification problem"—the detector is the classifier itself, requiring no additional separate pipeline, and there is only one threshold (dummy class probability vs $\delta$).

### Key Technical Innovation 2: splitGSC Benchmark Setting

There is no existing benchmark for FSOS-KWS. The splitGSC designed by this paper has three layers of consideration (Section 3.2):

- **Class-level 15/10/10 split**: From the 35 keywords in GSC v2, 15 training words (Happy, House, Bird, Bed, Backward, Sheila, Marvin, Wow, Tree, Follow, Dog, Visual, Forward, Learn, Cat), 10 validation words (digits Zero to Nine), and 10 test words (Yes, No, Up, Down, Left, Right, On, Off, Stop, go) are split. The split is by class label, with three disjoint sets, mimicking the miniImageNet [14] protocol. The reason for a fixed split is stated plainly in the paper: to "prevent possible performance variance from split changes over trials," allowing the mean variance of 5 trials to be compared credibly.
- **Test words specifically chosen from the traditional 12-class KWS command words**: This allows splitGSC's test performance to directly converse with mainstream GSC KWS literature—a word group repeatedly verified under standard settings, now re-examined in a few-shot open-set manner.
- **Validation words use digits 0-9**: Digit words are acoustically and semantically distant from command words, reducing lexical similarity leakage between the validation and test sets (this is a design intent inferred from the split choice by the author, not explicitly stated in the paper).
- **Silence class only allowed in the open set**: In real deployment, no one registers "silence" as a wake word. Background noise is always an object to be rejected. Therefore, Silence never enters the known classes, only mixes into open-set candidates. Each episode randomly draws 5 known classes without Silence, then draws the same number of open-set classes from the remaining classes (including Silence).

### Key Technical Innovation 3: RFN Input Normalization (Supporting Discovery, Not Main Mechanism)

Inspired by research on "background shortcut learning" in visual few-shot learning [34], this paper introduces "letting the model focus on the keyword itself rather than pseudo-differences between instances" into FSOS-KWS: adding a Relaxed instance Frequency-wise Normalization (RFN) module at the encoder input (from the author team's own [35, 36]):

$$\text{RFN}(x) = \lambda \cdot \text{LN}(x) + (1-\lambda) \cdot \text{IFN}(x)$$

where IFN is instance normalization along the frequency axis [37]—for each speech, each time frame, standardize the 40-dimensional mel spectrogram along the frequency dimension, wiping out absolute energy distribution differences across the entire spectrum (such as "instance color differences" like speaker timbre, channel frequency response, and recording volume); LN (Layer Normalization [38]) plays a "relaxing" role here: pure instance normalization is too harsh and might wipe out discriminative information like formant positions. So, it uses $\lambda=0.5$ to compromise with LN. The logical chain of motivation: in few-shot scenarios, support samples are extremely scarce, and the easiest solution for the model is to grab pseudo-correlated features like speaker timbre (the registered 5 utterances are all from the same person). Once the test speaker changes, performance collapses, and open-set decisions are also interfered with by timbre. Instance normalization along the frequency axis is precisely a targeted operation to erase timbre/channel color differences, equivalent to the speech version of "erasing the background, keeping only the foreground object" in the visual domain. The results in Table 4 prove this move is effective across all backbones (see Experimental Results section), and the authors even list it as one of the future research directions for FSOS-KWS.

### Technical Differences with Existing Methods

| Comparison Object | Opponent's Mechanism | Difference with D-ProtoNets |
|---|---|---|
| Proser [22] | Fixed learnable dummy classifiers after training, adapting to static closed-set OSR | Dummy prototypes are calculated on the fly each episode by the generator from the current prototype set, adapting to drifting closed sets |
| PEELER [12] | Unknown sample entropy maximization + per-class Gaussian embedding, indirectly suppressing known class probabilities to expose anomalies | Explicitly learns a dummy class representation; open-set detection = N+1 class classification, mechanism is direct and calibratable |
| SnaTCHer [24] | Runs Transformer transformations on the support set and **each query**, detecting open sets via prototype transformation consistency; heavy inference | Dummy prototype is generated only once per episode (generator is a two-layer FC with hidden dim 32); each query only calculates L=3 Euclidean distances more, inference is almost free |
| FEAT [17] | Set-to-set transformation makes support samples task-relevant, improving low-sample accuracy, but no open-set capability | Orthogonal and stackable: D-Proto+FEAT achieves AUROC 70.6/78.5 on miniImageNet (Table 2), higher than using either alone |

Another methodological difference worth pointing out: what to use for the open-set score. Existing works are divided into two camps—using softmax max probability (PEELER, OpenMax [29], counterfactual images [30]) and using unnormalized distance (SnaTCHer). This paper's stance is to use probability uniformly during training (softmax in Equation 4), but flexibly switch during inference: when combined with FEAT, unnormalized distance $-d(f_\phi(x_i), c_{N+1})$ was actually better in practice, 1-shot AUROC from 68.5 to 70.6, 5-shot from 78.2 to 78.5 (Section 4.3, main text numbers); while in Table 1, SnaTCHer's distance method collapsed on Conv4-64 (AUROC 51.1/53.1). The conclusion is that both paths have failure domains, there is no universal score, and the benefit of the dummy class mechanism is insensitivity to score choice.

## Experimental Results

### Datasets Used and Their Scales

**splitGSC (Main Experiment)**: Based on GSC v2 [5], totaling 105,829 utterances, 2,618 speakers. First, the official split (hashing audio filenames) was used to obtain 84,843 / 9,981 / 11,005 utterances for train/val/test; then filtered according to splitGSC's class-level split to obtain 22,916 / 3,643 / 4,074 utterances; finally, following the convention of [5], "Silence" samples were added to each set (quantity taken as the average number of utterances per class in that set), resulting in final **24,444 / 4,007 / 4,482 utterances**. The test set follows the GSC official test set with the class split applied, ensuring test speakers are consistent with the official protocol. Data augmentation has only one type, also standard for GSC tasks: superimposing GSC official background noise with a probability of 0.8.

**miniImageNet (Cross-Domain Validation)**: Subset of ImageNet, 100 classes, 600 84×84 images per class, split into 64/16/20 classes by convention [32]; backbone is ResNet-12 (outputting 640 dimensions), first pre-trained with a 64-class classification head with softmax (following the official implementations of FEAT and SnaTCHer), then trained for 200 epochs, 100 episodes per epoch.

**Input Features and Training Details (splitGSC)**: Each speech is 1 second, 16 kHz; 40-dimensional log mel spectrogram, frame shift 10 ms, window length 30 ms (following the settings of BCResNet [4], ensuring comparability with KWS literature). Adam optimizer with initial learning rate 0.001, decayed by 0.5 every 20 epochs, total 100 epochs, 100 episodes per epoch; training episodes are 5-way 5-shot, 5 known and 5 open-set classes, 5 queries per class; during testing, 15 queries per class, evaluating 1,000 episodes in total, reporting mean (std) of 5 trials; early stopping based on few-shot accuracy on the validation set. The dummy prototype generator is deliberately kept minimal: $g_1$ is FC-ReLU-FC, hidden dim 32; Euclidean distance; $\lambda=0.1$; $\tau_{n \neq N+1}=1, \gamma=3$; Gumbel temperature anneals from 2 to 0.5; default L=3. To ensure fairness for baselines, the authors adapted official implementations: FEAT and SnaTCHer-F's Transformer hidden dim set to 16, dropout taken as 0.5/0 (Conv4-64) and 0.6/0.1 (ResNet-12).

### Definition and Rationale for Evaluation Metrics

- **Accuracy (FSL Accuracy)**: Classification accuracy of known class queries within the N classes. Why it must be reported: The inherent risk of open-set mechanisms is that dummy classes occupy classification head capacity, dragging down closed-set accuracy. Acc is the gatekeeper metric for "not harming the main task."
- **AUROC (Threshold-Free Open-Set Detection)**: Treating "sample belongs to open set" as a binary classification problem, using dummy class probability (or distance) as the score, sweeping all thresholds to calculate the area under the ROC curve. This follows the existing protocols of PEELER and SnaTCHer for direct comparison. Why it was chosen: The decision threshold $\delta$ at deployment is essentially determined by the false alarm budget (the tolerance for false wake-ups in wake word systems is a product parameter). Accuracy at a single threshold point is not comparable across systems; AUROC integrates over thresholds, decoupling detector quality from operating points, and is the common comparable metric for FSOSR.
- Reporting format: Mean (std) of 5 trials, combined with splitGSC's fixed class split (split is not randomized), variance mainly comes from episode sampling.

### Detailed Comparison with Baseline and SOTA Methods

**splitGSC Main Results (Table 1, 5-way 1/5-shot)**, key alignment on ResNet-12 backbone:

| Model | 1-shot Acc | 1-shot AUROC | 5-shot Acc | 5-shot AUROC |
|---|---|---|---|---|
| ProtoNet | 68.3 (1.0) | 60.7 (0.7) | 85.9 (0.7) | 68.4 (1.2) |
| FEAT | 68.8 (1.1) | 65.6 (0.7) | 84.0 (0.9) | 71.0 (0.7) |
| PEELER | 65.4 (1.5) | 66.2 (0.9) | 82.4 (1.1) | 72.1 (1.7) |
| SnaTCHer-F (SOTA) | 70.4 (1.0) | 73.2 (1.0) | 84.7 (0.6) | 83.3 (0.8) |
| **D-ProtoNet, L=3** | 69.7 (1.0) | **78.8 (0.3)** | **86.9 (0.3)** | **86.7 (0.3)** |

D-ProtoNet's open-set advantage over the strongest baseline SnaTCHer-F: 1-shot AUROC +5.6 points (78.8 vs 73.2), 5-shot +3.4 points (86.7 vs 83.3), while 5-shot Acc is also 2.2 points higher (86.9 vs 84.7), and 1-shot Acc only drops by 0.7 points. The standard deviation is also generally smaller (0.3 vs 0.8-1.0), indicating better stability.

On the Conv4-64 weak backbone, the advantage is even larger: D-ProtoNet AUROC 65.9 (0.3) / 73.9 (0.7), compared to ProtoNet's 55.3 / 63.8, an increase of +10.6 and +10.1 points respectively; while SnaTCHer-F here only achieves 51.1 / 53.1 (worse than ProtoNet doing nothing), FEAT maxes at 61.1 / 65.5, PEELER 57.5 / 66.7—under weak representations, the explicit supervision of dummy classes is much more robust than indirect mechanisms relying on embedding quality like "transformation consistency," which aligns perfectly with the reality of on-device small models (KWS backbones generally have only tens of K to hundreds of K parameters).

On the KWS-specific backbone BCResNet-8 (bottom two groups of Table 1): D-ProtoNet AUROC 75.7 (0.9) / 82.3 (1.5), an improvement of +14.8 / +13.5 points over ProtoNet's 60.9 / 68.8, which is the largest relative gain in all settings. The cost is also visible: Acc 65.2 vs 66.7 (1-shot), 81.9 vs 83.1 (5-shot). On this backbone with the smallest capacity, the dummy class loss squeezes out a small amount of closed-set accuracy—this is the first manifestation of the capacity trade-off between the main task and open-set detection. The subsequent RFN experiments happen to make up for this. The paper did not run other baselines like SnaTCHer on this backbone (the paper does not report the reason; I infer it is the adaptation cost of Transformer-based bases on 256-dimensional outputs).

**miniImageNet Cross-Domain Validation (Table 2, ResNet-12)**: D-ProtoNet L=3 achieves AUROC 70.2 (0.4) / 77.8 (0.3), surpassing self-run SnaTCHer-F (69.4 / 76.4) and the three variants of SnaTCHer cited in the original paper (68.3-70.2 / 76.2-77.4). The 1-shot 70.2 is on par with the highest SnaTCHer-T cited; combined with FEAT (L=3 + FEAT), it further reaches 70.6 (0.6) / 78.5 (0.9). However, in the Acc dimension, 1-shot is only 63.4, significantly lower than FEAT's 67.1 and SnaTCHer's 67.4. The paper explains this as: FEAT/SnaTCHer's set-to-set transformations can utilize **relationships between a few support samples**, making them more robust in the extremely low sample interval (when support set has only 5 points at 1-shot); D-ProtoNet does not perform prototype transformations, spending capacity on open-set detection. This gap basically disappears at 5-shot (81.8 vs 82.3/82.4). These numbers honestly mark the boundaries of the method: the fewer the samples, the higher the opportunity cost of the dummy class mechanism.

### Findings from Ablation Experiments

**Table 3 (splitGSC, ResNet-12) breakdown of four factors**:

1. **Dummy prototype itself contributes the bulk**: Adding only dummy class training (L=3, $\gamma=1$, no Gumbel) on the ProtoNet baseline, AUROC jumps from 60.7/68.4 to 76.4 (1.1) / 82.7 (1.2), an increase of +15.7 and +14.3 points respectively (paper describes as "improvements of more than 10%"), while Acc hardly moves (68.3→69.9, 85.9→86.4). That is, the single action of "giving the open set an explicit class representation" explains the vast majority of the total gain; subsequent tricks are refinements.
2. **Role of asymmetric temperature $\gamma$**: $\gamma=1 \to 3$ (both without Gumbel), 5-shot AUROC 82.7→86.2, 1-shot 76.4→78.7. Fine scan of $\gamma$ $\{1, 2, 3, 5, 10\}$ (all with Gumbel) yields 76.8 / 78.3 / 78.8 / 78.7 / 79.1 (1-shot) and 82.2 / 85.9 / 86.7 / 86.4 / 86.7 (5-shot)—clear rise from 1 to 3, plateau after 3 ($\gamma=10$'s 1-shot 79.1 is the highest single point in the scan, but the paper judges "seems to converge near $\gamma=3$"; from the std of 0.5, this single-point advantage is within noise range). Conclusion: Temperature compensation is basically maxed out at 3x.
3. **Role of Gumbel softmax**: Adding Gumbel under $\gamma=3$, 5-shot AUROC 86.2→86.7, Acc 86.5→86.9; adding Gumbel under $\gamma=1$ is 82.7→82.2 (5-shot), a small negative effect. Overall, it is a small but stable positive contribution, and it makes end-to-end training of multiple dummy prototypes possible.
4. **Saturation point of dummy prototype count L**: L=1/2/3/4/5 corresponds to 1-shot AUROC 78.7 / 78.5 / 78.8 / 78.8 / 78.4 and 5-shot 85.9 / 86.1 / 86.7 / 86.5 / 86.7—rise from 1 to 3, no further gain at 4 and 5 (paper's words: "converged at L=3"). The effective number of modes in the open set on this benchmark is around 3; creating more dummy points is just wasting capacity.

**Table 4 (Universal Gain of RFN)**: Adding RFN at the encoder input, all backbones, all models show consistent improvement. The most convincing three groups: On ResNet-12, D-ProtoNet+RFN reaches 72.6 (0.5) Acc / 80.3 (1.0) AUROC (1-shot) and 88.3 (0.6) / 87.8 (0.9) (5-shot), which are the highest points in the entire paper, pulling 1-shot Acc from 69.7 to 72.6—**RFN not only improves open-set detection but also pays back the debt D-ProtoNet owed in closed-set accuracy**; On BCResNet-8, D-ProtoNet+RFN's Acc recovers from 65.2/81.9 to 69.7/85.5, AUROC to 78.3/85.4, directly erasing the erosion of dummy class loss on KWS backbone closed-set accuracy; Even the simplest ProtoNet+RFN improved from 43.2/55.3 to 46.3/57.3 (1-shot) on Conv4-64. From this, the paper makes a judgment beyond the main mechanism: "erasing undesirable instance discrepancy is highly important in FSOS-KWS"—erasing instance differences at the speaker/channel level is a highly important universal component for few-shot open-set KWS, and it is listed as a future research direction.

## Main Contributions

1. **Problem Formalization**: Defines and proposes for the first time the setting of Few-Shot Open-Set Keyword Spotting (FSOS-KWS), pointing out that "open set drifts with episodes" is the essential difficulty distinguishing it from traditional OSR and ordinary FSL (Figure 1).
2. **Benchmark Contribution**: splitGSC—fixed class-level 15/10/10 split eliminates trial variance; test words align with traditional 12-class GSC KWS for easy dialogue with mainstream literature; Silence only enters the open set, fitting deployment reality. It provides a reusable protocol for subsequent FSOS-KWS work.
3. **Method Contribution**: Episode-known dummy prototype mechanism (generator with DeepSets structure synthesizes dummy class centers on the fly from the current episode's prototypes), paired with asymmetric temperature $\gamma$ (allowing a single-point dummy class to cover multimodal open sets without distorting the embedding space), dual-path weighted loss $\lambda=0.1$ (protecting the closed-set main task), Gumbel softmax multiple dummy extension (differentiable dummy prototype division of labor). The inference overhead of the entire additional mechanism is close to zero (one small FC generation per episode + L distance calculations per query), compatible with the constraints of always-listening on-device KWS.
4. **Empirical Contribution**: AUROC leads comprehensively on three backbones of splitGSC (ResNet-12 78.8/86.7, Conv4-64 65.9/73.9, BCResNet-8 75.7/82.3, Table 1), with larger advantages on weak backbones; reaches SOTA level open-set detection on miniImageNet (70.2/77.8, 70.6/78.5 after combining with FEAT, Table 2), proving the domain-independence of the mechanism; and empirically clarifies that the two open-set scoring routes of "distance score vs. probability score" each have failure domains.
5. **Discovery Contribution**: RFN input normalization is consistently effective across all FSOS-KWS backbones (Table 4), identifying "instance pseudo-differences (such as speaker timbre) are an important shortcut risk for few-shot open-set speech tasks" as a problem independent of the main mechanism.

## Limitations and Future Work

### Technical Limitations of the Method

- **Closed-set accuracy concession in the extremely low sample interval**: On miniImageNet 1-shot, Acc is 63.4, lagging behind FEAT (67.1) and SnaTCHer (67.4) by about 4 points (Table 2). The root cause is that D-ProtoNet does not have set-to-set transformations to model relationships between support samples, and when 1-shot, the support set information is extremely sparse, and the capacity diverted by dummy class supervision cannot be compensated. There is a clear opportunity cost curve between "open-set detection" and "extremely low sample classification" in the method, basically catching up only after 5-shot.
- **Ceiling of single-point (or three-centroid) approximation of multimodal open sets**: No matter how dummy prototypes are generated, they are just discrete points in the embedding space. The open set of splitGSC is a finite combination of 25 words + Silence, and L=3 saturates (Table 3); in real deployment, the open set is "all human speech," with modalities far exceeding 3. Whether the coverage capability of point-like dummy classes can extrapolate is unverified. Theoretically, a more natural approach would be dummy distributions (e.g., Gaussian dummy classes) or multi-dummy structures clustered by unknown sub-classes.
- **Wide hyperparameter space and some uncalibrated**: Five knobs: $\gamma, \lambda, L$, Gumbel annealing interval, inference threshold $\delta$. The paper only ablates $\gamma$ and L; $\lambda$ only gives the default value 0.1 (paper does not report $\lambda$ sensitivity); the deployment-period selection process for $\delta$ (how to calibrate according to false alarm budget) is completely not given (paper does not report). It is doubtful whether sweet spots like $\gamma=3, L=3$ still hold when switching to a dataset with different open-set complexity.
- **Lack of quantification of overhead**: The paper qualitatively argues that the generator is extremely small (FC-ReLU-FC, hidden dim 32) and contrasts it with SnaTCHer running Transformer per query, but the FLOPs, parameter count, on-device latency, and power consumption of the entire system are not reported by the paper—for an on-device KWS work bearing the Qualcomm name, this is a significant gap.
- **Sensitivity to backbone capacity**: On BCResNet-8, dummy class training directly causes Acc to drop (65.2 vs 66.7, 81.9 vs 83.1, Table 1), indicating that small-capacity backbones cannot handle dummy class supervision without additional normalization. The method is not "plug-and-play boost"; it needs supporting components like RFN to hold the bottom.

### Shortcomings in Experimental Design

- **Single and in-distribution open-set sources**: Unknown classes are only drawn from the remaining 25 words of the same vocabulary plus Silence, all isolated English command words, 1-second slices, with recording conditions consistent with known classes. The open set in real wake word scenarios includes conversational speech, media audio, and cross-lingual content, with much larger inter-class gaps and intra-class diversity. Under the current protocol, "open-set detection" is more like "held-out class detection of closed-set words," and the reference value for deployment is discounted.
- **Offline episode-based evaluation disconnected from streaming deployment**: There are no streaming false alarm/false rejection rates (e.g., false wake-ups per hour, FRR@FAR operating point curves at the wake word level), only episode-level AUROC. The operating point metrics most concerned in wake word engineering are absent.
- **Weak statistical strength**: 5 trials, reporting mean ± std; although the fixed split suppresses split variance, differences of less than 1 point on AUROC (e.g., 79.1 for $\gamma=10$) are hard to determine as significant.
- **Speaker dimension not discussed**: The GSC official split hashes filenames and does not guarantee that speakers do not overlap between train/test. In the few-shot open-set setting, speaker leakage will simultaneously inflate Acc and AUROC (the paper does not report speaker non-overlap, nor does it conduct supplementary experiments with disjoint speakers).
- **Incomplete baseline coverage**: On BCResNet-8, the backbone closest to on-device deployment, only ProtoNet was compared (Table 1), without FEAT/PEELER/SnaTCHer comparisons. This is exactly where the most relevant backbone lacks direct confrontation with SOTA.
- **Single robustness**: Augmentation is only superimposing background noise with probability 0.8, without standard pressure tests for KWS such as far-field reverberation, additive reverberation, or multi-noise superposition.

### Possible Future Improvement Directions

- **Along the paper's recommended direction**: Advance "erasing undesirable instance discrepancy" as an independent research line for FSOS-KWS (explicitly listed as future research in the conclusion section)—RFN is only the simplest form of frequency-axis instance normalization. Stronger speaker disentanglement and channel-invariant representations are worth verifying on this benchmark.
- **Deepening combination with set-to-set transformations**: D-Proto + FEAT has been verified as complementary (Table 2), but it is just a simple assembly; using Transformer prototype transformation as input to the dummy generator (generate dummy prototypes after transformation), or integrating consistency checks like SnaTCHer during inference, are low-hanging improvements.
- **Distributionalization of dummy prototypes**: From points to distributions (anisotropic Gaussians, or automatically clustering unknown spaces with multiple dummy prototypes), to cover the multimodality of real open sets, and incidentally provide a more physically meaningful threshold calibration method.
- **Evaluation protocols towards real deployment**: Integrate into query-by-example on-device systems (the author team's own [6] is a ready-made carrier), report false wake-ups/false rejects per hour on streaming long audio, and establish the mapping relationship between threshold $\delta$ and false alarm budget—this is a necessary step from a benchmark paper to a deployable system.
- **Harder open-set protocols**: Introduce large-vocabulary continuous speech as negative samples, cross-lingual and media audio, to construct an "open-world version of splitGSC" to test the failure boundaries of point-like dummy classes under nearly infinite open sets.

**Appendix: Terminology Quick Reference**

- **Episode**: The basic unit of few-shot evaluation, drawing N classes once, each with M support samples and several query samples, simulating "register and use."
- **Support / Query Set**: The support set is the labeled samples used for registration; the query set is the samples to be classified or judged as open-set.
- **Open-Set**: The set of classes that do not belong to any known class and have no support samples during evaluation; in this setting, it changes with the class sampling of each episode.
- **AUROC**: Area under the ROC curve, sweeping the true positive rate-false positive rate trade-off under all decision thresholds, a threshold-free open-set detection quality metric.
- **ProtoNets**: A metric learning few-shot method that uses the mean of intra-class sample embeddings as prototypes and classifies by distance softmax.
- **DeepSets**: A neural network structure paradigm that maintains permutation invariance for set inputs (element-wise transformation + symmetric aggregation).
- **Gumbel Softmax**: A reparameterization technique that relaxes discrete argmax sampling into differentiable soft sampling, with temperature annealing controlling the hardness.
- **RFN (Relaxed instance Frequency-wise Normalization)**: An input normalization module that performs instance normalization along the mel frequency axis and relaxes it with layer normalization, used to erase instance spectral color differences at the speaker/channel level.
