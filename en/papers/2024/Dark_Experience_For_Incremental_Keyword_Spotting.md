## Problem Statement

### Problem Background and Domain Pain Points

Keyword Spotting (KWS) is the task of identifying specific keywords from an audio stream. It is a core component of voice entry points such as Apple Siri and Google Home, and is almost always deployed on edge devices. The paper repeatedly emphasizes two realistic constraints: First, KWS systems are often always-on and must run continuously on small models with limited computing power and storage. Consequently, existing deep learning KWS systems (from Chen et al. 2014, who first applied DNNs to KWS classification tasks, to Choi et al. 2019’s TC-ResNet) generally train on a **limited set of keywords** to reduce computational and memory overhead. Second, the real world does not accommodate this limited set: after deployment, models will continuously encounter unfamiliar keywords from new domains (e.g., manufacturers supporting custom wake words, adding new languages, or adding new command words). The most common industrial response is few-shot fine-tuning—adapting the model to the new scenario using a small amount of target domain data.

The pain point lies here: few-shot fine-tuning frequently leads to **catastrophic forgetting** (a phenomenon described by McCloskey and Cohen as early as 1989 in connectionist networks)—new knowledge gradually replaces learned old knowledge. As the model improves on new keywords, its performance on the original source domain data significantly deteriorates. For always-on edge KWS, this is fatal: you cannot forget all the keywords you previously recognized well just to learn a new wake word. Continual Learning (CL) was born to solve this problem, with the goal of continuously acquiring new knowledge while retaining and reusing old knowledge. However, applying CL to edge KWS adds a third constraint—lightweight devices cannot afford the storage and parameter overhead that grows with the number of tasks.

### Specific Deficiencies of Existing Methods

The paper categorizes existing countermeasures into several lines and points out their defects in the edge KWS scenario one by one:

- **Direct few-shot fine-tuning adaptation**: Structurally, there is no anti-forgetting mechanism. When new task data arrives, the old class boundaries are collapsed. In the paper's experiments, the Finetune baseline achieved an average accuracy of only 26.80%, while the joint training upper bound was 95.70% (Table I), a gap of 68.90 percentage points—this huge落差 itself is quantitative evidence that "fine-tuning causes forgetting."
- **Progressive CL (e.g., Huang et al., ICASSP 2022)**: This belongs to the task-incremental paradigm, relying on task-ID auxiliary information during inference to determine which task is currently active. Moreover, the required storage grows with the number of tasks. The paper points out that these two limitations make it **impractical** for lightweight devices: in real deployments, task-IDs are not always available, and storage cannot grow infinitely. Therefore, this paper shifts to **Class-Incremental Learning (CIL)**, which does not rely on task-IDs—although CIL has greater potential in real applications, it remains a less explored direction in the KWS field.
- **Rehearsal/replay methods, such as Naive Rehearsal (NR)**: Randomly stores old data in a buffer and mixes it with an equal amount of new data for training. It has two defects: it only stores "samples + one-hot labels," losing the inter-class relationship information implicitly contained in the output distribution (i.e., dark knowledge, a concept proposed by Hinton et al.); and it mixes replay data and current task data into a unified training set, without independent weight allocation for old and new supervision signals. In Table I, NR achieves an ACC of only 46.45% with buffer=200, only about 20 percentage points higher than Finetune, indicating that naive rehearsal is inefficient.
- **Self-distillation methods**: Use snapshots of models from early tasks as teachers and the current model as students, comparing the responses of the two models on current task data to judge whether knowledge is retained. The defect is that it **requires saving the complete parameters of past models**—this is a parameter-level storage overhead (in the paper's Table I, the RK method using self-distillation has 129.96K parameters, approximately twice the base model's 64.48K); moreover, this distillation usually only occurs near task boundaries and uses only current task data for comparison, failing to cover the entire training process.
- **Regularization methods, such as EWC / RWalk**: Measure parameter importance via the Fisher Information Matrix (RWalk adds path integration on top), applying dynamic regularization to important parameters. The defect is that the Fisher matrix itself is of the same magnitude as the parameters, effectively doubling the model's storage requirements (Table I: EWC and RWalk both have 129.96K parameters vs. 64.48K); performance is only moderate (EWC 75.23%, RWalk 87.53% with buffer=500).
- **Latest methods for incremental KWS**: RK (Rainbow Keywords, Interspeech 2022) uses a diversity-based sampler to ensure per-class diversity and combines it with self-distillation, with 129.96K parameters; DM3 (Interspeech 2023) uses dual memory components to retain old task memory and multi-modal components to capture invariant representations, with 193.44K parameters (approximately three times the base). The paper's criticism is that these methods **focus mainly on retaining old task knowledge, ignoring richer contextual information within speech segments**, and do so at the cost of doubling parameters or storage.
- **Dark Experience Replay (DER, Buzzega et al., NeurIPS 2020)**: Stores past logits and distills "experience" over the entire training trajectory, considered a strong and simple solution—but its application in the KWS field has **never been explored**. This is the entry point of this paper.

### Key Challenges to be Solved by This Paper

In summary, this paper aims to simultaneously satisfy a set of mutually constraining constraints: (1) Suppress catastrophic forgetting in a **task-ID-independent** class-incremental setting, where the model must be able to recognize all learned keywords; (2) **Do not increase model parameters**—base parameters remain at 64.48K, exactly consistent with Finetune/Joint (Table I Parameters column), which is a hard metric for edge deployment; (3) The memory buffer is **bounded** and guarantees equal probability for each data point to enter the pool under the premise of **unknown stream length**; (4) In real streaming scenarios, **task boundaries are often vague**, and the method must work without relying on clear boundaries; (5) Achieve a balance between "retaining old knowledge" and "adapting to new tasks," especially preventing collapse in mid-term tasks (the paper's Fig. 2 shows that many methods significantly degrade on mid-term tasks like T2, T5). These five constraints are the source of every design decision in the methodology section.

## Methodology

### Overall Architecture Design and Design Motivation

The overall framework of DE-KWS is shown in the paper's Fig. 1: a memory buffer $M^{\tau_{t-1}}$ is deployed on the main training line, recording experience triplets up to the previous task—**input sample + output logit + true label**. The data flow during training is: streaming data from the current task is first fed into the backbone network (TC-ResNet-8), the backbone outputs logits, and the classification loss $L_C$ is calculated on the current task; then, streaming data, labels, and corresponding logits are written to the buffer via **reservoir sampling**; then, two small batches are independently sampled from the buffer, one batch $(x', y')$ calculates the replay loss $L_R$, and one batch $(x'', z'')$ calculates the distillation loss $L_D$; the three losses are weighted and summed to update the model.

There are four interlinked design motivations behind this architecture:

First, **why store logits instead of model snapshots**. Self-distillation requires saving the complete parameters of past models to act as teachers, whereas logits are just the output vectors of each sample from the previous forward pass. Storing logits has three benefits: the memory cost is far lower than saving the entire set of model parameters; input audio samples can be directly reused from the replay process's stored copies, requiring no additional copying; most importantly, logits embed **dark knowledge** that true labels cannot provide—the model's relative confidence in each class, i.e., inter-class relationship information. Hard labels only say "this is cat," while logits also say "this looks more like cat and less like off, with moderate similarity to stop." These soft structures are anchors that prevent class boundary drift.

Second, **why continuously sample and use logits throughout the entire training process, rather than only at the end of a task**. This is the differentiated point explicitly emphasized by the paper: continuous sampling can capture the model's progressive evolution process—the logits in the buffer come from different moments on the training trajectory. Distilling them is equivalent to constraining the current model to maintain response consistency with "itself at various historical stages," thereby producing smoother transitions between tasks, stronger adaptability, and reducing the risk of catastrophic forgetting (especially in mid-term tasks), while making the method **not dependent on task boundaries**. This forms an essential difference from the conventional practice of "storing logits only once at the end of a task and performing distillation only at task boundaries."

Third, **why use reservoir sampling**. The total length of the real data stream is unknown. Reservoir sampling (Vitter 1985) ensures that each data point has an **equal chance** of being stored in the buffer, keeping old and new task data roughly uniform in the pool, avoiding systematic bias due to order effects.

Fourth, **why separate replay and distillation into two independent loss terms rather than mixing them into one training set**. NR-style mixed training allows old and new supervision signals to share the same cross-entropy weight, making it impossible to independently adjust the intensity of "remembering old samples" and "maintaining old responses." DE-KWS splits them into $L_R$ and $L_D$ and assigns weights $\alpha$ and $\beta$ respectively. Ablation experiments (Table II) prove that this allocation is informative: increasing $\beta$ (distillation weight) yields better results.

### Mathematical Principles of the Core Algorithm

**Problem Formulation**: The system learns from a sequence of tasks $\{\tau_1, \tau_2, \dots, \tau_T\}$, where input samples $x$ and labels $y$ for task $\tau_t$ follow distribution $D_t$. The goal of CIL is to train model $f(x; \theta)$ so that it can continuously adapt to new data while retaining memory of old data, pursuing optimal overall average accuracy (Equation 1):

$$ \arg\min_\theta \sum_{t=0}^{T} \mathbb{E}_{(x,y)\sim D_t} [L_{CE}(y, f(x; \theta))] $$

where $L_{CE}$ is cross-entropy. The paper specifically points out: considering data storage costs and time efficiency, **full access to all old task data and从头 joint training is unrealistic**—this is why the upper bound method Joint training can only serve as a reference and not as a solution; while fine-tuning only on new data leads to catastrophic forgetting. Equation 1 is the formal expression of "wanting both."

**Replay Loss** (Equation 2):

$$ L_R = \mathbb{E}_{(x',y')\sim M^{\tau_{t-1}}} [L_{CE}(y', f(x'; \theta))] $$

where $(x', y')$ is a small batch sampled from the buffer $M^{\tau_{t-1}}$ (the buffer state before the current task $\tau_t$ begins, see Fig. 1 caption). Note that here the current model parameters $\theta$ are used for the forward pass to calculate CE—the essence of replay is to re-expose old samples to the current model, supervised directly by true labels.

**Distillation Loss** (Equation 3):

$$ L_D = \mathbb{E}_{(x'',z'')\sim M^{\tau_{t-1}}} [L_{MSE}(z'', h(x''; \theta))] $$

where $L_{MSE}$ is mean squared error, $h(\cdot; \theta)$ is the network's **pre-softmax output** (i.e., logits), and $(x'', z'')$ is another small batch of data pairs sampled from the buffer, where $z''$ is the historical logit saved earlier. This loss constrains the current model's response to old samples to be consistent with historical logits, thereby retaining old task memory. Two technical details are worth noting: first, unlike classic knowledge distillation which uses KL divergence with temperature-softened outputs, here MSE is directly applied to raw logits, requiring no temperature hyperparameter (following DER's approach), making implementation simpler; second, the "teacher" for distillation is not a frozen old model, but historical output snapshots scattered across various moments of the training trajectory—the teacher itself is evolving and non-unique.

**Total Objective** (Equation 4):

$$ L_{DE-KWS} = L_C + \alpha \cdot L_R + \beta \cdot L_D $$

$\alpha$ and $\beta$ are **hyperparameters** balancing the three losses, with their optimal values determined by ablation experiments (Table II: $\alpha=0.5, \beta=1.0$ is optimal).

**Reservoir Sampling Mechanism**: The paper cites Vitter (1985)'s standard reservoir sampling to maintain the buffer, ensuring equal probability for each data point to enter the pool when stream length is unknown, but **the paper does not report** specific implementation details such as replacement probability formulas. According to the standard semantics of reservoir sampling (a common mechanism in this method's literature, not an original expansion of this paper): when the buffer is not full, data is written directly; when full, the $i$-th arriving sample replaces a random sample in the pool with probability $M/i$ ($M$ is pool capacity), otherwise it is discarded. This ensures that samples in the pool at any moment approximately constitute a uniform sample of the historical stream.

**Training Pipeline Summary** (Five steps in paper Section II-B-3): Streaming data forward pass $\rightarrow$ calculate current task loss $L_C$ $\rightarrow$ streaming data/labels/logits fill buffer via reservoir sampling $\rightarrow$ sample twice from buffer to construct $L_R$ and $L_D$ independently $\rightarrow$ merge three losses to update model. Note that the logits used to fill the buffer are calculated by the **model currently being trained**, so the pool naturally mixes outputs from when the model was "young" and when it was "mature." This is exactly how "dark experience covering the entire training trajectory" is implemented.

### Key Technical Innovation 1: Triplet Dark Experience Buffer (Sample + Label + Logit)

Traditional replay methods store pairs (sample, label), and self-distillation methods store model snapshots. DE-KWS's buffer stores triplets: sample, label, logit. The three types of information in the triplet each play their role—true labels help the model **remember old samples** via experience replay (the "what is it" in a classification sense), while logits ensure the model **retains response patterns to old data** (the "what is it similar to" in a relational sense). These two types of memory are complementary: label supervision can correct logit drift, while logit distillation stabilizes the inter-class geometric structure that label supervision cannot cover.

The comparison in storage costs can be read directly from the Parameters column in Table I: self-distillation methods like RK, which need to save model snapshots, have 129.96K parameters; DM3, with dual memory and multi-modal components, has 193.44K parameters; EWC/RWalk, which need the Fisher matrix, have 129.96K parameters. In contrast, DE-KWS always remains at 64.48K—**zero additional model parameters**, exactly the same as the baseline Finetune/Joint. The paper defines the Parameters metric as "the total parameters of the model under this strategy," without breaking down the composition of additional parameters for each method. From the numerical relationships (129.96K is approximately twice 64.48K, 193.44K is approximately three times), it is reasonable to infer that these numbers include the states required to be saved by their respective strategies (such as importance matrices or teacher snapshots), but this is the author's inference, not explicitly stated in the paper. Additionally, it should be pointed out that logits themselves have storage overhead (a float vector of dimension equal to the number of classes per sample, i.e., 30-dimensional on GSC), but this is counted as buffer storage, not model parameters, and the paper does not report quantitative figures for this part.

### Key Technical Innovation 2: Continuous Sampling Throughout Training, Breaking Dependency on Task Boundaries

The distillation timing in conventional incremental learning is "at the moment the task ends": a batch of data/model is saved at the end of a task, and distillation is performed in the next task. This implicitly assumes two strong conditions—task boundaries are clearly known, and old knowledge only needs to be protected at boundaries. DE-KWS spreads the sampling and use of logits across the **entire training process**: data flowing through each batch may enter the pool via reservoir sampling, and distillation loss is calculated for every batch.

This design brings two direct consequences. First, the method **does not depend on task boundaries**—the paper explicitly states this makes it "more suitable for real-world incremental learning scenarios where task boundaries are often vague." Second, the logits in the buffer record the model's **progressive evolution**. Distillation is equivalent to constraining the current model to remain consistent with the entire historical trajectory, resulting in smoother transitions between tasks. The paper supports this with the mid-term task performance in Fig. 2: RK and RWalk show significant drops at T2 (dropping to 65.78% and 66.87% respectively after learning all six tasks), and RWalk collapses to 54.28% at T5, while DE-KWS achieves 78.84% and 91.24% at the same positions (Fig. 2). The paper's explanation is that logits, as dark experience, act as a **regularizer**—helping the model retain key features of early tasks while adapting to new tasks. Continuous sampling captures model evolution and stabilizes internal representations, thereby reducing the risk of forgetting in mid-term tasks.

### Key Technical Innovation 3: Decoupled Three-Component Loss and Ablation Support for Hyperparameters

The structure $L_C + \alpha \cdot L_R + \beta \cdot L_D$ explicitly separates the three goals of "learning new," "remembering old samples," and "retaining old responses." The ablation in Table II yields two informative conclusions: First, $\alpha=0.5, \beta=1.0$ outperforms $\alpha=1.0, \beta=0.5$ and $\alpha=0.5, \beta=0.5$ (ACC 89.24% vs. 87.95% and 88.38%), indicating that **the weight of the distillation component needs to be higher than that of the replay component** to achieve the most effective trade-off—dark experience is a more important anti-forgetting signal than hard label replay; Second, removing distillation (w/o Distillation) drops ACC from 89.24% to 84.84% (-4.40 percentage points), and BWT worsens from -0.034 to -0.056; removing replay (w/o Rehearsal) only drops ACC from 89.24% to 88.02% (-1.22 percentage points), and BWT changes slightly from -0.034 to -0.036. The contributions of the two are highly asymmetric: distillation is the main force, and replay is auxiliary.

Why is the harm of removing replay not significant? The author's analysis is: the distillation loss is already calculated on buffer samples (the $x''$ in Equation 3 comes from the same buffer), so old samples are still participating in training, just with supervision signals changed from hard labels to historical logits; however, once distillation is lost, only hard label replay remains, and the inter-class geometric structure loses its anchor, causing forgetting to intensify immediately. Conversely, although hard label replay contributes a smaller numerical value, it plays the role of **preventing the accumulation of logit staleness**—logits in the pool come from different (often weaker) historical stages of the model. Without periodic correction by true labels, distilling only old logits may gradually amplify errors. This complementary mechanism is the value of the triplet design.

### Technical Differences with Existing Methods

Compared one-by-one with nine reference methods (all baselines set in paper Section III-C): **Finetune** is the lower bound with no protection (ACC 26.80%); the difference between DE-KWS and it is the entire chain. **Joint** is the upper bound assuming all data is visible (95.70%); it is not a deployable solution but a performance ceiling. **NR** stores samples for random replay but mixes training and lacks dark knowledge—the difference between DE-KWS and it is "triplet + separated loss + continuous sampling," pulling the ACC for buffer=500 from 55.30% to 89.24% (Table I) with the same 64.48K parameters. **iCaRL** uses nearest-class-mean exemplar classification rules plus a distillation term, with 75.29K parameters, achieving 84.72% with buffer=500—DE-KWS does not need exemplar classification rules, replacing its distillation term with logit MSE, achieving 4.52 percentage points higher under the same conditions with fewer parameters. **EWC/RWalk** rely on parameter regularization to resist forgetting, requiring importance matrices that double parameters to 129.96K—DE-KWS carries memory in data space (buffer) rather than parameter space (regularization), with zero parameter growth. **BiC** adds a bias correction layer to balance old and new tasks, achieving 79.96% with buffer=500—DE-KWS introduces no extra layers. **RK** (previous work in incremental KWS, Interspeech 2022) relies on diversity sampling plus self-distillation, requiring saving teacher snapshots (129.96K)—DE-KWS replaces saving models with saving logits, halving parameters and achieving 4.28 percentage points higher ACC with buffer=500 (89.24% vs. 84.96%). **DM3** (Interspeech 2023) uses dual memory plus multi-modal, 193.44K—DE-KWS uses a single buffer, one-third the parameters, and achieves 1.14 percentage points higher ACC (89.24% vs. 88.10%). **DER** (NeurIPS 2020) is the source of this paper's ideas. DE-KWS's differentiation lies in introducing DER to the KWS domain and strengthening the operation of "continuously sampling and using logits throughout the training process" (the original DER paper did not emphasize the streaming semantics of breaking free from task boundaries in buffer filling/placement), while providing systematic empirical results for the KWS scenario.

## Experimental Results

### Datasets Used and Their Scale

Experiments are conducted on the Google Speech Command dataset v1 (GSC)—a widely used short audio collection in the KWS field, containing **64,727 one-second long utterances, 30 different command words**, all sampled at 16 kHz (paper Section III-A). Following the partitioning methods of previous works RK and DM3: 80% training, 20% validation. Note that the paper's description is a train/validation binary split, **not reporting** an independent test set; evaluation is suspected to be performed directly on the 20% validation set (see Limitations discussion).

Features and Backbone: Input is 40-dimensional MFCC (MFCC = 40); the backbone uses **TC-ResNet-8**—a lightweight convolutional network designed by Choi et al. (Interspeech 2019) for edge KWS, containing 3 residual blocks (composed of 1D temporal convolutional layers, batch normalization layers, and ReLU activation layers), with channel numbers for each layer (including the first convolutional layer) as $\{16, 24, 32, 48\}$, totaling 64.48K parameters (Table I Parameters column). The motivation for choosing this backbone is straightforward: it is the "standard small backbone optimized for resource-constrained devices" for KWS. Only incremental methods validated on it can represent edge feasibility.

Training Configuration (paper Section III-E): By default, data is randomly split into **6 tasks—the first task has 15 keywords, and the remaining 15 words are evenly divided into 5 tasks, with 3 words per task**; two finer partitions are also set for stress testing: 11 tasks (first task 10 words, remaining tasks 2 words each) and 21 tasks (first task 10 words, remaining tasks 1 word each). Optimizer is Adam, learning rate 0.1, batch size 128, trained for 50 epochs. Buffer size varies among $\{200, 500, 1000, 1500\}$ to examine its impact.

### Definition and Rationale for Evaluation Metrics

Three metrics (paper Section III-D): **ACC (Average Accuracy)**—the average accuracy across all learned tasks, the core metric for CIL, directly measuring "how much is remembered after learning all tasks"; **BWT (Backward Transfer)**—describes the impact of learning new tasks on old tasks. A negative value indicates that learning new tasks harms old tasks, with larger absolute values indicating more severe forgetting (this metric comes from Lopez-Paz and Ranzato's GEM work). The reason for choosing it is that ACC may mask the dynamic of "learning while forgetting," while BWT isolates and quantifies forgetting—Finetune's BWT is -0.379, while DE-KWS with buffer=1500 is -0.026, a difference of over 14 times, reducing forgetting by an order of magnitude (Table I; here the multiple is calculated by the author as -0.379/-0.026 $\approx$ 14.6); **Parameters**—the total parameters of the model under this strategy, measuring edge deployment cost. The reason for choosing it is self-evident: one of the paper's core selling points is "not increasing model size." Two points need to be pointed out: the paper does not give the exact mathematical definition formula for BWT (its standard definition is the average of the difference between accuracy at the end of each task and accuracy immediately after learning it; here it is the common definition in the literature); Parameters only counts model parameters, not buffer storage, while the buffer (samples + logits) is precisely the necessary overhead of this method. This accounting favors replay-based methods (see Limitations).

### Detailed Comparison with Baseline Methods and SOTA

Main comparison is in Table I (including buffer-free, 200, 500, 1000, 1500 five tiers; methods are not run across all tiers, BiC is only reported at 500, EWC only at buffer-free, DE-KWS only above 200):

**buffer-free tier**: Finetune 26.80% (BWT -0.379, Parameters 64.48K) is the lower bound; Joint 95.70% (Parameters also 64.48K) is the upper bound; EWC 75.23% (BWT -0.105, Parameters 129.96K)—regularization methods without buffers only show moderate performance and double parameters.

**buffer=200 tier**: NR 46.45% (-0.219), iCaRL 78.81% (-0.091, 75.29K), RWalk 80.38% (-0.082, 129.96K), RK 77.05% (-0.088, 129.96K), DM3 83.35% (-0.058, 193.44K), **DE-KWS 85.13% (-0.048, 64.48K) leads**—1.78 percentage points higher than DM3 with only one-third the parameters, and 8.08 percentage points higher than RK with half the parameters.

**buffer=500 tier**: NR 55.30%, iCaRL 84.72%, RWalk 87.53%, BiC 79.96%, RK 84.96%, DM3 88.10%, **DE-KWS 89.24% (BWT -0.034, 64.48K) is still first**—1.14 percentage points higher than the second-best DM3 (1/3 parameters), 1.71 percentage points higher than the third RWalk (approx. 1/2 parameters), and BWT is also the best in the field (-0.034 vs. DM3's -0.043, RWalk's -0.047).

**buffer=1000 / 1500 tier**: DE-KWS continues to monotonically improve to 90.38% (-0.029) and 91.17% (-0.026), gradually approaching the joint training upper bound of 95.70%. Marginal returns diminish significantly (author's calculation: 200$\rightarrow$500 increases by 4.11 percentage points, 500$\rightarrow$1000 increases by 1.14, 1000$\rightarrow$1500 increases by only 0.79), indicating that a buffer of about 500~1000 has captured most of the available old knowledge; even at 1500, there is still a 4.53 percentage point gap from the upper bound. This gap is essentially the information difference between "only seeing bounded old samples" and "all data visible."

**Per-task perspective** (Fig. 2, buffer=500, rows are "after learning how many tasks," columns are accuracy matrix for task numbers): After learning all six tasks, DE-KWS maintains 80.13% on the first task T1 (initially 96.82% after learning, a drop of 16.69 percentage points, retention rate approx. 82.7%, author's calculation), far better than EWC's 60.53% (dropped from 95.84% by 35.31 percentage points); the advantage in mid-term tasks is more obvious—on T2, DE-KWS 78.84% vs. RK 65.78%, RWalk 66.87%; on T5, 91.24% vs. RWalk 54.28%, EWC 49.20%. An honest detail is: in maintaining the oldest task T1, RWalk (83.75%) is actually slightly higher than DE-KWS (80.13%). DE-KWS's overall advantage comes from **balanced performance across mid-term and recent tasks** (final six tasks are 80.13/78.84/82.05/75.15/91.24/95.87) rather than extreme performance at a single point. Another noteworthy phenomenon is the accuracy on the newest task: when DE-KWS finishes T6, the accuracy for that task is 95.87%, lower than EWC's 98.78%, RWalk's 98.94%, iCaRL's 98.89%, RK's 98.66%—this is a direct reflection of the stability-plasticity trade-off: distillation regularization constrains the model's plasticity, making learning new tasks slightly slower and duller, but in exchange for significant retention of old tasks, the net gain in average (ACC) is positive.

**Task Number Stress Test** (Fig. 3): Increasing the number of tasks to 10 (Fig. a) and 20 (Fig. b) tiers, ACC for all methods decreases with the number of tasks, but DE-KWS continues to lead other competitive baselines (NR, EWC, RK, iCaRL, BiC) in both settings, maintaining advantages in more challenging long task sequences, verifying the method's robustness to task number expansion. Note that Section III-E of the main text writes "11-task/21-task" partitions, while Fig. 3 caption writes "10-task/20-task scenario." The two expressions are inconsistent (see Limitations).

### Findings from Ablation Experiments

Table II (component and hyperparameter ablation under buffer=500 setting) yields three sets of findings:

**Hyperparameter Combinations**: $\alpha=1.0/\beta=0.5 \rightarrow$ ACC 87.95%, BWT -0.039; $\alpha=0.5/\beta=0.5 \rightarrow$ 88.38%, -0.037; **$\alpha=0.5/\beta=1.0 \rightarrow$ 89.24%, -0.034 (optimal on both metrics)**. The pattern is clear: the gain from increasing distillation weight $\beta$ from 0.5 to 1.0 (+0.86 percentage points) is greater than the loss from decreasing replay weight $\alpha$ from 1.0 to 0.5. The optimal configuration is "light replay, heavy distillation." The paper's explanation is that under this allocation, the model achieves the most effective trade-off—the information density of dark experience signals for KWS incremental learning is higher than that of hard label replay.

**Component Removal**: Removing distillation (w/o Distillation, under $\alpha=0.5/\beta=1.0$ config) $\rightarrow$ 84.84%, -0.056, ACC loss 4.40 percentage points, BWT worsens by 65%; removing replay (w/o Rehearsal) $\rightarrow$ 88.02%, -0.036, ACC loss only 1.22 percentage points. Conclusion: both components are necessary, but **distillation's contribution is about 3.5 times that of replay** (author's calculation: 4.40/1.22 $\approx$ 3.6). This also inversely confirms the rationality of the triplet design: if only labels are stored (pure replay), the most significant part of the information (inter-class relationships) is lost.

**Key Points Not Covered by Ablation**: The paper's differentiated claim—"continuously sampling and using logits throughout training, rather than only at the end of a task"—**has no corresponding ablation control** (e.g., a variant of "sampling logits only at the end of a task"); reservoir sampling is not compared against RK-style diversity sampling; the backbone (TC-ResNet-8) and features (MFCC 40) are not subjected to substitution experiments. These gaps mean that some attributions can only remain at the level of the paper's textual arguments (see Limitations).

## Main Contributions

1. **First introduction of dark experience replay into class-incremental learning for keyword spotting**: Fills the application gap of DER in the KWS domain, proposing DE-KWS—a CIL framework that does not rely on task-ID and does not require saving model snapshots, targeting the triple reality of edge KWS: "always-on + lightweight + continuous arrival of new keywords."
2. **Triplet Dark Experience Buffer**: Maintains samples, labels, and logits simultaneously in the same buffer, allowing replay (CE loss in Equation 2) and distillation (logit MSE loss in Equation 3) to share storage and work complementarily—labels are responsible for "remembering what it is," logits for "maintaining what it is similar to," carrying dark knowledge at a memory cost far lower than model snapshots.
3. **Continuous Sampling Mechanism Throughout Training**: Fills and uses the buffer across the entire training trajectory (rather than at task boundaries) via reservoir sampling, freeing the method from dependence on clear task boundaries, capturing model progressive evolution, smoothing task transitions, and particularly improving forgetting in mid-term tasks (Fig. 2).
4. **SOTA Performance with Zero Parameter Increment**: On GSC, with buffer=500, ACC 89.24%, BWT -0.034, while parameters remain at 64.48K—surpassing both DM3 (1/3 parameters) and RWalk (1/2 parameters) (Table I); with buffer=1500, it reaches 91.17%, approaching the joint training upper bound of 95.70%.
5. **Open Scripts**: Code is publicly available on GitHub (https://github.com/NeverlandCookies/DE-KWS), facilitating reproduction and extension for subsequent incremental KWS research.

## Limitations and Future Work

### Technical Limitations of the Method

- **Real storage overhead of the buffer is not quantified**. The Parameters metric only counts model parameters (64.48K), while the necessary cost of the method lies precisely in the buffer: 1500 samples, each containing 1 second of audio plus 30-dimensional logits. The paper does not report whether samples are stored as raw waveforms or MFCC features—if waveforms (1 s @ 16 kHz @ 16 bit is approx. 32 KB/sample), 1500 samples are approx. 48 MB, far exceeding the model itself (64.48K parameters in FP32 is approx. 258 KB, author's calculation); if features are stored, it is much smaller. This missing information makes the argument for applicability on "resource-constrained edge devices" incomplete. The comparison with RK/DM3 parameters is also not entirely equivalent due to different accounting methods (the other methods' additional parameters are included in the metric, while this method's buffer storage is not included in any metric).
- **Staleness of logits**. The logits in the buffer come from models at different moments on the training trajectory, many of which are outputs from the "weak model period" (in the paper's semantics, this is a feature—capturing evolution; but it also means potentially distilling errors or suboptimal soft labels). The paper does not discuss quality control mechanisms for stale logits (such as DER-style variants that periodically refresh pool logits with the current model), nor does it report the impact of the old/new composition of pool logits on performance.
- **Output head dimension implicitly presumes total number of classes**. The parameter count in experiments is constantly 64.48K, identical to joint training, implying that the classification head is a fixed structure pre-allocated for 30 classes. In real deployment, the number of new keywords is unknown beforehand. How the output head dynamically expands during class increment (and the dimension alignment problem of old logits after expansion) is not discussed in the paper—this is precisely a classic difficulty in CIL landing.
- **Remaining gap from the upper bound**. Even with buffer=1500, it is still 4.53 percentage points behind joint training (Table I), indicating that information loss under bounded memory is not negligible; continuing to increase the buffer yields diminishing marginal returns (500$\rightarrow$1000 only +1.14 percentage points).
- **Privacy dimension not touched**. The replay mechanism requires persistently storing user speech segments on the device. In edge scenarios, this is sensitive data. The paper does not discuss any desensitization or feature-level storage alternatives.
- **Slight sacrifice of new task plasticity**. Fig. 2 shows that the accuracy on the newest task (95.87%) is lower than that of the no-regularization baseline (EWC 98.78%, etc.). The plasticity loss brought by distillation constraints is an inherent trade-off of the method. The paper does not provide a mechanism to adjust this trade-off (e.g., decaying $\beta$ as tasks progress).

### Deficiencies in Experimental Design

- **Single and overly clean dataset**. All experiments are conducted only on GSC v1 (30 words, 1-second clean utterances, English). There are no scenarios with noise/far-field/multi-speaker/multi-language, nor is there a real incremental scenario for few-shot custom wake words (each new task consists of complete 3~15 words with sufficient data), creating a gap with the problem motivation of "new domain adaptation."
- **Edge claims lack edge evidence**. The paper takes edge devices as its core motivation but does not report any real-device deployment, inference latency, memory usage, power consumption, or training overhead numbers (not reported by the paper)—the static number of 64.48K parameters cannot replace runtime verification, and the computational cost of incremental training itself on the edge is not discussed.
- **Evaluation protocol has confounding factors**. The dataset is split 80/20 into train/validation, without using an independent test set. Model selection and final evaluation are suspected to share the same 20% data (independent test protocol not reported by the paper), posing a risk of optimistically biased metrics.
- **ACC accounting is questionable**. The author calculates the arithmetic average of the six columns in the final state of Fig. 2 (after learning six tasks), yielding DE-KWS 83.88% (RWalk 75.26%, EWC 66.31%), which does not match Table I's ACC 89.24% (87.53%, 75.23%). If estimated by the "average of average accuracies at each stage of the incremental process," DE-KWS is approx. 88.63%, still not precisely coinciding. The paper does not report the aggregation formula for ACC, and the discrepancy between Fig. 2 and Table I cannot be self-consistently verified.
- **Core claims lack ablation**. The gain of "continuous sampling throughout" relative to "sampling at task end," and the gain of reservoir sampling relative to diversity sampling, are not supported by control experiments; the backbone and features each have only one variant (TC-ResNet-8 + MFCC 40), and the method's generalization to architectures is unknown.
- **Lack of statistical robustness**. All experiments lack repetition with multiple random seeds, and no variance or significance is reported (not reported by the paper); task partitioning is "random split" but seeds and stability under different partitions are not reported.
- **Inconsistent expressions**. Section III-E of the main text writes 11-task and 21-task settings, while Fig. 3 caption writes 10-task and 20-task scenario; learning rate 0.1 with Adam is significantly higher than conventional (1e-3 magnitude) and no scheduling strategy is explained. Reproduction details are not complete.
- **Incomplete baseline grid**. BiC appears only at buffer=500, EWC only at buffer-free, DE-KWS only above 200. Methods are not fully grid-compared under a unified buffer budget, and some cross-tier comparisons are indirect.

### Possible Directions for Future Improvement

- **Complete the edge verification loop**: Measure latency, peak memory, and energy consumption of incremental training and inference on real microcontrollers/DSPs. Quantify buffer storage (and clarify waveform/feature storage forms), upgrading the argument from "no parameter increase" to a complete argument of "no system resource increase."
- **Logit lifecycle management**: Explore periodic refreshing of pool logits, confidence weighting (down-weighting logits from the weak model period), or sliding window consistency to mitigate error distillation from stale soft labels. How such mechanisms are compatible with this paper's claim of "retaining evolution trajectories" deserves dedicated research.
- **Dynamic output head combined with open vocabulary**: Combine DE-KWS with audio-text contrastive open-vocabulary KWS (such as CTC-aligned embedding methods) to solve head expansion and logit dimension alignment when the number of new keywords is unknown, moving towards true custom wake word increment.
- **Few-shot incremental setting**: Tighten the task definition from "3 words per task, sufficient data" to "custom words with few samples per task," examining whether the ratio of distillation to replay needs to be redesigned under few-shot conditions, which is closer to real product needs.
- **Sampling strategy comparison and fusion**: Systematically compare the differences between reservoir sampling and diversity sampling (RK) on KWS streams, explore reservoir variants under class balance constraints, and prevent long-tail classes from being diluted in the pool.
- **More comprehensive evaluation**: Introduce multi-random-seed variance reports, independent test sets, KWS deployment-level metrics (DET-like metrics for false alarm rate/missed detection rate), generalization experiments on multiple datasets (noise, far-field, multi-language), and dedicated analysis of mid-term task forgetting.
- **Privacy-friendly memory forms**: Research replacing raw audio entering the pool with features or irreversible representations, combined with federated/device-local incremental learning, making the replay mechanism compliant with edge privacy constraints.
