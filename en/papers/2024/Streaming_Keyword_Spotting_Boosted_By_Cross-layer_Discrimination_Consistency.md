## Problem Statement

### Problem Background and Domain Pain Points

Wake word detection is a persistent voice entry point for devices such as smart speakers, wireless earbuds, and in-car assistants. It requires continuously determining "whether a preset keyword has appeared and in which frame" on an infinitely long continuous audio stream. KWS systems are typically deployed on resource-constrained edge devices, where computational and memory overheads must be minimized (Introduction). Under these constraints, CTC (Connectionist Temporal Classification) has become the mainstream training criterion for streaming KWS due to two characteristics: first, it eliminates the need for frame-level alignment annotations; second, it is non-autoregressive—outputting label posteriors independently per frame without recursive dependencies, making it naturally suitable for frame-by-frame streaming inference. Consequently, a large body of work performs KWS within the CTC framework (Introduction, References [6]–[11]).

However, an appropriate training criterion does not imply an appropriate decoding strategy. The real decision-making process in KWS is a "sliding local detection" problem on the audio stream, whereas existing decoders are mostly designed for ASR's "full-sentence transcription." The model is already proficient at outputting frame-level phoneme posteriors; the challenge lies in: how to convert these posteriors into a streaming score that triggers at any moment with low false alarm and low miss rates. It is also crucial to note that the performance metric for KWS is the operating point curve defined by the false alarm rate (FAR) and recall rate: the same set of posteriors, depending on the decoding algorithm, determines where the system ultimately lands on this curve and how far the curve can be pushed. If the decoding algorithm fails, even a powerful acoustic model cannot realize its potential. This mismatch between training and decoding is the pain point addressed in this paper. It is worth emphasizing that the approach chosen here is "do not change the acoustic model, only modify the decoding and scoring"—this means that almost all gains come at no model-level cost, which is directly attractive for edge deployment, but it also places all the pressure on the design of the decoding algorithm.

### Specific Shortcomings of Existing Methods

The paper categorizes existing continuous decoding strategies for CTC-based KWS into two types (Introduction):

The first type is based on ASR inference: the model outputs a token sequence in a streaming manner, and then matches the keyword within the updated decoding results. Its fundamental shortcoming is objective mismatch—the goal of ASR decoding is to search for the "most likely complete hypothesis" in the entire acoustic space, producing a full transcription rather than optimizing for the binary judgment of "whether the keyword appears." Search budgets are largely spent on speech unrelated to the keyword; if the content near the keyword is transcribed incorrectly, the result is wrong. The data in Table I quantifies this gap: with the same CTC acoustic model, greedy search achieves an average of only 71.7%, and prefix beam search (beam=10) only 75.5%, indicating that stronger general search does not translate to better KWS performance. Furthermore, these methods face an awkward situation in evaluation: it is difficult to directly control the false alarm rate, so the paper can only report accuracy at FAR=0 for them (Section III-C).

The second type is KWS-specific decoding graphs: these graphs contain keyword paths and optional filler paths, customized for KWS with better performance. However, to be deployed, they must implement WFST (Weighted Finite State Transducer) graphs plus the Token Passing algorithm, which is complex to engineer, difficult to implement, and hard to iterate upon (Introduction). In Table I, the graph baseline averages 75.8%, stronger than both ASR baselines, confirming that the direction of "customizing search for KWS" is correct, but implementation complexity is the cost. Moreover, graph methods have additional weaknesses under strong noise: decoding tokens struggle to pass through the decoding graph to reach the final state, causing accuracy to collapse at low SNR (Explanation in Section IV-A, graph baseline is only 23.9 at -5 dB in Table I).

There is also a common problem shared by both types of methods: they only consume the posteriors from the final output layer, discarding the discriminative information learned by the model's intermediate layers during inference. The authors' previous work, TDT-KWS [14] (ICASSP 2024), has already demonstrated the value of "locking the decoding space to keywords" for Transducer-based KWS—it feeds back the decoded keyword token sequence (rather than partial hypotheses) into the Transducer's predictor, restricting posterior generation and decoding only keywords. However, this idea has not yet been transferred to CTC, and intermediate layer information remains unused.

### Key Challenges to be Solved by This Paper

The paper aims to solve three things simultaneously. First, design a strictly frame-synchronized streaming decoding algorithm for CTC that locks the search space within the keyword template and supports initiating search from any position in the audio stream (unlike ASR decoding, which can only start from the beginning of the utterance). The performance must exceed both ASR and graph baselines, while the implementation must be much simpler than WFST graphs. Second, without significantly increasing training and inference costs, utilize information from the intermediate layer (ICTC branch) during inference, specifically to distinguish "true wake-up positive samples" from "high-scoring negative samples prone to false triggers." This requires first answering "what exactly do the intermediate layers learn differently from the final layer." Third, the CDC score looks at future frames near the wake-up point, inevitably introducing extra latency. It is necessary to clearly quantify the trade-off between window size and latency, provide a deployable configuration, and explain where the upper limit of benefits lies. Essentially, this is focusing on "accuracy" within the "accuracy, speed, and cost" triangle while refusing to pay the "cost" penalty. The difficulty lies in extracting reliable incremental discriminative signals from existing CTC/ICTC outputs.

## Methodology

### Overall Architecture Design and Design Motivation

The overall framework is shown in Fig. 1. The acoustic encoder is a 6-layer DFSMN (Deep Feedforward Sequence Memory Network), with 440-dimensional input, 512-dimensional hidden layer, and 320-dimensional projection. The DFSMN's look-back order is set to 8, and the look-ahead order is set to 2 (Section III-B). The motivation for choosing DFSMN is directly related to streaming constraints: it is a purely feedforward structure, using fixed-length memory blocks to replace recursion. With a look-ahead of only 2 frames, the algorithmic latency of the entire network is extremely small, matching the positioning of frame-by-frame streaming decoding; additionally, it is an architecture deeply cultivated by this team (X-LANCE), forming a comparison of different training criteria under the same architecture with previous work [14].

An additional linear projection layer is attached in the middle of the encoder (default layer 3, near L/2), supervised by ICTC (Intermediate CTC, intermediate layer CTC regularization, Reference [20]). The training loss is:

$$L = w \cdot L_{ICTC} + (1-w) \cdot L_{CTC}$$

where w defaults to 0.3 (Eq. 2, Section III-B). The reason for needing this intermediate branch stems from a key phenomenon observed by the authors in preliminary experiments (Fig. 2): near the wake-up point, the main layer CTC score curves for positive samples and ICTC score curves are both stable and similar to each other; whereas for high-scoring negative samples prone to false triggers, the activation is brief, and the two curves diverge significantly. The mechanistic explanation provided by the authors is: the pattern of positive samples (the same wake word) is relatively consistent, which even a limited-capacity intermediate layer can learn; negative samples have diverse patterns, which shallow layers cannot fully characterize. The final layer may overfit to some false alarm patterns, while the ICTC branch, due to limited capacity, maintains regularization. Thus, "whether the discrimination of the two layers is consistent" itself becomes a nearly free false alarm detector—this is the physical origin of CDC (Cross-layer Discrimination Consistency).

Inference is a four-stage multi-stage pipeline (Fig. 1): using the same decoding algorithm (Algorithm 1), calculate the frame-by-frame initial score $s^{(init)}$ and intermediate score $s^{(inter)}$ on the posteriors of the main CTC branch and ICTC branch, respectively. Then, calculate the CDC score $s^{(cdc)}$ using sliding window cosine similarity, and finally average with the initial score to obtain the refined score $s^{(refine)}$. The entire process is performed frame-by-frame, maintaining full streaming capability.

### Mathematical Principles of the Core Algorithm

The CTC part follows the standard definition: given acoustic features $x$ ($T$ frames, $D$ dimensions) and target label sequence $y$ ($U$ labels), introduce a blank symbol $\phi$. CTC maximizes the sum of probabilities over all alignment paths that can map to $y$:

$$L_{CTC} = -\log P(y|x) = -\log \sum_{\pi \in B^{-1}(y)} P(\pi|x)$$

where $\pi$ is the alignment path, and $B$ is the mapping from alignment paths to label sequences (Eq. 1). The modeling units take the 70 monophones from the cmudict-0.7b phoneme dictionary, plus one CTC-specific blank symbol (Section III-B).

The mathematical skeleton of streaming decoding (Algorithm 1) inserts the keyword phoneme sequence $y$ into the blank-expanded template $\tilde{y} = [\phi, y_1, \phi, \dots, \phi, y_U, \phi]$, with length $\tilde{U} = 2U+1$. Then, Viterbi-style dynamic programming is performed on this restricted template, with state scores denoted as $\delta(t, \tilde{u})$. Each frame only scans $\tilde{U}$ states, with complexity $O(T \cdot \tilde{U})$:

- At the start of each frame $t$, set $\delta(t,1) = \delta(t,2) = 1$. These two rows constitute the "any-start" mechanism: a new competing path starts from the beginning of the template with probability 1 at every moment, allowing the keyword to be captured regardless of which frame it starts. This is something ASR-type methods "can only search from the beginning of the utterance" cannot do (Introduction Contribution 1) and is a hard requirement for streaming scenarios.
- If the current state is a blank symbol: $\delta(t,\tilde{u}) = p_t(\phi) \cdot \max\{\delta(t-1,\tilde{u}-1), \delta(t-1,\tilde{u})\}$. The predecessor either advances from the previous phonon state or stays in the blank (corresponding to continuous blank output in CTC).
- If the current state is a phonon: $\delta(t,\tilde{u}) = p_t(\tilde{y}_{\tilde{u}}) \cdot \max\{\delta(t-1,\tilde{u}-2), \delta(t-1,\tilde{u}-1), \delta(t-1,\tilde{u})\}$. The three predecessors correspond to skipping the preceding blank (blanks can be omitted), advancing from the blank, or repeating the same phonon—this is exactly the complete expansion of CTC alignment rules on the keyword template.
- The wake-up score for this frame: $Scores[t] = S_{Bonus} \cdot \max\{\delta(t,\tilde{U}-1), \delta(t,\tilde{U})\}$, meaning the path stopping at the last phonon or the ending blank symbol counts as a hit, multiplied by a bonus score $S_{Bonus}$ (experimentally set to $e^3$, approx. 20, Section III-C), amplifying the score for paths that complete the whole word detection.
- Timeout mechanism: record the length $\ell(t)$ of the maximum score path. If it exceeds $T_{out}$ (3 seconds), it is directly set to zero to prevent accumulating too much history as a false keyword; finally, perform length normalization $Scores[t] = Scores[t]^{1/\ell(t)}$, i.e., geometric mean. The paper does not explicitly state the reason for this step, but the mechanistic inference is: path scores are probability products; the longer the path, the more terms are multiplied, resulting in smaller values. Without normalization, there would be a systematic bias towards shorter paths. Geometric mean eliminates this length bias, allowing candidates of different lengths to compete fairly.

The mathematical definition of CDC (Eq. 5): at time $t$, take a sliding window of length $L_{His} + L_{Fut}$, and calculate consistency between the two score curves:

$$s_t^{(cdc)} = f_{CDC}\left(s^{(init)}_{[(t-L_{His}):(t+L_{Fut})]},\ s^{(inter)}_{[(t-L_{His}):(t+L_{Fut})]}\right)$$

$f_{CDC}$ takes the cosine similarity function. The final refined score is a simple average (Eq. 6):

$$s^{(refine)} = \left(s^{(init)} + s^{(cdc)}\right) / 2$$

Intuitively: for positive samples, both curves rise steadily and consistently near the wake-up point, with cosine similarity close to 1, so the score is hardly reduced; for negative samples, activation is brief and the two layers diverge, resulting in low cosine similarity, which pulls down the high score of $s^{(init)}$. The role of CDC is equivalent to a "soft gate" that only passes if "both layers agree," and it is calculable frame-by-frame without breaking streaming properties (Section II-C). $L_{Fut}$ is the knob for tuning performance and latency: the more future frames, the more complete the divergence information after the wake-up point can be seen, but the output latency is larger.

### Key Technical Innovation 1: Any-Start Streaming Decoding Algorithm for CTC

There are four coordinated design decisions, each addressing a specific problem. First, narrowing the search space: instead of searching the entire space, DP is performed only on the $2U+1$ states of the keyword template, directly writing the prior "KWS only cares about this one word" into the decoding structure—this is a direct response to the objective mismatch of ASR decoding. Second, any-start: resetting the first two states to 1 at each frame allows new competing paths to enter at any time, solving the problem of unknown keyword start positions in streaming audio. This is more non-trivial than it appears: hypotheses in ASR-type prefix search accumulate and grow from the beginning of the utterance; when a keyword appears in the middle or later part of a long audio segment, the search is already occupied by preceding non-keyword content. In contrast, this algorithm treats "whether this frame is the first phonon of the keyword" as an assumption that can be independently restarted at each frame, coupled with frame-by-frame output scores, naturally requiring no prior knowledge of the keyword position. Third, timeout and length normalization: $T_{out}$ cuts off overly long paths to prevent false accumulation, and geometric mean eliminates length bias, together ensuring scores are comparable across different speaking speeds and keyword lengths. Fourth, engineering simplicity: the entire algorithm only requires the posterior matrix, the keyword phoneme sequence, and two hyperparameters ($S_{Bonus}$, $T_{out}$), with no WFST graph compilation and no Token Passing, making it easy to implement and iterate (Introduction Contribution 1, Conclusion). In comparison, graph methods require reconstructing the graph to change a keyword, whereas this method only requires changing a phoneme sequence.

### Key Technical Innovation 2: CDC Refinement Stage—Turning Training Regularization into an Inference Discriminator

ICTC in ASR literature [20]–[24] is purely a training-time regularization method, with the intermediate branch entirely discarded during inference. The incremental contribution of this paper is turning the intermediate layer output into an inference-time signal source for the first time (in this task), supported by the empirical observation in Fig. 2 and the mechanistic hypothesis "shallow layer capacity is small $\rightarrow$ it only learns consistent positive sample patterns." The implementation adds no learnable parameters: sliding window cosine similarity plus average fusion, all parameter-free post-processing. This design is restrained but effective, with the cost being only running the intermediate branch decoding once extra (overhead not reported by the paper) and a sliding window latency of up to 900 ms (optimal configuration in Table III). The prerequisite for its applicability is also worth noting: the "inconsistency" of the two-layer scores indicating false alarms relies on a capacity and information difference between the intermediate and final layers—Table IV's layer ablation exactly verifies this (see below).

### Technical Differences with Existing Methods

Compared to ASR decoding: the search space is narrowed from the entire acoustic space to the keyword template itself; the output per frame is a "keyword hit score" rather than a complete hypothesis; search can be initiated at any moment. Table I shows average accuracy improving from 71.7/75.5 to 82.1. Compared to KWS decoding graphs: it does not rely on WFST and Token Passing; a DP with $2U+1$ states and two hyperparameters suffices; moreover, under strong noise, graph methods struggle to pass tokens to the final state, whereas this method forces frame-by-frame output of activation scores, allowing scoring to continue even with strong background noise (Section IV-A). Compared to the authors' previous work TDT-KWS [14]: the previous work was designed for Transducer (feeding back keyword sequences to restrict predictor posterior generation); this paper transplant the same "locking search space" idea to CTC, and additionally leverages CTC's unique multi-branch ICTC structure for CDC enhancement, which is a natural asset not present in the Transducer framework. Compared to the original use of ICTC: upgraded from training regularization to inference-time discriminative signal, the intermediate layer investment of the model yields returns for the first time during inference.

## Experimental Results

### Datasets Used and Their Scale

- LibriSpeech (Reference [25]): Approximately 960 hours of English ASR corpus, used for pre-training the CTC acoustic model to obtain a stronger base (Section III-A).
- Hey-Snips (Reference [26]): Open-source KWS dataset, wake word "Hey Snips". Positive samples for train/dev/test are 5,799 / 2,484 / 2,599 sentences respectively. Negative samples have no transcripts and cannot be used for ASR-type training. Thus, following the method of previous work [14], the data was reorganized, and all original negative samples were aggregated into a large negative test set of approximately 97 hours (Section III-A).
- WHAM! (Reference [27]): A library of various environmental noises. Clean Hey-Snips samples were randomly mixed with WHAM! noise to synthesize noisy keyword samples at different SNRs to investigate robustness (Section III-A).

Training configuration (Section III-B): Pre-trained on the complete LibriSpeech first (using only frame-level cross-entropy at this stage); in the fine-tuning stage, equal sampling from LibriSpeech and Snips forms a general ASR dataset. Clean sentences from both sources are mixed with WHAM! noise (SNR uniformly distributed between 0–20 dB). The fine-tuning set consists of approximately 24,000 sentences (12,000 clean + 12,000 noisy). Features are 40-dimensional log FBank, window length 25 ms, frame shift 10 ms; two types of augmentation: online speed perturbation (warping factor uniformly sampled from {0.9, 1.0, 1.1}) and SpecAugment (2 time masks $T_{max}=50$, 2 frequency masks $F_{max}=10$); 5 frames before and after are concatenated to form a 440-dimensional input, then downsampled by a factor of 3, so that each input frame carries 30 ms of acoustic information. In the fine-tuning stage, pure CTC or CTC+ICTC is used depending on the model, with w defaulting to 0.3.

### Definition and Rationale for Evaluation Metrics

The main metrics are recall rate (equal to 1 minus miss rate) at fixed false alarm rate (FAR) and macro-average recall across SNR bins (Section III-C). Rationale: KWS is a detection task, and the only meaningful way to compare is to fix the false alarm operating point and compare recall; reporting accuracy in isolation is meaningless. For ASR-type baselines, since they struggle with false alarm decoding, the paper reports accuracy at FAR=0 (semantically equivalent to recall at FAR=0), which is anan unavoidable handling explained by the authors (Section III-C). When comparing with graph-based systems, the operating point is unified to FAR = 0.05 times/hour, which the authors call a "more reasonable and stricter" metric for KWS systems (Section III-C). For robustness evaluation, each positive sample is mixed with {0, 5, 10, 15, 20} dB noise, and an additional -5 dB positive sample set is created to examine extremely low and out-of-domain SNR conditions; the negative test set is also mixed with 0–20 dB noise. Decoding hyperparameters $S_{Bonus} = e^3$, $T_{out} = 3$ seconds (Section III-C).

### Detailed Comparison with Baselines and SOTA

Table I (FAR=0, SNR from -5 to +inf, seven bins): Under the same CTC acoustic model, greedy search averages 71.7, prefix beam search (beam=10) 75.5, KWS graph 75.8, and the proposed streaming decoding 82.1. That is, an average absolute improvement of 10.4 and 6.6 percentage points relative to the two ASR baselines, and an absolute improvement of 6.3 percentage points relative to the graph baseline (Section IV-A). The most striking results are in the low SNR segment: at -5 dB, the proposed method achieves 35.5 compared to greedy's 22.7 and graph method's 23.9; at 0 dB, 68.0 compared to 50.7/54.7; the low SNR segment generally achieves absolute gains of about 10 percentage points or more. The authors' explanation: at extremely low SNR, ASR decoding cannot generate correct hypotheses because the speech is drowned by noise; in graph methods, decoding tokens struggle to pass through the decoding graph to reach the final state, leading to low accuracy; whereas this method forces the decoder to output activation scores frame-by-frame, allowing scoring to continue even under strong background noise (Section IV-A).

Table II (FAR=0.05/hour, same operating point as graph baseline, same acoustic model): A (no ICTC, graph decoding) averages 85.3; B (no ICTC, streaming decoding) 89.4; C (with ICTC, graph) 85.6; D (with ICTC, streaming) 91.1; E (ICTC + CDC streaming) 92.1. Three sets of readings are worth looking at separately. First, streaming decoding itself is stronger than graph decoding: B is on average +4.1 higher than A (54.0 vs 41.6 at -5 dB, +12.4); the gain from pure decoding algorithm exceeds that of the graph method. Second, the gain from ICTC is much larger for streaming than for graph: D is on average +1.7 higher than B, while C is only +0.3 higher than A; and ICTC gains are concentrated in low SNR—at -5 dB, B's 54.0 is raised to D's 59.8 (+5.8), indicating that CTC intermediate layer regularization is particularly effective in noisy scenarios (Conclusion in Section IV-B "ICTC gains are more obvious at low SNR"). Looking closely at C vs A, there is a reverse detail: in the +inf (clean) column, ICTC actually lowers the graph method from 98.8 to 98.3, and from 97.5 to 96.8 at 15 dB (Table II), contributing positively only at low SNR—after the training objective's weight is shared by the intermediate loss, the extreme optimization of graph decoding in high SNR is slightly harmed, but this buys robustness in noise, which is a typical regularization trade-off curve. Third, CDC adds another layer: E is on average +1.0 higher than D, with -5 dB +3.6 (59.8 to 63.4) and 0 dB +2.0 (86.4 to 88.4), again showing the greatest benefit under the hardest conditions. Finally, E vs A: average recall absolute improvement of 6.8 percentage points, average miss rate relative decrease of 46.3% (from 14.7% to 7.9%), achieved at an extremely low false alarm rate of 0.05 times per hour (Abstract, Section IV-B).

### Findings from Ablation Experiments

CDC window ablation (Table III, total window fixed at 30 frames; since each input frame carries 30 ms, max latency is 900 ms): $L_{His}=0 / L_{Fut}=30$ (latency 900 ms) averages 92.1, the best; performance monotonically decreases as fewer future frames are used: $L_{Fut}=25$ is 91.5 (latency 750 ms), 20 is 91.3 (600 ms), 10 is 91.0 (300 ms), 0 is 90.7 (zero latency). Two upper-bound references are provided: full future window ($L_{Fut}=\infty$) 92.1, and fully offline full-sentence window 92.3. Conclusion (Section IV-C): The discriminative information of CDC comes almost entirely from future frames after the wake-up point; after $L_{Fut}=30$, benefits diminish, and introducing less than 1 second of slight latency is sufficient to approach the upper-bound performance. There is another striking point in the data that the paper does not elaborate on: $L_{His}=30 / L_{Fut}=0$ (zero extra latency) averages only 90.7, which is 0.4 lower than D (91.1) which does not use CDC at all—pure history window CDC is not only useless but slightly harmful (cross-table comparison of Table III and Table II). This indicates that the divergence of the two-layer scores mainly occurs after activation; pulling the two yet-to-be-aligned curves to calculate cosine similarity before the wake-up point introduces noise rather than signal; this again confirms that the essence of CDC is to see "whether the two layers rise and fall together after activation."

ICTC position and weight ablation (Table IV, encoder has L=6 layers total, L/2=3): Scanning weights with layer 3 fixed, w=0.3 is best (92.1), w=0.4 / 0.2 / 0.1 are 91.8 / 91.4 / 91.2 respectively—when w is too large, the main CTC objective is diluted; when too small, the intermediate branch fails to learn sufficient discriminative power. Scanning layers with w=0.3 fixed: Layer 2 is 89.3, Layer 3 is 92.1, Layer 4 is 92.3, Layer 5 is 91.2. Explanation (Section IV-D): Too shallow layers are mainly doing feature extraction and have not effectively encoded keyword information; too deep layers learn things that are homogenized with the main CTC, causing the two-layer scores to lose complementarity, and neither can extract useful CDC information; placing it near L/2 (Layers 3, 4) allows obtaining a branch that "participates in discrimination and has a capacity difference with the main layer." This ablation actually reversely verifies the mechanistic hypothesis of CDC: the value of the intermediate branch lies precisely in it being "different" from the final layer; being too similar or too dissimilar is no good. Another detail: when w=0.1, the +inf (clean) column 99.9 is slightly higher than w=0.3's 99.9 (Table IV), indicating that under clean conditions, the marginal benefits of CDC/ICTC are nearly saturated, and their value is mainly reflected in noise and out-of-domain conditions—this also suggests that if the deployment scenario is clean, w can be reduced to trade for more stable main task optimization.

## Main Contributions

1. Proposed a streaming decoding algorithm for CTC-based KWS: locking the search space in the keyword template ($2U+1$ states DP), introducing new competing paths with probability initialization of 1 at each frame to achieve any-start detection, combined with timeout truncation and path length normalization. Compared to ASR decoding, average absolute improvement of 10.4 and 6.6 percentage points; compared to graph baseline, improvement of 6.3 percentage points (Table I), and implementation and maintenance are much simpler than WFST graphs (Introduction Contribution 1, Algorithm 1, Conclusion).
2. Proposed and utilized Cross-layer Discrimination Consistency (CDC): based on empirical observations of behavioral differences between the main layer and ICTC intermediate layer on positive/negative samples (Fig. 2), using sliding window cosine similarity to turn "whether the discrimination of the two layers is consistent" into a frame-by-frame score, which significantly suppresses high-scoring negative samples after averaging with the main score (Introduction Contribution 2, Eq. 5/6). Turning training-time regularization into an inference-time discriminator for the first time, with zero additional learnable parameters.
3. Systematically verified on clean and noisy Hey-Snips: at FAR=0.05/hour, average recall absolute +6.8, miss rate relative decrease 46.3%, exceeding graph-based CTC KWS baselines; recall at -5 dB out-of-domain condition is still 63.4 (Table II), leading comprehensively across all SNR bins (Table I, II, Abstract, Conclusion).

## Limitations and Future Work

### Technical Limitations of the Method

- Latency cost: The optimal CDC configuration ($L_{His}=0 / L_{Fut}=30$) introduces 900 ms of extra latency (Section IV-C, Table III). The authors call it "deployable," but wake-word products are usually sensitive to response latency; whether nearly 1 second of extra waiting is acceptable depends on the product form; and under the zero-latency configuration ($L_{Fut}=0$), CDC is almost ineffective or even slightly negatively effective (90.7 in Table III vs 91.1 for D in Table II), making the trade-off between latency and gain quite rigid.
- Dependence on ICTC branch during training: CDC requires the model to have intermediate CTC supervision during training, and cannot be directly applied to a pre-trained ordinary CTC model to obtain gains without training; migration requires re-fine-tuning.
- Fusion and metric are manually selected: $f_{CDC}$ is fixed to cosine similarity, Eq. 6 is fixed to simple average, with no learnable weights, and no exploration of other consistency metrics; the paper does not report sensitivity analysis for these choices.
- Hard truncation of timeout: Paths exceeding $T_{out}=3$ seconds are directly set to zero (Algorithm 1); whether this is safe for boundary cases of extremely slow speakers or longer keywords is not discussed.
- Applicability of mechanistic hypothesis: The observation in Fig. 2 "positive samples are consistent across layers, negative samples diverge across layers" is an empirical phenomenon observed on Hey-Snips. Its explanation (shallow layer capacity is small, so it learns consistent positive patterns) is a reasonable inference rather than a theoretical guarantee; whether it holds after changing datasets or keywords needs re-verification.

### Shortcomings in Experimental Design

- Verified only on one English dataset (Hey-Snips) and one wake word; generalization across multiple keywords, languages, and datasets is not reported.
- All baselines come from the CTC family (greedy, prefix beam, KWS graph); no direct comparison with Transducer-based KWS (including the authors' own TDT-KWS [14]) or dedicated small KWS architectures, making it impossible to position this solution within the broader method landscape.
- ASR baselines report accuracy at FAR=0, while graph and this method report recall at FAR=0.05/hour; the two operating points are on different tracks, and Table I and Table II cannot be directly compared across tables (the authors themselves explained this unavoidable situation, Section III-C).
- Computational overhead is completely unquantified: RTF, memory, and additional parameter count for running the ICTC branch decoding and frame-by-frame sliding window cosine similarity are not reported. Negative samples only include Snips in-distribution plus WHAM! noise mixing, lacking more tricky negative sample types such as real far-field, reverberation, and TV leakage, which are exactly the main sources of false alarm pressure.
- Results are from a single run; random seed variance is not reported (not reported in the paper).

### Possible Directions for Future Improvement

- Extend the decoding idea of "locking search space + any-start" to other sequence modeling frameworks such as Transducer/TDT, unifying with the authors' previous work [14] into a cross-training-criterion streaming KWS decoding theory.
- Make the CDC window adaptive to latency budgets, or use causal prediction to approximate future frame information under streaming constraints, striving to eliminate the 900 ms latency—Table III shows that pure causal windows currently have negative benefits, which is a clear open problem.
- Replace simple average with learnable fusion (small network or learnable weights), and replace cosine similarity with richer consistency metrics (correlation, divergence, etc.), along with systematic sensitivity analysis.
- Verify the universality of the observations in Fig. 2 and the CDC mechanism on real far-field, multi-keyword, multi-language data, and supplement computational overhead and false alarm evaluation under different false trigger sources (reverberation, TV audio).
