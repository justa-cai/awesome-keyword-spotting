# Scalable Keyword Spotting via Modular Network Expansion

- **Authors/Affiliations**: Viktor Khaymonenko, Dzmitry Saladukha, Aliaksei Rak, Alexander Rostov - Yandex (Russia/Belarus, Embedded Voice Input Team)
- **Date**: 2026.07
- **Link**: https://arxiv.org/abs/2607.19918
- **Keywords**: keyword spotting, modular network expansion, class-incremental learning, catastrophic forgetting, parameter-efficient tuning, embedded deployment, non-regression guarantee

## Problem Statement

### Problem Background and Domain Pain Points

Keyword Spotting (KWS) is a core component of hands-free voice entry on resource-constrained devices, where small models must maintain accuracy and reliability over time across various speakers and acoustic conditions. However, deployed products are not static: new features, new dialects, and new user demands constantly require adding new keywords to the vocabulary. This paper from Yandex’s Embedded Voice Input Team focuses precisely on this "post-deployment" update scenario, which presents three industrial-grade pain points:

First, original training data is unavailable. Due to privacy compliance and storage costs, the training audio corresponding to the online model is often inaccessible during the update phase, disqualifying any scheme that relies on "replaying old data." Second, full retraining is computationally expensive, and even if affordable, it极易 introduces regression on old keywords—breaking a user’s long-standing reliance on a keyword like "stop" via an OTA update is far more severe than a new keyword simply performing poorly. Third, the growth of on-device models must be strictly limited: wake-word detection is a resident, fixed-latency single detector; it is impossible to attach an independent large model for each new keyword, nor can it accept a multi-branch structure that requires a task ID at inference time to select a branch.

The paper strictly defines this problem as class-incremental keyword expansion: maximizing the detection performance of new keywords under three constraints: unavailability of original training data, strictly bounded model growth, and the requirement that the output and threshold decision rules of the shipped detector for old keywords remain exactly unchanged for all inputs.

### Specific Deficiencies of Existing Methods

The paper systematically reviews four existing routes, each of which fails at least one constraint:

- **Fixed-vocabulary small models** (CNN-based, SVDF streaming structures): Offer the best balance of accuracy and latency/memory, but expanding the vocabulary requires retraining and class rebalancing, with updates potentially causing regression on old keywords at any time.
- **Open-vocabulary / Query-by-Example (QbE) and few-shot metric learning** (e.g., Prototypical Networks): Require no retraining and allow user-defined phrases, but suffer from systematically lower robustness in embedded settings compared to fixed-vocabulary models, particularly in distinguishing high-noise and phonetically similar words (e.g., on/off, stop/go pairs in the paper’s experiments). More troublingly, maintaining stable performance on the old keyword set after model updates is difficult—especially when original data is unavailable.
- **Continual Learning**: Regularization-based methods (EWC, LwF) constrain parameter drift, while replay-based methods (experience replay, generative replay) reconstruct old samples. However, the former offers only "soft protection"—it reduces the probability of forgetting but provides no strict guarantees; in the paper’s experiments, EWC still increased the False Rejection Rate (FRR) for core keywords from 2.71% to 4.47%. The latter requires storing and reusing old data, directly violating the no-$\mathcal{D}_1$ setting. Furthermore, EWC requires Fisher information derived from $\mathcal{D}_1$, strictly speaking also failing the no-original-data constraint.
- **Parameter-Efficient Fine-Tuning (PEFT)** (Adapters, LoRA): While the number of trainable parameters is indeed small, they are inserted into shared computational paths. Changing the path changes the logits for old keywords, making it structurally impossible to guarantee behavioral invariance. Preserving old behavior would require additional inference compute.

The closest relative is the Progressive Neural Network (PNN): freezing old columns and adding new columns with lateral connections naturally prevents forgetting. However, PNN operates in a task-incremental setting—inference assumes knowledge of the task identity and which column to run. This paper faces a always-online, fixed-latency single detector where no task label is available at inference time to select a branch, which is the fundamental reason PNN’s structure cannot be directly adopted.

### Key Challenges to Be Solved

The core challenge can be summarized in one sentence: How to make the "non-regression guarantee" arise from construction rather than from regularization or retraining luck, without letting this safety compromise new keyword performance and inference overhead. The easiest way to achieve safety is to freeze the base model and train only the new head (Head-Only), but the paper’s experiments show its average new keyword FRR is as high as 22.30%—freezing the representation is insufficient for new class discrimination. The other extreme of safety is training an independent 10k-parameter new model in parallel (Ensemble, 6.46%), but it completely fails to reuse the base model’s intermediate features, wasting the 10k budget by learning from scratch. The true sweet spot lies in: zero-risk "borrowing" of the base model’s learned speech representations, without touching anything in the computation graph that would affect core outputs, while keeping the parameter/MACC conversion rate lower than comparable PEFT methods.

## Methodology

### Overall Architecture Design and Design Motivation

The overall solution is a three-piece set: "frozen base + parameter-capped expansion branch + independent new keyword head."

The base is a small-footprint SVDF-style architecture with approximately 150k parameters: each Base (Encoder) Block consists sequentially of SVDF, Batch Normalization (BN), hard-swish activation, and dropout. The encoder output undergoes temporal pooling before connecting to the Core Classification Head (Core Head), which outputs logits on $\Y_1 \cup \{\emptyset\}$ followed by softmax. The choice of SVDF over CNN/RNN is motivated by its factorized structure designed for streaming low-latency KWS (citing Alvarez & Park 2019, Nakkiran 2015’s rank-constrained topology), aligning with Yandex’s real-world shipping pipeline—the methodological stance of this paper is "research aligned with deployment pipelines," and base selection adheres to this.

The expansion path consists of $L$ Expanded Blocks plus a New Head, with total new parameters (Expanded Blocks + New Head) capped at 10k, resulting in a final model of approximately 160k parameters. Each Expanded Block "taps" into the activation of the frozen Base Block, concatenating with the output of the previous Expanded Block along the channel dimension, followed by a lightweight transformation: small-kernel temporal Conv1D → BN → hard-swish. The first Expanded Block is a special case, consuming only the frozen encoder activation with no previous expansion output, making the concatenation degenerate to identity. The output of the last Expanded Block undergoes temporal pooling and feeds into the New Head, outputting logits on $\Y_2 \cup \{\emptyset\}$.

Why each design decision was made this way:

- **Full freezing, including BN**: The paper explicitly emphasizes that freezing "includes BN affine parameters and sliding statistics." This is a hidden pitfall in many "freeze backbone" implementations—freezing weights but not BN running stats means the forward pass during expansion training still updates statistics, causing base representations to drift and core logits to change, instantly invalidating the non-regression guarantee. Thus, the complete statement of "constructive guarantee" is: computation path isolation + statistic isolation, both indispensable.
- **Small-kernel temporal convolution for expansion transformation instead of fully connected or large kernels**: Parameter-to-compute conversion rate is a recurring underlying theme. Under a 10k parameter budget, using small-kernel Conv1D in each block keeps MACCs far below the level of Adapters/LoRA (see experimental comparison), and temporal convolution aligns with the base’s streaming processing.
- **Intra-block BN + hard-swish replicates base block recipe** (citing MobileNetV3’s hard-swish): The expansion branch maintains the same normalization/activation dynamics as the base, reducing feature distribution mismatch between the two paths. Note that BN within expansion blocks consists of new parameters serving only the new path, interfering with the frozen base BN.
- **Temporal pooling convergence**: The output of the last Expanded Block is pooled along the time dimension before entering the New Head, aligning with the base’s "encoder output pooled then into Core Head" convergence method, ensuring both ends make decisions at the same temporal aggregation granularity, yielding one word-level decision per 1-second speech segment.
- **Independent softmax for dual heads instead of merging into one large head**: The intuitive approach is to concatenate old and new keywords into a joint head of $(|\Y_1|+|\Y_2|+1)$ classes, but a joint head either alters core logits (violating Eq. 3) or requires joint calibration of the softmax normalization denominator on both old and new data (impossible without $\mathcal{D}_1$). Two independent softwares with their own background classes restrict the normalization range to their respective label sets, allowing threshold calibration to be completed independently. This is the only viable output structure under the no-$\mathcal{D}_1$ setting. A single background label $\emptyset$ (rather than a negative class per keyword) is standard practice for small-footprint KWS; the background class absorbs all non-target audio, avoiding negative class explosion that dilutes positive supervision.
- **Chained concatenation (residual style)**: Each Expanded Block consumes both "frozen base features" and "its own preceding state," allowing the expansion path to gradually build sequence states independent of base vocabulary, while each layer is re-anchored by base features, preventing the small 10k-parameter branch from overfitting and drifting on $\mathcal{D}_2$.

### Mathematical Principles of the Core Algorithm

**Problem Formalization**. Let $x$ be the input speech, $\Y_1$ be the deployed core keyword set, $\Y_2$ be the disjoint new keyword set ($\Y_1 \cap \Y_2 = \emptyset$), and $\emptyset$ be the single background label ("no target keyword"). The base model $f_{\text{base}}(x;\theta_{\text{base}})$ is trained on $\mathcal{D}_1$ (labels $\Y_1 \cup \{\emptyset\}$); the expansion stage only accesses $\mathcal{D}_2$ (labels $\Y_2 \cup \{\emptyset\}$), with no access to $\mathcal{D}_1$. The goal is to obtain $f_{\text{exp}}(x;\theta_{\text{base}},\theta_{\text{exp}})$: small number of new parameters, trained only on $\mathcal{D}_2$, satisfying strict non-regression on $\Y_1$, and maximizing performance on $\Y_2$.

**Dual-head Output and Identity Guarantee**. The expansion model outputs two independent softmaxes:

$$p_{\text{core}}(y \mid x) = \mathrm{softmax}(\ell_{\text{core}}(x)), \quad y \in \Y_1 \cup \{\emptyset\} \tag{1}$$

$$p_{\text{new}}(y \mid x) = \mathrm{softmax}(\ell_{\text{new}}(x)), \quad y \in \Y_2 \cup \{\emptyset\} \tag{2}$$

Since the Core Head’s computation is frozen and does not depend on the expansion path, for any input $x$:

$$\ell_{\text{core}}^{\text{exp}}(x) \equiv \ell_{\text{core}}^{\text{base}}(x) \;\Rightarrow\; p_{\text{core}}^{\text{exp}}(y \mid x) \equiv p_{\text{core}}^{\text{base}}(y \mid x), \; \forall y \in \Y_1 \cup \{\emptyset\} \tag{3}$$

Eq. (3) is the logical pivot of the entire paper: non-regression is not "experimentally observed no regression," but an identity.

**Training Objective**. Only $\theta_{\text{exp}}$ is updated, only $\mathcal{D}_2$ is consumed, and cross-entropy is applied only to the New Head:

$$\min_{\theta_{\text{exp}}} \; \mathbb{E}_{(x,y)\sim \mathcal{D}_2}\left[-\log p_{\text{new}}(y \mid x)\right] \tag{4}$$

Note that $p_{\text{new}}$ includes the background class $\emptyset$—the new head must learn to reject independently, which is a prerequisite for it to make independent threshold decisions.

### Key Technical Innovation 1: Constructive Non-Regression (Frozen Base + Parameter-Capped Expansion Branch)

The essence of this innovation is reducing "safety" from an algorithmic problem to a computation graph topology problem. Why do this: Regularization methods (EWC/LwF) have probabilistic safety boundaries, dependent on hyperparameters and Fisher estimation quality, offering only prayer for product-level red lines like "unacceptable regression." Replay methods require old data; PEFT modifies shared paths. The only way to mathematically guarantee unchanged old behavior is to completely disconnect the old output from new parameters in the computation graph—the identity in Eq. (3) is thus obtained for free, requiring no additional training tricks. Capping parameters at 10k (a ~6.7% increase for a 150k base) responds to the deployment constraint of "strictly bounded model growth": the expansion budget is a hard cap, not a soft target, and all capacity-adding methods are compared under the same budget line.

### Key Technical Innovation 2: Core-First Cascaded Decision Rule

An easily overlooked but crucial insight in the paper is: **preserving logits does not equal preserving product behavior**. The shipped detector promises users a "threshold decision rule," so the decision rule itself must be preserved. Thus, a core-first two-stage cascade is designed:

$$\hat{y}_{\text{core}}(x) = \begin{cases} y^*_{\text{core}}(x), & \text{score}^{\text{core}}_{y^*_{\text{core}}(x)}(x) > \tau^{\text{core}}_{y^*_{\text{core}}(x)} \\ \emptyset, & \text{otherwise} \end{cases} \tag{5}$$

where $y^*_{\text{core}}(x) = \arg\max_{y \in \Y_1} p_{\text{core}}(y|x)$, and thresholds $\tau^{\text{core}}_y$ are inherited from the shipped model’s original thresholds, unchanged by a single byte. **Only if** the core detector outputs $\emptyset$ (rejects) is the new head evaluated:

$$\hat{y}(x) = \begin{cases} \hat{y}_{\text{core}}(x), & \hat{y}_{\text{core}}(x) \neq \emptyset \\ y^*_{\text{new}}(x), & \text{score}^{\text{new}}_{y^*_{\text{new}}(x)}(x) > \tau^{\text{new}}_{y^*_{\text{new}}(x)} \\ \emptyset, & \text{otherwise} \end{cases} \tag{6}$$

The benefits of cascading are twofold: for old keywords, the decision path is bitwise identical to the shipped system (Eq. 3 guarantees score consistency + Eq. 5 guarantees rule consistency, together constituting complete non-regression); for new keywords, the new head only needs to model the small label space of $\Y_2 \cup \{\emptyset\}$, making 10k parameters sufficient. The cost is system decision serialization—new keyword detection is ranked after core detection. This introduces a coupling not quantified by the paper: if the core head falsely triggers on new keyword speech (outputting non-$\emptyset$), the new head never gets evaluated, and the new keyword FRR has a theoretical floor dictated by the core’s false acceptance rate, the magnitude of which is not reported.

### Key Technical Innovation 3: Chained Feature Reuse and Optimal Reuse Depth

The design of the Expanded Block answers "what to steal from the frozen base": each block concatenates the frozen Base Block activation with the preceding expansion state along the channel dimension, passing through Conv1D→BN→hard-swish. The reuse depth $L$ is not arbitrary but derived from ablation studies (Fig. 3): tapping only shallow layers (1–3 blocks) results in high new keyword FRR due to insufficient semantic abstraction—shallow features are acoustic-biased and cannot distinguish phonetically similar words; expanding to 4 blocks yields the minimum median FRR; going deeper leads to performance plateauing or slight degradation because the base’s deepest layers are overly specialized to the core keyword set $\Y_1$, offering limited transfer value. This "shallow is insufficiently semantic, deep is overly specialized" inverted-U shape is a specific manifestation of the classic transfer learning trade-off in KWS expansion, leading to the adoption of a 4-block configuration throughout. The paper also points out that the fundamental flaw of the Ensemble baseline lies in zero reuse depth: completely ignoring base model intermediate features, requiring the same 10k budget to learn from random initialization.

### Technical Differences with Existing Methods

The essential differences with various routes can be listed in a matrix: Full Finetune changes paths and outputs, offering no guarantees; EWC changes paths, offers soft protection, and violates the no-$\mathcal{D}_1$ constraint (requires Fisher); Adapters/LoRA change shared paths, offer no guarantees, and have higher MACCs under the same parameter budget; Ensemble does not change paths but has zero feature reuse; PNN guarantees no forgetting but requires known task identity at inference; This method does not change paths, reuses mid-level features, operates as a single detector without task labels at inference, and caps both parameters and MACCs. The relationship with Head-Only is particularly clean: Head-Only is the degenerate case of this method with $L=0$, making the ablation spectrum naturally continuous.

## Experimental Results

### Datasets Used and Their Scale

Main experiments are conducted on the official train/validation/test splits of Google Speech Commands v2 (GSC). The target vocabulary is the standard 10-command set {left, right, on, off, stop, go, up, down, yes, no}, with all other words in GSC and silence segments folded into the background label $\emptyset$. The expansion task uses five held-out pairs to eliminate sensitivity to single keyword selection and cover different confusion patterns: {left, right}, {on, off}, {stop, go}, {up, down}, {yes, no}—each pair consists of easily confused commands. In each task, one command pair forms the new keyword set $\Y_2$, and the remaining eight commands form the deployment core set $\Y_1$; the base model is trained on $\mathcal{D}_1$ (GSC train restricted to $\Y_1 \cup \{\emptyset\}$), and expansion uses only $\mathcal{D}_2$ (restricted to $\Y_2 \cup \{\emptyset\}$), with no access to $\mathcal{D}_1$ audio. The paper does not explicitly state whether $\Y_2$ audio in $\mathcal{D}_1$ (and $\Y_1$ audio in $\mathcal{D}_2$) is folded into background or removed; this detail affects the background distribution composition and is an unreported item.

Key experimental design: Negative sample calibration does not use GSC itself (whose background word distribution is narrow and biased), but uses Mozilla Common Voice v17 (CV) as pure negative sample corpus; all reported results use positive samples from GSC test, with FAR-calibrated negative samples from CV test. This simulates the engineering reality in real products where "negative samples must be far richer than the test set."

Feature and training configuration: 16 kHz mono, 40-dimensional log-Mel filter bank, 25 ms window / 10 ms hop; SpecAugment (time masking + frequency masking) is applied directly to log-Mel features during training to improve channel and speaker style robustness; Adam optimizer with cosine learning rate schedule; base model trained for 40 epochs on $\mathcal{D}_1$, expansion stage trained for 10 epochs on $\mathcal{D}_2$. The small expansion training volume is intentional—new keyword data is naturally scarce.

### Definition and Rationale for Evaluation Metrics

The metric is **macro FRR @ 1% FAR** (macro-average False Rejection Rate at 1% False Acceptance Rate). The rationale directly corresponds to product logic: the operational contract of a wake-word system is a "cap on daily false wake-ups" (FAR budget), making it meaningful to compare miss rates (FRR) under this budget; sliding thresholds are closer to deployment than area-under-curve metrics. Specifically: for each keyword $y$, the threshold $\tau_y$ is calibrated on the CV test partition to ensure FAR is exactly 1% (core keywords use Core Head scores, new keywords use New Head scores), then FRR is calculated on GSC test, and macro-averaged over the keywords in the evaluation set. For statistical robustness, each (method, word pair) configuration runs 8 independent random seeds, reporting sample mean and 95% confidence interval $\bar{x} \pm t_{0.975,7}\, s/\sqrt{8}$. This protocol (external negative sample calibration + fixed FAR operating point + multi-seed t-intervals) is closer to industrial acceptance standards than the majority of GSC papers that only report accuracy.

### Detailed Comparison with Baseline and SOTA Methods

**Overhead Comparison (Table 1, worst-case computation for 1 second of speech under the deployed core-first pipeline)**: Base 150K parameters / 15.08M MACs (1.00×); Full Finetune and EWC add no parameters, both 15.08M; Head-Only 151K / 15.16M (1.01×); Ensemble 160K / 16.14M (1.07×); Adapters 160K / 18.45M (1.22×); LoRA 160K / 20.52M (1.36×); This Method 160K / 16.34M (1.08×). With the same 10k new parameters, this method’s MACC increment is only 1.26M, whereas Adapters is 3.37M and LoRA is 5.44M. The paper does not directly explain the mechanism behind this gap; a reasonable inference is: Adapters/LoRA modules are inserted in parallel top-L branches, performing transformations at full channel width at every layer, whereas this method’s expansion blocks are chained and use small-kernel temporal convolutions, resulting in a lower parameter-to-compute conversion rate (this is the author’s interpretation based on structural description, not elaborated in the paper).

**Core Keyword Performance (Table 2 Core Phrases)**: Base model average FRR 2.71% (±0.12), with pairs ranging from 2.37% to 3.29%. Full Finetune pushes core keyword FRR to an average of 69.08% (±1.98), with the worst {left, right} pair reaching 82.94%—a textbook demonstration of catastrophic forgetting. EWC mitigates this to 4.47% (±0.18), still significantly worse than the baseline, and it relies on Fisher information derived from $\mathcal{D}_1$, violating the strict no-$\mathcal{D}_1$ setting (the paper takes $\lambda = 5\times10^5$). All methods freezing the core path (Adapters/LoRA/Ensemble/This Method) show bitwise identical core keyword results to the base model, omitted from the table.

**New Keyword Performance (Table 2 New Phrases, average FRR)**: Full Finetune 2.35% (±0.27) is best but unavailable as noted; Head-Only 22.30% (±4.27) with huge variance (±16.44 on {left,right}), proving that freezing representations completely is insufficient; Adapters 8.05% (±0.35); EWC 7.95% (±0.64); Ensemble 6.46% (±0.42); LoRA 6.41% (±0.66); **This Method 4.37% (±0.33)**. Compared to the parameter-matched independent model baseline (Ensemble), this is an absolute improvement of 2.09 percentage points, or a relative improvement of ~32%. Looking at pairs individually, this method outperforms or matches all deployment-constrained methods on all five word pairs: {left,right} 6.69 (±1.04), {on,off} 2.68 (±0.39), {stop,go} 4.56 (±0.86), {up,down} 4.57 (±0.73), {yes,no} 3.36 (±0.38). An honest detail: EWC outperforms this method on the {left,right} pair (5.44% vs 6.69%), but at the cost of violating two constraints (altering core path + requiring $\mathcal{D}_1$); this method’s weakest pair is also {left,right}, suggesting room for improvement in the expansion branch for phonetically similar new keyword pairs.

**Statistical Significance**: Look at confidence intervals, not just point estimates. This method’s interval (4.37 ± 0.33) does not overlap at all with LoRA (6.41 ± 0.66), Ensemble (6.46 ± 0.42), EWC (7.95 ± 0.64), or Adapters (8.05 ± 0.35). The gap (~2 points) compared to the strongest compliant baseline LoRA is robust under the 8-seed protocol, not random fluctuation. Conversely, Head-Only’s interval on {left,right} (42.55 ± 16.44) is so wide it lacks engineering significance—freezing representations makes the new head’s learning extremely sensitive to seeds, which itself is evidence that "zero reuse is infeasible." Full Finetune’s core keyword interval (54.33 ± 13.55 on {up,down}) is also extremely wide, indicating the depth of catastrophic forgetting is unpredictable, which is the technical root of "unacceptable regression" on the product side.

**Meaning of Worst-Case Metric**: Table 1 is specifically labeled as "worst-case computation under the deployed core-first pipeline," assuming the core head always rejects and the expansion path must be executed for every analysis frame. For a resident, fixed-latency wake-word detector, capacity planning must be based on worst-case scenarios; savings in average cases are meaningless—this is why the paper uses 16.34M (1.08×) for comparison rather than average values against Adapters/LoRA’s 18.45M/20.52M. Incidentally, actual average overhead is usually lower than the worst-case value (the new head is only evaluated after core rejection), but the paper does not report average-case numbers.

### Findings from Ablation Studies

The only ablation is expansion depth $L$ (Fig. 3, $\Y_2 = \{left, right\}$): tapping 1–3 blocks results in high new keyword FRR (insufficient semantic abstraction); 4 blocks yield the minimum median FRR; going deeper leads to plateauing or slight degradation because the base’s deepest layers are overly specialized to the core vocabulary, offering limited transfer value. The conclusion is that 4-block is the optimal configuration and is used for all main comparisons. This result aligns with the general rule in representation learning that "mid-level features transfer best": too shallow contains only acoustic details, too deep binds to the source task’s decision boundary—for KWS, the source task’s decision boundary is the eight core commands, and new keywords must bypass it. A notable cross-method pattern is: {left,right} is the hardest word pair for almost all methods (Head-Only 42.55%, Ensemble 8.77%, EWC 5.44%, This Method 6.69% are all their respective worst), and it was selected as the sole experimental object in the ablation, indicating the authors deliberately chose the hardest scenario for deep analysis, making conclusions conservative rather than optimistic. The paper does not report ablations on other dimensions (e.g., expansion block channel width, convolution kernel size, number of expansion training epochs, new head temperature), nor does it report whether $L=4$ is optimal for other word pairs.

## Main Contributions

1. **Transforms the non-regression guarantee for on-device KWS vocabulary expansion from a probabilistic problem to a topological one**: Fully frozen base (including BN affine parameters and sliding statistics) + computation graph isolation + independent new head, making old keyword logits and threshold decision rules identical for all inputs (Eq. 3 + Eq. 5), guaranteeing "by construction" validity, which is a structural alternative to the EWC/LwF/PEFT routes.
2. **Achieves dual optimization of new keyword performance and inference overhead within a hard 10k parameter budget**: Average new keyword FRR of 4.37%, 2.09 absolute percentage points lower than the parameter-matched independent model baseline, and 3.68/2.04 percentage points lower than Adapters/LoRA respectively; worst-case MACs of 16.34M, significantly lower than Adapters (18.45M) and LoRA (20.52M) under the same budget.
3. **Core-first cascaded decision rule**: Explicitly states that "preserving logits ≠ preserving product behavior," embedding the shipped detector’s threshold rules directly into the expansion system’s inference pipeline, completing decision-level non-regression, and ensuring the new head is only evaluated when the core rejects.
4. **Quantitative characterization of feature reuse depth**: Provides the transfer depth trade-off of "shallow is insufficiently semantic, 4 layers optimal, deep is overly specialized," providing reusable design priors for subsequent modular expansion work.
5. **A evaluation protocol closer to industrial acceptance**: External negative sample corpus (CV v17) for threshold calibration, reporting macro FRR at a fixed 1% FAR operating point, five held-out easily confused word pairs, and 8-seed t-confidence intervals.

## Limitations and Future Work

### Technical Limitations of the Method

- **The non-regression guarantee covers the core keyword set, not the system-wide false acceptance rate**. The expansion system may now accept new keywords on audio that previously output $\emptyset$, causing the system-level total FA budget to expand with vocabulary growth; the paper only calibrates each new keyword’s threshold individually to 1% FAR, without analyzing the change in merged system-level FAR (unreported).
- **Cascading introduces a core-new keyword coupling lower bound**: The new head is only evaluated when the core detector rejects; if the core head falsely triggers on new keyword speech, the new keyword will inevitably be missed; the contribution of this interaction to the new keyword FRR floor is not quantified by the paper.
- **Capacity per expansion is an independent budget**: 10k/expansion, adding only one pair of words at a time. Whether parameters accumulate linearly across multiple consecutive expansions, and whether expansion blocks also need to reuse parameters, is completely unexplored (listed by authors as future work).
- **The 10k budget is a hard cap, not a performance-optimal solution**: The abstract explicitly states the method works within a 10k budget; behavior under larger expansion budgets or larger new keyword sets (adding more than 2 words at once) is not reported.
- **Only MACs are reported**: No actual hardware latency, SRAM/Flash usage, or power consumption measurements (all unreported), which is a missing link for the deployment claim of "fixed-latency resident detectors."

### Deficiencies in Experimental Design

- **Narrow data scope**: All conclusions are built on GSC v2’s 10 commands and 1-second segmented audio, lacking real-product-scale data, far-field/multi-channel/strong noise condition tests, despite the paper’s motivation stemming from Yandex’s shipped products (the team has previously published multi-channel noise KWS work, which this paper fails to connect to). The scale of the base model on real deployment vocabulary is also unreported.
- **Single baseline configuration**: Adapters/LoRA’s L and rank are deliberately configured to match this method’s compute rather than being individually tuned; EWC only takes a single $\lambda = 5\times10^5$ without scanning; open-vocabulary/few-shot routes (e.g., Prototypical Networks) are only qualitatively discussed in related work and not included in experimental comparisons.
- **Thin ablation**: Only one dimension of expansion depth, and only on the {left,right} pair; internal structure of expansion blocks (channel count, kernel width), number of training epochs, and new head capacity are not ablated.
- **Background distribution details unexplained**: It is unclear whether audio of commands from $\Y_1$ in $\mathcal{D}_2$ (and vice versa) is folded into $\emptyset$ or removed, affecting the background distribution learned by the new head.
- Another note: The paper includes a generative AI usage disclosure (ChatGPT GPT-5.2 used for English polishing, technical content authored by the authors), which does not affect technical conclusions.

### Possible Directions for Future Improvement

- **Multi-stage sequential expansion** (direction explicitly pointed out by authors): Adding new keyword sets in batches, focusing on parameter reuse and accumulation in expansion paths, avoiding linear addition of 10k per round; this directly determines whether the method can support long-term vocabulary evolution in products.
- **Removing core-new keyword coupling**: Researching controllable false acceptance by the core head on new keyword speech (e.g., diagnosing core head behavior on $\mathcal{D}_2$), or changing cascading to parallel scoring + global threshold allocation, quantifying the allocation problem of system-level FAR budgets.
- **Real-device validation**: Reporting latency, memory, and power consumption on target DSP/MCU, translating the paper advantage of 16.34M MACs into deployment evidence.
- **Harder evaluation scenarios**: Far-field reverberation, multi-speaker, cross-dialect negative samples, adding multiple new words at once, and direct experimental comparison with open-vocabulary/few-shot methods, to answer the true boundaries between this method and flexibility routes.
- **Automated expansion depth**: Transforming "4 layers optimal" from manual ablation to a learnable/searchable choice (similar to neural architecture search for tap positions), adapting to different base models and new keyword characteristics.

## Terminology Quick Reference

- **SVDF**: Singular Value Decomposition filter, decomposing fully connected layers into low-rank two-stage factorized structures, a classic layer type for streaming low-latency KWS.
- **FRR / FAR**: False Rejection Rate (said but not woken) / False Acceptance Rate (not said but woken); comparing lower-bound FRR at fixed FAR is the standard evaluation posture for wake-word systems.
- **macro FRR**: Arithmetic mean of FRR calculated separately for each keyword in the evaluation set, preventing small classes from being diluted by large class sample sizes.
- **EWC**: Elastic Weight Consolidation, a regularization-based continual learning method that adds quadratic penalties to important parameters using Fisher information.
- **LoRA / Adapters**: Two major families of parameter-efficient fine-tuning—low-rank side-path matrices / bottleneck plugin modules, both modifying shared computational paths.
- **PNN**: Progressive Neural Network, freezing old task columns and adding new task columns with lateral connections, relying on task identity at inference.
- **non-regression by construction**: A guarantee method where old behavior remains mathematically identical through computation graph isolation (rather than regularization/data replay).
- **core-first decision rule**: Core-priority cascaded decision, running the old detector first and evaluating the new head only upon its rejection.
